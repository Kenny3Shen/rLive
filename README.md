# rLive

**rLive** 是基于 **Tauri 2 + React + TypeScript + Rust** 的跨平台直播客户端，提供多站点浏览、播放、弹幕与本机数据管理。

## 环境要求

- [Rust](https://www.rust-lang.org/)
- [bun](https://bun.sh/)
- [Tauri 2 平台依赖](https://v2.tauri.app/start/prerequisites/)
- ASR 仅支持 Tauri 桌面客户端。Linux、macOS 桌面端使用 CPU；Windows 桌面默认构建 CUDA-capable shared runtime，可在「设置 → 播放 → 语音字幕」选择自动、CUDA 或 CPU。Windows CUDA 运行需要 Compute Capability 6.1 及以上的 NVIDIA GPU、兼容驱动、CUDA 11.x 与 x86-64 cuDNN 8.x；自动模式检测失败会回退 CPU。CUDA runtime 会增加桌面构建体积，构建 CPU-only Windows 版本可设置 `SHERPA_ONNX_GPU=0`

### Windows 推荐目录

| 组件           | 路径                           |
| -------------- | ------------------------------ |
| 项目镜像       | `D:\dev\rLive`               |
| Rust           | `D:\dev\rust\{cargo,rustup}` |
| VS Build Tools | `D:\VS\BuildTools`           |
| 临时目录       | `D:\Temp\build`              |

## 开发

```bash
bun install
bun run tauri dev
```

仅启动前端：

```bash
bun run dev
```

构建与测试：

```bash
bun run build
bun run test:unit
cd src-tauri && cargo test --lib
bun run tauri build
```

ASR 使用 sherpa-onnx streaming Zipformer，仅在 Tauri 桌面客户端启用。Linux、macOS 桌面端固定使用 CPU；Windows 支持自动、CUDA、CPU 三种后端，自动模式优先 CUDA，运行库或驱动不可用时回退 CPU，实际 provider 会显示在设置页。识别、标点与可选 CAMPPlus 声纹模型使用同一 provider；当前 VAD 是 Zipformer 的 CPU endpoint 规则，不是独立 ONNX 模型。CPU provider 下各模型最多使用 8/2 个线程；本地热词启用时使用 modified beam search。完整参数见[本地语音字幕](docs/zh/本地语音字幕.md)。

### Windows 交付（WSL → `D:\dev\rLive`）

日常在 WSL 开发，在 Windows 上生成可执行文件：

```bash
# 在 WSL 仓库根目录执行：同步 + 构建
./scripts/build-windows-from-wsl.sh
```

成功产物：

```text
D:\dev\rLive\src-tauri\target\release\rlive.exe
```

规则见 [AGENTS.md](AGENTS.md)。

### 正式发布

推送与三处版本一致的 `vX.Y.Z` 标签会触发签名发布流程：生成 Android arm64-v8a APK / AAB 与 `SHA256SUMS.txt`，并创建待人工审核的 GitHub draft Release。签名材料只从受保护的 GitHub `release` Environment 注入；未配置密钥时工作流会失败，不会发布未签名的正式产物。正式发布不提供 Windows 安装包，Windows 可执行文件按上面的「Windows 交付」在本机构建。配置步骤见[发布流程](docs/zh/发布流程.md)。

## 快速使用

1. 首次启动默认打开哔哩哔哩；可在顶部切换站点（哔哩哔哩 / 斗鱼 / 虎牙 / 抖音 / Twitch）。
2. 从首页推荐、分类或搜索进入直播间；房间顶栏左侧的返回图标会回到来源页面，直接打开房间链接时则回到首页。
3. **哔哩哔哩弹幕**：设置 → 账号 → 选择「扫码登录」或「手动输入」保存 Cookie → 进入房间后右侧列表与飘屏生效。普通聊天会按原顺序显示平台图片表情，只加载校验过的 B 站 CDN 图片；意外断线会轮换网关、刷新短时 token 后自动重连。若需发送，先在「设置 → 账号」开启默认关闭的「启用发送功能」，并保存含 `SESSDATA` / `bili_jct` 的 Cookie；发送框位于播放器功能栏中间。**斗鱼**可扫码或手动保存完整本机 Cookie；当前网页对齐的发送链路已在个人直播间验证。每次发送仍以 `chatres(res=0)` 作为平台接收信号，并以正常收弹幕连接的真实回显决定 UI 展示，详见[斗鱼平台 API 文档](docs/zh/斗鱼平台API文档.md)。**虎牙**可扫码登录，或手动保存含数字账号 ID（`yyuid` 或 `udb_uid`）及登录凭据（`udb_n` / `udb_cred` / `udb_biztoken`）的本机 Cookie。
4. **弹幕设置与操作**：右侧标签依次为「弹幕 / 关注 / 设置」；在「设置」中调整显示区域、行数、不透明度、字号、字重、速度、相同内容合并、默认开启的礼物信息过滤和屏蔽词。相同内容合并窗口默认 10 秒，可在 5–30 秒间调整。礼物信息过滤也会隐藏抖音「点赞 × 数量」等平台互动通知。支持 SC 的 B 站房间还可关闭默认开启的画面 SC 卡片。B 站、斗鱼、虎牙可在此会话级开启「自动发送弹幕」：默认关闭且不保存，只有本机发送授权、对应 Cookie/可发送状态及文本校验均有效时可开启。开启时立即发送首段；文本会将换行和连续空白压缩为一个空格，按最多 20 个用户可见字符且不超过平台 UTF-16 上限拆段并循环发送。后续发送起始至少相隔发送间隔；该会话参数默认 20 秒，可在 10–3600 秒间调整，修改会重排下一次发送。编辑文本、切换房间（会清空该会话文本）、离开页面或任何发送失败都会立即停用并显示原因，失败不会自动重试。滑块与屏蔽词输入都会即时生效，屏蔽词会自动保存。点击一条普通弹幕可选择图标「复制」或「+1」；复制会写入剪贴板，「+1」会提交完全相同的一条文本，不会附加“+1”。本机提交不等于送达，右侧列表与飘屏仅在收到平台真实回显后显示。
5. **主播信息 / SC / 关注**：右栏顶部显示主播头像、用户名、平台图标、房间号和当前热度；哔哩哔哩醒目留言以卡片叠放在播放器左下角，发送者头像与名称位于身份区，金额保持醒目，安全校验的金额档位颜色用于正文带；头像缺失或加载失败时显示名称首字母。首次关注可选择已有分组或当场新建分组；关注页用「直播关注 / IPTV 频道」页签区分两类内容，切换时带有短暂过渡。直播页签支持新建、重命名和删除分组，可整卡拖到明确的目标分组或通过右键菜单移动；桌面端使用左侧分组栏，移动端使用横向分组条。IPTV 页签在 Shell 顶栏切换中文、中国大陆、东亚、综合及已配置的自定义频道源，并使用独立的自定义频道分组；桌面端分组位于左栏，移动端为横向分组条，也可从频道卡片直接调整归属。M3U 自带分类仍作为频道元数据显示，分组内容会随方向平移。房间右侧「关注」可直接切换到任一已关注房间，无需先退出当前房间，直播中的卡片会在平台名称后显示已开播时长。直播关注顶部可按「全部平台」或单个平台筛选；关注状态按钮仅有「全部 / 直播中 / 未开播」。移动端列表统一下拉刷新，桌面端保留右下角刷新按钮。
6. **播放器控制**：控制条以透明方式叠放在视频底部，播放期间闲置后自动隐藏，移动、点击或键盘操作可再次显示；打开音量、清晰度或线路选项时会保持显示。移动端可在画面左半边上下滑动连续调节亮度、右半边上下滑动调节音量，中央 HUD 会实时显示图标、百分比和进度。Android 客户端的右侧手势、音量滑块和静音按钮通过原生桥调整系统媒体音量，与硬件音量键共享设备档位并在离开播放页后保留；其他移动端仍调整当前直播间媒体元素。焦点位于画面时，`Space` / `K` 播放或暂停，`M` 静音，`F` 全屏。刷新位于暂停左侧；单一音量按钮展开竖向滑杆，静音按钮位于滑杆底部；「仅播声音」会隐藏视频、飘屏与画面叠加层并允许屏幕休眠，再次点击恢复画面；清晰度和线路仅显示当前选择项；右栏、飘屏与全屏均为图标开关。直播地址通常是音视频复用流，此模式不会改用独立音频地址，也不保证减少网络流量。
7. **本地语音字幕（仅 Tauri 桌面端）**：在「设置 → 播放 → 语音字幕」开启 streaming Zipformer，默认下载约 `550 MiB` 的中英双语识别与标点模型；关闭自动标点时约 `488 MiB`，可选「说话人区分」会再下载约 `27 MiB` 的 CAMPPlus 声纹模型。VAD、自动标点和说话人可独立开关；本地热词支持主播名、游戏名等领域词。更新间隔可在 `0.2–1.0 秒`间调整（默认 `0.2 秒`），字幕字号范围为 `12–48 px`。进入直播间后点击控制栏字幕图标即可显示实时 partial 与稳定 final；鼠标悬停或键盘聚焦该图标可打开翻译设置，选择原文、译文语言并开启双语字幕。ASR 音频始终只在本机处理；字幕翻译默认关闭，开启后仅将已定稿的文字发送到 Google 翻译，实时 partial 不会发送。移动端暂不展示字幕设置或播放器入口。关闭总开关会释放本地模型内存但保留模型文件。
8. **外观**：桌面侧栏「设置」上方保留太阳 / 月亮按钮，每次点击会在亮色与暗色模式之间轮换；移动端设置页不提供显式亮暗模式入口。
9. **抖音 / Twitch**：抖音可匿名浏览推荐和分类并加载更多后续页面；列表请求使用本地 `a_bogus` 签名，首屏签名失败时回退 SSR，网页访问验证仍可能限制扫码或搜索。搜索需要在「设置 → 账号」选择扫码登录或保存完整网页 Cookie。房间优先从 SSR 取得内部房间号，再使用公开 reflow 数据解析播放信息。抖音弹幕在本机完成 MSSDK 签名后直连官方 WSS，无需外部签名服务。Twitch 支持直播列表、分类、搜索、房间、HLS 播放与匿名 IRC 弹幕；受公开接口限制，浏览结果仅可靠支持首屏，不提供翻页。
10. **IPTV 与直链播放**：从侧栏进入「IPTV」后首先到达频道发现首页，不会自动打开或播放任何流。可加载 IPTV-org 官方日更的中文、中国大陆、东亚或综合公开频道分表；自定义源在「设置 → 网络」保存 HTTP(S) M3U 地址后显示为「自定义源」。同一分类下的「直链播放」可输入你有权使用的 HTTP(S) 媒体地址，直接进入共享播放器；rLive 会按地址识别 HLS、FLV、MPEG-TS 或原生媒体并通过本机 `stream_proxy` 转发。页面在手机上使用紧凑来源菜单与双列频道，在桌面上使用分段来源切换与多列频道；两端均可在频道卡片或播放页关注频道，并用「关注」筛选只看当前来源的关注项。各来源的 IPTV 关注会汇总到关注页的「IPTV 频道」页签，并由同一 Shell 来源栏切换查看；页面内可新建、重命名或删除独立的自定义分组，从频道卡片直接调整归属。关注会保留频道快照，源更新后暂时移除的频道仍可从关注页或关注筛选进入播放。页面同时提供「更新源」、多关键词搜索、分类筛选、可用状态筛选和「检测可用性」。更新与检测遵循应用代理；检测对当前搜索/分类结果按 URL 去重，单次最多处理前 120 个频道，并显示进度、响应耗时与失败状态。检测结果只保留在当前页面会话，更新或切换来源后清除；“可用”仅表示本次请求取得媒体数据（HLS 同时通过清单头校验），不保证后续分片、解码、地区授权或持续稳定。点击频道才会进入独立的沉浸式播放页（`/iptv/play`）并走 HLS、MPEG-TS 或 FLV 播放路径；播放页与直播房间共享 React 控制栏，提供重连、播放/暂停、静音/音量、仅播声音、画中画和全屏，并在播放闲置后自动隐藏。返回会回到进入播放前的 IPTV、关注或设置页面。内置公开源关注与 IPTV 自定义分组包含在配置导入导出中；自定义地址及其频道关注只保存在当前设备，不写入路由、历史或配置包。
11. **局域网同步**：在「设置 → 数据管理 → 局域网同步」中，发送设备创建有效期 5 分钟的一次性会话，接收设备输入发送端显示的同步地址和 6 位配对码后拉取并合并配置。同步完成一次后会话自动关闭，连续 5 次输入错误配对码也会锁定。同步范围与配置档案一致，包含主播关注、标签、内置公开源 IPTV 关注、IPTV 自定义分组、历史和可移植设置；不包含 Cookie、自定义 M3U 地址及其频道关注、多画面布局、本机弹幕发送授权或 ASR 本机配置。两台设备须位于可互访的同一局域网；传输使用临时 HTTP 会话，请仅在可信网络中使用。若无法连接，请检查系统防火墙和 Wi-Fi 的 AP/客户端隔离设置。
12. **桌面多画面**：从侧栏进入「多画面」，或在直播卡片右键菜单、单房间顶栏选择加入多画面。最多同时播放 6 个直播间；主画面占据左下 2×2 区域，副画面沿上方和右侧排列。拖动画面把手可交换位置或移动到空槽，双击副画面或点击「设为主画面」可切换主副画面。每路会记住自己的副画面槽位；连续切换主副时，离开主画面的直播间会回到它记忆的副画面位置，被暂时占用的副路再转移到本次被提升直播间的原位置，避免直播间位置因连续切换而漂移。每路可独立暂停、刷新、静音和调节音量；首路默认 80%，后续新增副路默认静音且音量为 0%。切换主副时新主解除静音（音量为 0% 时恢复为 80%），全部副画面静音，但各路音量数值仍会保留。多画面不启动弹幕、ASR 或房间侧栏，槽位、位置记忆与各路音量只保存在当前设备的 localStorage，不进入配置导入导出。

## 技术边界

B 站、抖音、斗鱼、虎牙均支持扫码或手动 Cookie。B 站、斗鱼和虎牙的单条发送与会话级自动发送共用 `danmaku_send_enabled`、Cookie、文本和冷却校验。斗鱼将本地提交、`chatres(res=0)` 与房间真实回显作为独立状态处理。

不支持支付、送礼、批量发送、自动回复或录制；发送出现未知结果时不会自动重试。
