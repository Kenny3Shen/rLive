# rLive 架构说明

## 1. 总体结构

顶层采用标准 Tauri 布局，按前后端拆分：

```
rLive/
├── src/          # React UI（Vite 入口与页面）
├── src-tauri/    # Tauri 2 + Rust（commands / sites / DB）
├── tests/        # 前端单元测试
├── docs/         # 中文文档
└── scripts/      # WSL 同步、Windows 桌面构建、Windows Android 真机
```

```
┌─────────────────────────────────────────────┐
│  React UI (src/)                              │
│  首页 / 关注 / 分类 / 历史 / IPTV / 多画面 / 设置 / 房间页 │
│  xgplayer 协议插件播放 · 多会话代理 · Canvas 弹幕 · SC 叠加层 │
└──────────────────┬──────────────────────────┘
                   │ Tauri commands / events（浏览器访问时为 web_bridge HTTP / SSE）
┌──────────────────▼──────────────────────────┐
│  Rust (src-tauri/)                            │
│  LiveSite · stream_proxy · danmaku WS · ASR · DB │
└─────────────────────────────────────────────┘
```

| 目录 | 职责 |
|------|------|
| `src/` | 前端：页面、播放控制、弹幕引擎、设置 |
| `src-tauri/src/sites/` | 各站点 HTTP / 签名 / 房间解析 |
| `src-tauri/src/danmu_rs/` | 弹幕 WebSocket 与协议解析 |
| `src-tauri/src/stream_proxy.rs` | 本机流媒体代理、HLS 改写、线路探测与脱敏聚合遥测 |
| `src-tauri/src/web_bridge/` | 可选的本机 HTTP 服务：向普通浏览器提供打包前端、`/api/invoke/<cmd>` 命令转发与 `/api/events` 弹幕 SSE |
| `src-tauri/src/iptv/` | 代理感知的 M3U 获取、大小限制、频道元数据解析与有界可用性探测 |
| `src-tauri/src/asr.rs` | sherpa-onnx Zipformer/标点/CAMPPlus 模型下载、流式会话生命周期、转写与匿名说话人聚类 |
| `src-tauri/src/db/` | SQLite：关注、历史、设置、Cookie |
| `scripts/` | WSL 同步、Windows 桌面构建、Windows Android 真机开发 |

SQLite 文件连接使用 WAL 日志和 `synchronous=NORMAL`，为单条历史写入降低同步落盘开销，并配置 5 秒锁等待、8 MiB 页缓存和检查点后的 WAL 保留上限。观看历史按 `watched_at + site_id + room_id` 建立稳定排序索引，最多保留最近 2,000 个不同直播间；迁移旧数据库时只裁剪超限记录并复用空闲页，不在启动阶段执行阻塞性的 `VACUUM`。弹幕发送历史分别使用站点内和全局时间索引，继续保持每个平台 50 条的既有上限。可运行 `bash scripts/benchmark-history-sqlite.sh`，在临时目录中复现旧版与当前实现的读取、独立写入和稳定态存储对比。

## 2. 播放路径

1. `LiveSite::get_play_urls` 返回带 `source_id`、安全标签、显式协议、平台优先级、URL 和 headers 的结构化 `PlayUrl[]`。
2. 前端按 `site_id + room_id` 恢复最近一次手动线路选择，优先匹配 `source_id`，缺失时回退到保存的序号；没有记忆时遵循平台顺序。
3. 前端请求 `stream_proxy_start`，Rust 在 `127.0.0.1` 为当前 `sessionId` 准备独立监听器，并在就绪后只替换同一会话的旧活动代理。
4. 浏览器访问 `http://127.0.0.1:<port>/...`，代理向上游带正确 UA/Referer；HLS 清单中的子清单、密钥与分片会在本机代理中改写到受限的 localhost 资源路径。
5. 前端统一由 `xgplayer` 管理媒体元素和播放器生命周期：直播 FLV 与裸 MPEG-TS 使用 `xgplayer-mpegts.js` / `mpegts.js` 并通过 `mediaDataSource.type` 区分容器，所有 HLS 使用 `xgplayer-hls.js` / `hls.js`，原生媒体交给 `<video>`；流媒体内核只保留这两套。
6. 房间播放器每 2 秒采样媒体与代理聚合指标，最多保留 120 条内存快照；不上传、不持久化，也不保存 URL 或 headers。

HLS 播放列表可以引用 MPEG-TS（`.ts`）分片，但这不等于裸 MPEG-TS 流。`hls.js` 先解析 m3u8 清单，再依据分片序号、时间轴、不连续标记和加密信息拉取、转封装 `.ts` 并写入 MSE。裸 `.ts` 地址没有 m3u8 清单，不能进入这套 HLS 状态机，因此 IPTV 的连续 MPEG-TS 流仍由 `xgplayer-mpegts.js` / `mpegts.js` 处理。斗鱼连续 FLV 上游关闭时，前端在 `mpegts.js` 报告 `loading_complete` 后重新获取房间详情与网页播放签名，再刷新清晰度、线路并完整重建会话。

每次播放器会话会携带唯一 session ID；`stream_proxy` 以 `sessionId` 为键并存活动监听器和启动预留，停止请求只会关闭同一会话持有的代理。因此快速离开并再次进入同一房间时，旧清理不会误关新代理，多画面的多路流也不会互相抢占监听器。房间与 IPTV 播放页复用 `src/shared/components/player/PlayerControls.tsx` 的 React 控制层，不启用浏览器 `<video controls>` 或 xgplayer 默认皮肤。控制层以透明方式叠放在画面底部，播放闲置后自动隐藏；播放、静音、画中画和全屏共享相同状态接口，房间按需追加线路、清晰度、弹幕、ASR 和侧栏。ASR 控制与相关设置仅在 Tauri 桌面端挂载；Android 原生桥管理 Activity 级亮度、系统 `STREAM_MUSIC` 音量和全屏方向，房间与 IPTV 的音量入口共享设备媒体音量。非 Android 平台仍直接写当前播放器的 `<video>` 音量。

桌面 `/multi-room` 路由使用 `src/features/multi-room/` 的导播矩阵，可选择 4 或 6 画面布局。4 画面有两种排列：左主右副使用 3×3 网格，主画面占左侧 3×2，3 个副槽纵向占据右侧；均分排列使用 2×2 网格，4 个槽尺寸相同，但槽位 0 仍是音频、弹幕与全屏角色上的主画面。6 画面使用 3×3 网格，左下 2×2 为主画面，其余槽位沿上方和右侧分布。切换到 4 画面会把不连续的副槽压缩到 1–3，超过 4 路时拒绝切换，确保没有不可见播放器。拖拽可调整槽位；主副切换会保留每个直播间最近的副画面槽位，离开主画面的直播间优先回到该槽位，被占用时将原占位副路转移到被提升直播间的原槽位，避免连续交换导致位置身份漂移。发生主副交换时，新主解除静音（0% 恢复 80%），全部副路静音，但各路音量数值不被清除。首路默认 80%，新增副路默认 0% 且静音。多画面复用房间详情、播放控制器和 `useWebPlayer`；弹幕、SC 与 ASR 只挂在主画面一路，副路和主路都不创建房间侧栏。全屏同样归属主画面：`useWebPlayer` 的 `fullscreenOwner` 只对主路为真，主路容器带 `data-player-stage` / `data-fullscreen`，全屏时脱离网格铺满窗口，而不是放大整个矩阵。容量与排列选择、槽位、位置记忆和各路音量由 Zustand persist 保存到设备 localStorage `rlive-multi-room`，不进入 SQLite 或配置导入导出。

`waiting` / `stalled` 只计入内存遥测，不再触发自动换线或重载；B 站 HLS 的重复 fatal 事件仍保留 20 秒原地恢复窗口，避免短暂上游波动造成频繁重建。默认开启的「软切换」会在 HLS、MPEG-TS、FLV 同协议线路间通过 xgplayer `switchURL` 保留外层播放器与媒体元素；FLV 同时替换内部 `mpegts.js` core，协议变化、API 不可用或切换失败会回到完整重建。完整数据契约、故障转移、遥测字段、参数与性能验收见[播放器技术文档](播放器技术文档.md)。

IPTV 前端将 `/iptv` 作为仅用于发现的首页：展示响应式来源切换、分类、搜索、关注、会话级可用状态和频道列表，进入时不会创建播放器或代理会话，也不会默认播放第一个流。自定义 HTTP(S) M3U 地址只能在「设置 → 网络」保存；首页选中 `source=custom` 时从本机设置解析，地址本身不会写入路由、历史或配置包。`iptv_load_playlist` 与 `iptv_check_channels` 都从本机设置读取代理；前者重新获取当前 M3U，后者接受最多 32 个一批的去重频道请求，以 12 路并发和 7 秒单项上限读取首批媒体数据，并额外校验 HLS 清单头、空响应与 HTML 验证页。前端把当前筛选结果限制为 120 个、按 24 个一批调用并渐进合并结果；状态不进入 URL、数据库或配置包，更新/换源即清除。

IPTV 关注使用独立的 `iptv_favorites` SQLite 表，以 `source_id + channel_url` 为主键并持久化频道快照；用户归组存于独立的 `favorite_group_id`，M3U `group_name` 只保留为源元数据。自定义分组定义存于 `iptv_favorite_groups`，删除分组会在同一事务内清空频道引用。`iptv_favorite_list` 接受可选 `source_id`：发现页与播放页按源读取，关注页先读取全量缓存，再按当前 `source` 对应的稳定来源 ID 筛选；TanStack Query 会同步更新全量与按源缓存。关注页通过 `view=iptv` 与直播关注分开，频道源和当前自定义分组分别写入 `source`、`group` 查询参数。Shell 只承载关注类型一级页签，频道源 Select 与直播平台/状态 Select 都由关注页侧栏负责；桌面端在左栏顶部显示，移动端显示在分组横条上方。已配置的自定义 M3U 与内置来源由 `playlistSourcesForSettings` 共用构造。自定义分组保留在桌面左栏和移动端横向栏。关注页 Tab 在移动端由 `useHorizontalSwipe` 的双面板 track 跟手切换，点击 Tab 使用短暂淡入平移；IPTV 分组内容复用 `PagePan` 按分组顺序平移。“只看关注”优先使用最新列表元数据，频道不在最新 M3U 中时回退到保存的快照，因此仍可进入 `/iptv/play`。不同自定义 M3U 用地址派生的本地哈希命名空间隔离，原始 M3U 地址不进入关注表或播放路由；当前配置的自定义来源通过同一哈希读取对应关注快照。配置档案导出 IPTV 分组和内置公开源关注，自定义源关注不离开设备。点击频道才会创建播放会话；播放页返回会恢复进入播放前的 IPTV 发现页或关注页。

## 3. 站点模块

| 模块 | 说明 |
|------|------|
| `sites/bilibili/` | 房间、画质、播放、弹幕 token |
| `sites/huya/` | 移动端页 `HNF_GLOBAL_INIT`、anticode、FLV |
| `sites/douyu/` | betard / homeH5Enc、Boa + CryptoJS 签名、getH5Play |
| `sites/douyin/` | `a_bogus` 验签分区列表（推荐/分区可翻页）、SSR 分类、Cookie 会话、SSR → reflow 房间详情/画质/播放、登录搜索 |
| `sites/twitch.rs` | 公开首屏直播列表 / 分类 / 搜索、房间详情与 HLS 播放 token |
| `sites/registry.rs` | 元数据 + `is_ready` |

**斗鱼签名注意：** Boa 需 polyfill `escape` / `unescape` / `String.prototype.substr`，且 CryptoJS 挂到 `globalThis`。

**虎牙注意：** 解析 HTML 中的 JSON 时必须按 UTF-8 字符边界处理，避免中文页 panic。

**抖音注意：** `DouyinSite` 从账号库注入用户 Cookie，并在每个站点实例首次使用时访问直播首页刷新临时 `ttwid` 会话。推荐与分区列表调用网页端分页接口 `webcast/web/partition/detail/room/v2/`，其浏览器验签参数 `a_bogus` 由 `sites/douyin/a_bogus.rs` 在本机以纯 Rust（SM3 + RC4）计算，不需要 JS 运行时；每页 15 条、`offset` 按页递增，因此「加载更多」真实可用。推荐页并非真实分区，使用合成分区 `720/1`；分类树的 `id,type` 会拆成 `partition` 与 `partition_type`（均须为数字），「全部 X」条目 id 为 `0` 时回退到父分区。上游不下发 `has_more`，只有满页且 `offset` 前进时才继续翻页，避免重复拉取。首页首屏若验签失败会回退到 `hot_live` SSR。短房间号优先从 SSR 房间页取得内部 `id_str`，再调用不携带 `.douyin.com` Cookie 或 `msToken` 的公开 reflow 接口取得播放数据，避免受浏览器验签保护的网页进房接口导致 `code=101`。播放 URL 只保存在房间 `raw` 的临时数据中。搜索调用官方网页直播搜索接口，需要完整登录 Cookie，用户可扫码或手动保存；二维码和搜索仍可能遇到网页访问验证，应用不会自动绕过。实时弹幕由 `danmu_rs/douyin_sign.rs` 在本机用 Boa 执行 `webmssdk` 计算短时签名，`danmu_rs/douyin.rs` 组装 WSS 查询串并直连；Cookie 头使用保存 Cookie 加本次临时 `ttwid` / `msToken`，临时值不序列化、不持久化。

**Twitch 注意：** `TwitchSite` 通过公开 GraphQL 获取直播列表、分类、搜索、房间详情和 HLS 播放 token。公开接口的 cursor 翻页会触发完整性校验，因此所有浏览结果都只返回可靠的首屏并设置 `has_more = false`，不伪造翻页。

## 4. 弹幕模块

| 文件 | 协议 |
|------|------|
| `danmu_rs/bilibili.rs` | 二进制帧 + zlib/brotli + JSON cmd |
| `danmu_rs/douyin.rs` | 本地 MSSDK 签名 → WSS；PushFrame / gzip / 最小 protobuf 解码与 ack |
| `danmu_rs/douyin_sign.rs` | Boa + `assets/douyin_webmssdk.js` 计算 WSS `signature` |
| `danmu_rs/douyu.rs` | STT + 小端帧；`native-tls`；端口 8501–8506；借用式逐包解析与进场包早期丢弃；当前网页协议对齐的本机 Cookie 普通弹幕发送 |
| `danmu_rs/huya.rs` | TARS join + uri=1400 聊天；本机 Cookie 认证的普通弹幕发送 |
| `danmu_rs/twitch.rs` | 匿名 IRC WebSocket 聊天 |
| `danmu_rs/tars.rs` | 最小 TARS 编解码 |
| `danmu_rs/mod.rs` | 按站点启动/断开，事件名 `danmaku` |

`DanmakuEvent` 带可选 `SuperChatInfo` 与有序的 `DanmakuContentSpan`。哔哩哔哩 `SUPER_CHAT_MESSAGE` 会在 Rust 层校验并提取消息 ID、金额、币种、时长、颜色元数据和发送者头像 URL，随后通过 Tauri 事件传给前端。SC 前端再次校验头像 URL，仅以无 Referer 方式加载受信任的 B 站 CDN；不会补查或持久化用户资料。播放器左下角最多叠放 3 张卡片，按置顶时长退出；卡片将头像、发送者、金额和倒计时置于身份区，经校验的主色与底色用于下方正文带。普通 B 站聊天会从 `info[0][13].url` 与 `info[0][15].extra.emots` 提取图片表情；只接受 B 站 CDN 的 HTTPS URL，并保留文字/图片原始顺序。

B 站连接关闭、读取失败、认证被拒或长时间无数据时不会以“连接结束”终止：客户端会轮换网关，刷新短时 token 与主机列表后退避重连，并将重连状态写入系统消息。

B 站正式发送在 `danmu_rs/bilibili.rs`：仅 `POST /msg/send` 的单条普通文本；后端先重验与斗鱼、虎牙共用且默认关闭的本机授权 `danmaku_send_enabled`，再校验 `SESSDATA` / `bili_jct`、房间号和文本，并按房间保守冷却。携带 Cookie 的写请求禁止跟随重定向，且不自动重试。

斗鱼发送由 `danmu_rs/douyu.rs` 处理：它重验共用的 `danmaku_send_enabled`、房间、文本和 3 秒本机冷却，并使用用户本机保存的完整会话字段。2026-07-27 的受控诊断发现旧路径采用过期 `loginreq` / 聊天载荷、跳过网页登录后协商并忽略 `chatres` / `error`；当前实现已替换为网页对齐的认证状态机、稳定设备身份、统一 WSS 代理与平台回包解析，并已在个人直播间成功验证。运行时仍将本地提交、`chatres(res=0)` 平台接收与正常收弹幕连接的真实回显分开处理；详见[斗鱼平台 API 文档](斗鱼平台API文档.md)。虎牙发送由 `danmu_rs/huya.rs` 处理：同样先重验共用授权，需要扫码或手动保存含数字账号 ID（`yyuid` 或 `udb_uid`）及登录凭据（`udb_n` / `udb_cred` / `udb_biztoken`）的本机 Cookie，解析房间元数据后校验单条、单行且最多 30 个 UTF-16 单元的文本再写入。扫码实现见 `account/huya_qr.rs`。所有发送路径均不得记录、导出或上传 Cookie，也不得对不确定写入自动重试。

`PlayerPane` 在 `DanmakuSettingsPanel` 之上持有 B 站 / 斗鱼 / 虎牙的房间会话级自动发送调度器，因此切走右侧「设置」标签后仍会随当前直播间运行。它完全在前端复用既有的平台单条发送 command 与校验/状态检查，不新增 Tauri command、数据库字段、`AppSettings` 字段或配置导入导出数据。开关、文本和发送间隔只存于会话内；间隔默认 20 秒，可在 10–3600 秒间调整。只有共用本机授权、当前平台 Cookie/可发送状态和文本校验都有效时才能开启。开启时立即发送首段，将换行和连续空白压缩为一个空格，再按 grapheme 拆成最多 20 个用户可见字符且满足平台 UTF-16 上限的片段；单个超出上限的 grapheme 为校验错误。请求串行不重叠，后续发送起始至少相隔当前会话设置的发送间隔，修改间隔会重排下一次发送，末段后回到首段循环。编辑文本、切房（同时清空会话文本）、离开/卸载播放器、关闭应用或任一发送失败都会立即停止本会话并展示原因；失败或未知写入不会自动重试。

前端不会从本机 command 返回值合成弹幕。右侧列表与 Canvas 只应在房间连接收到平台真实 `DanmakuEvent` 回显后显示消息，并保留平台原有样式；一次本机写入结果不是平台确认。斗鱼会区分本地提交、`chatres` 平台接收与真实回显，三者仍不可混为一谈。

前端：

- `useDanmakuConnection`：哔哩哔哩 / 虎牙 / 斗鱼 / 抖音 / Twitch 进房 `danmaku_connect`；前后端 epoch 栅栏保证切房时过期 connect / disconnect 不能覆盖新房间；抖音在本机签名失败或 WSS 断连时返回可重试提示，Twitch 使用匿名 IRC

播放器只使用并持久化 `playback_soft_switch_enabled`。`playback_smart_line_selection` 与 `playback_stall_auto_switch_enabled` 仅作为旧数据库和配置包的兼容字段保留，前端不再显示或读取。逐房间线路记忆使用设备本地 `rlive-playback-line-preferences`，最多保留最近 100 个房间，不进入配置导入导出。

## 5. 本地语音字幕

本地语音字幕仅在 Tauri 桌面客户端启用。`supportsLocalAsr` 同时校验 Tauri runtime 与 `desktop` 平台；Android 和 iOS 不查询或准备模型、不采集 PCM，并隐藏系统设置、房间设置和播放器入口。

前端 `AudioCapturePipeline` 从播放器 `HTMLVideoElement` 创建共享 `MediaElementAudioSourceNode`，优先加载独立 `AudioWorkletProcessor`。Worklet 在 Web Audio 渲染线程保持原声直通、将声道混合为单声道，并按设置中的 `0.2–1.0 秒`更新间隔（默认 `0.2 秒`）生成无重叠分块；主线程只接收可转移的完整 `Float32Array`，再降采样为 16 kHz 单声道 f32 PCM。旧 WebView 不支持 worklet 或模块加载失败时回退到 `ScriptProcessorNode`。little-endian 原始字节经 Base64/Tauri IPC 传输。`useAsrCaptions` 串行调用 `asr_transcribe`，一个任务执行时只覆盖保存最新待办分块，慢设备不会积累无界队列。endpoint final 与当前 partial 分行显示，父容器使用 `white-space: pre-line` 和自然断词，最多保留两行。

字幕翻译只接收 endpoint final，不发送实时 partial、PCM、热词或声纹。`useCaptionTranslation` 使用独立的 4 项有界队列和 12 秒过期时间，不阻塞 ASR；同一 final 批次中的 segment 通过 `google-translate-api-x` 合并为一次 `batchexecute` 请求，重复 `(from, to, text)` 结果进入 160 项 LRU 缓存，单次请求 8 秒超时。原文和译文语言均允许 `auto`。切房、换源、关闭字幕或修改语言会递增 epoch 并丢弃迟到结果。请求经 Tauri HTTP 发出并继承应用代理，capability 只允许 `https://translate.google.com/**`。Google 返回 `429` 时停止当前翻译队列且不自动重试，原字幕继续显示。

Rust `AsrManager` 在用户明确启用后才下载固定的中英双语 Zipformer 压缩包（`511,274,346` 字节）；自动标点开启时再下载 CT-Transformer 中英标点 int8 压缩包（`64,717,756` 字节），说话人开关启用后按需下载 CAMPPlus 中英声纹 ONNX（`28,281,164` 字节）。默认总量约 `550 MiB`，关闭标点时约 `488 MiB`，开启说话人时约 `576 MiB`。下载写入 `.part` 文件并校验精确长度，bzip2/tar 解压在 blocking 线程池执行；状态依次经过 `downloading`、`extracting`、`loading`、`ready`。前端显式处理 `extracting`，因此首次解压不会因状态分支缺失导致页面黑屏。

`NativeAsrSession` 持有一个 `OnlineRecognizer`、一个跨 IPC 分块复用的 `OnlineStream` 和可选的 `OfflinePunctuation`。Windows 和 Linux x86_64 的 `asr_provider` 支持 `auto`、`cuda`、`cpu`；自动模式通过 CUDA Driver API 读取设备 0 的 Compute Capability，要求官方预编译 runtime 支持的 6.1 及以上，并检查对应平台的 CUDA/cuDNN 依赖和随应用提供的 provider 文件；不可用时回退 CPU，并将实际 provider 与原因返回前端。Linux CUDA runtime 已接入但尚未完成完整硬件和发行版测试。不能直接单独加载 CUDA provider 文件，因为 provider 需要由 ONNX Runtime 完成初始化。CUDA provider 会传递给 Zipformer、标点和声纹模型；VAD 开关控制识别器的 CPU 静音端点规则，当前没有独立 VAD ONNX 会话。无热词时 Zipformer 使用 `greedy_search`，有热词时使用 `modified_beam_search` 并读取原子替换的本地 hotwords 文件；关闭时仍保留 20 秒最长语句边界。标点关闭时不创建标点 native 对象。可选 `NativeSpeakerSession` 对每句 final 的缓存 PCM 提取 CAMPPlus embedding，以 `0.55` 余弦阈值和 `0.68` 切换滞回维护最多 8 个匿名说话人；少于 `0.6 秒` 的短句沿用最近标签，只有 final 携带匿名 `speaker_id`。切房、切换媒体源或关闭字幕会重置 stream、PCM 和聚类编号。CPU provider 下识别最多使用 8 个线程，标点与声纹最多使用 2 个线程；同一 native 会话由互斥锁串行驱动。

`asr_enabled`、`asr_vad_enabled`、`asr_punctuation_enabled`、`asr_speaker_diarization_enabled`、`asr_hotwords`、`asr_window_seconds` 和 `asr_translation_*` 是设备本地设置，不随配置包导入导出；`asr_font_size` 是可移植的显示设置。模型文件、hotwords、PCM、embedding、聚类质心与字幕均不进入 SQLite。完整说明见[本地语音字幕](本地语音字幕.md)。

## 6. 浏览器访问（web platform）

`src-tauri/src/web_bridge/` 是一个默认关闭的本机 HTTP 服务，让同一套打包前端在普通浏览器标签页中运行，而不是只能运行在 Tauri WebView 里。它不是第二套实现：

- **静态资源**由 `AppHandle::asset_resolver()` 直接返回打包后的 Vite 产物，因此不存在单独的 `frontendDist` 路径处理；未命中且不含扩展名的路径回退 `index.html` 以支持 SPA 路由。`assets/` 使用 `immutable` 长缓存，其余为 `no-cache`。
- **命令**走 `POST /api/invoke/<cmd>`。`web_bridge/dispatch.rs` 把命令名映射到既有 `#[tauri::command]` 函数并共用同一个 `AppState`，所以浏览器执行的是与 WebView 完全相同的 Rust 代码路径，新增命令只需在该表中登记一行。命令失败通过 HTTP 200 的 `{"error": AppError}` 返回，前端因此只有一条解码路径，`AppError` 形状与 `invoke` 的 reject 完全一致。
- **弹幕**走 `GET /api/events` 的 Server-Sent Events，把 Rust 侧 `danmaku-batch` 事件原样转发。校验、epoch 围栏和分发逻辑仍在 `src/features/room/danmaku/eventBus.ts` 中共用，只有监听方式不同。SSE 队列有界（64 条）并使用 `try_send`，浏览器读取过慢只会丢帧，不会阻塞弹幕管线。
- **前端选择传输层**的唯一位置是 `src/shared/api/tauri.ts`：`isTauri()` 为假时探测一次 `/api/status`，成功则改用桥接传输，失败则保留原有「请在 rLive 客户端中使用」错误，因此普通 `bun run dev` 预览行为不变。

已知限制：`stream_proxy` 仍只监听 `127.0.0.1`，且把 HLS 清单改写到该 origin，因此局域网设备打开的页面可以浏览、搜索、管理关注和接收弹幕，但播放地址会指向设备自身而失败。让远端播放需要把播放代理也绑定到局域网接口，这会把媒体代理一并暴露，属于独立的安全决策，当前不做。

安全边界：默认只监听 `127.0.0.1`。局域网暴露必须在客户端里显式开启，并生成 64 个十六进制字符（两个 v4 UUID，256 位熵）的随机令牌；`/api/` 请求需 `Authorization: Bearer`，无法设置请求头的 `EventSource` 与首次导航使用 `?token=`，令牌以常量时间比较。前端把令牌存入 `sessionStorage`，标签页关闭即失效。`web_bridge_start` 与 `web_bridge_stop` 位于 `NATIVE_ONLY_COMMANDS`，浏览器标签页可以读取状态但不能开启局域网监听或关闭自己所依赖的传输层——这个决定留在本机窗口一侧。需要本机文件对话框、麦克风 IPC 或 Android 播放器控制的命令同样列入 `NATIVE_ONLY_COMMANDS`，对应 UI 在浏览器中隐藏而非半可用。关闭窗口时与 `stream_proxy` / `image_proxy` / `lan_sync` 一同停止。

## 8. 构建与交付

- 开发：WSL `/home/.../rLive`  
- 运行：Windows `scripts/windows-sync.conf` 中 `WINDOWS_SYNC_PATH` 指定目录 → `rlive.exe`
- 一键：`./scripts/build-windows-from-wsl.sh`  

Windows 构建脚本使用 MSVC + sherpa-onnx shared libraries，默认下载 CUDA-capable `sherpa-onnx-v1.13.4-win-x64-cuda.tar.bz2` runtime，并把 `lib/` 导入库和 `bin/` DLL 复制到 Cargo 输出目录；该包需要 CUDA 11.x/cuDNN 8.x x86-64 DLL，设置 `SHERPA_ONNX_GPU=0` 可构建 CPU-only shared runtime。运行时仍需 NVIDIA 驱动及兼容 CUDA/cuDNN DLL。Linux x86_64 默认使用 `sherpa-onnx-v1.13.4-linux-x64-gpu.tar.bz2`，主机需 CUDA 11.x/cuDNN 8.x；Linux CUDA 路径尚未完成完整硬件和发行版测试。Android 通过 Tauri CLI 使用 NDK 工具链；Rust target 通过条件编译排除 ASR module、commands、state 及 `sherpa-onnx`、ONNX Runtime 和模型解压依赖，移动端不暴露字幕功能，也不会下载字幕模型。命令与依赖见[Android 开发与构建](Android开发-Windows.md)。

Release：`lto = "thin"`、`panic = "abort"`，故后端 panic 会导致进程退出，站点解析必须避免未处理 panic。
