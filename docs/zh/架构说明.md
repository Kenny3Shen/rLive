# rLive 架构说明

## 1. 总体结构

```
┌─────────────────────────────────────────────┐
│  React UI (中文)                              │
│  首页 / 关注 / 分类 / 历史 / IPTV / 设置 / 房间页 │
│  mpegts.js / hls.js 播放 · Canvas 弹幕 · SC 面板 │
└──────────────────┬──────────────────────────┘
                   │ Tauri commands / events
┌──────────────────▼──────────────────────────┐
│  Rust (src-tauri)                             │
│  LiveSite · stream_proxy · danmaku WS · DB    │
└─────────────────────────────────────────────┘
```

| 目录 | 职责 |
|------|------|
| `src/` | 前端：页面、播放控制、弹幕引擎、设置 |
| `src-tauri/src/sites/` | 各站点 HTTP / 签名 / 房间解析 |
| `src-tauri/src/danmaku/` | 弹幕 WebSocket 与协议解析 |
| `src-tauri/src/stream_proxy.rs` | 本机流媒体代理（CORS / Referer） |
| `src-tauri/src/iptv/` | M3U 获取、大小限制与频道元数据解析 |
| `src-tauri/src/db/` | SQLite：关注、历史、设置、Cookie |
| `scripts/` | WSL 同步与 Windows 构建 |

## 2. 播放路径

1. `LiveSite::get_play_urls` 拿到带 headers 的 FLV/HLS 地址。  
2. 前端请求 `stream_proxy_start`，Rust 在 `127.0.0.1` 起本地服务。  
3. 浏览器访问 `http://127.0.0.1:<port>/...`，代理向上游带正确 UA/Referer。  
4. 直播 FLV 使用 `mpegts.js` 以 MSE 播放；IPTV HLS 使用 `hls.js`，MPEG-TS / FLV 复用 `mpegts.js`。HLS 清单中的子清单、密钥与分片会在本机代理中改写到受限的 localhost 资源路径。

每次播放器会话会携带唯一 session ID；停止请求只会关闭同一会话持有的代理，因此快速离开并再次进入同一房间时，旧清理不会误关新代理而造成黑屏。播放控制以透明层叠放在画面底部，播放闲置后自动隐藏，指针、点击或键盘操作会再次显示。

IPTV 前端将 `/iptv` 作为仅用于发现的首页：展示来源、分类、搜索和频道列表，进入时不会创建播放器或代理会话，也不会默认播放第一个流。自定义 HTTP(S) M3U 地址只能在「设置 → 网络」保存；首页选中 `source=custom` 时从本机设置解析，地址本身不会写入路由、历史或配置包。点击频道才会进入独立、沉浸式的 `/iptv/play` 路由并创建播放会话；该页返回会恢复带来源、分类和搜索条件的频道列表。

## 3. 站点模块

| 模块 | 说明 |
|------|------|
| `sites/bilibili/` | 房间、画质、播放、弹幕 token |
| `sites/huya/` | 移动端页 `HNF_GLOBAL_INIT`、anticode、FLV |
| `sites/douyu/` | betard / homeH5Enc、Boa + CryptoJS 签名、getH5Play |
| `sites/douyin.rs` | SSR 分类/首屏列表、Cookie 会话、房间详情/画质/播放、登录搜索 |
| `sites/kuaishou.rs` | 公开推荐 / 分类 / 游戏分区、房间 SSR 初始状态、H.264 优先播放；无实时弹幕 |
| `sites/twitch.rs` | 公开首屏直播列表 / 分类 / 搜索、房间详情与 HLS 播放 token |
| `sites/registry.rs` | 元数据 + `is_ready` |

**斗鱼签名注意：** Boa 需 polyfill `escape` / `unescape` / `String.prototype.substr`，且 CryptoJS 挂到 `globalThis`。

**虎牙注意：** 解析 HTML 中的 JSON 时必须按 UTF-8 字符边界处理，避免中文页 panic。

**抖音注意：** `DouyinSite` 从账号库注入用户 Cookie，并在未提供 `ttwid` 时临时访问直播首页建立会话。推荐与分类读取直播页 SSR/RSC 数据；公开 SSR 的偏移参数不可靠，因此只公开首屏并返回 `has_more = false`，避免重复房间。房间详情优先尝试网页接口，受风控时回退 SSR；播放 URL 只保存在房间 `raw` 的临时数据中。搜索调用官方网页直播搜索接口，需要完整登录 Cookie，用户可扫码或手动保存。实时弹幕由 `danmaku/douyin.rs` 固定调用本机 `http://127.0.0.1:18080/sign` 换取短时 WSS URL；签名请求使用与房间解析相同的有效会话（保存 Cookie 加本次临时 `ttwid` / `msToken`），临时值不序列化、不持久化；该请求不走全局代理且不跟随重定向，因此携带 Cookie 的请求体始终停留在本机回环连接上。

**Twitch 注意：** `TwitchSite` 通过公开 GraphQL 获取直播列表、分类、搜索、房间详情和 HLS 播放 token。公开接口的 cursor 翻页会触发完整性校验，因此所有浏览结果都只返回可靠的首屏并设置 `has_more = false`，不伪造翻页。

## 4. 弹幕模块

| 文件 | 协议 |
|------|------|
| `danmaku/bilibili.rs` | 二进制帧 + zlib/brotli + JSON cmd |
| `danmaku/douyin.rs` | 固定本机签名服务 → WSS；PushFrame / gzip / 最小 protobuf 解码与 ack |
| `danmaku/douyu.rs` | STT + 小端帧；`native-tls`；端口 8501–8506；借用式逐包解析与进场包早期丢弃；本机 Cookie 认证的普通弹幕发送 |
| `danmaku/huya.rs` | TARS join + uri=1400 聊天；本机 Cookie 认证的普通弹幕发送 |
| `danmaku/twitch.rs` | 匿名 IRC WebSocket 聊天 |
| `danmaku/tars.rs` | 最小 TARS 编解码 |
| `danmaku/mod.rs` | 按站点启动/断开，事件名 `danmaku` |

`DanmakuEvent` 带可选 `SuperChatInfo` 与有序的 `DanmakuContentSpan`。哔哩哔哩 `SUPER_CHAT_MESSAGE` 会在 Rust 层校验并提取消息 ID、金额、币种、时长、颜色元数据和发送者头像 URL，随后通过 Tauri 事件传给前端。SC 前端再次校验头像 URL，仅以无 Referer 方式加载受信任的 B 站 CDN；不会补查或持久化用户资料。卡片将头像、发送者、金额和置顶时长置于浅色身份区，经校验的主色与底色用于下方完整正文带。普通 B 站聊天会从 `info[0][13].url` 与 `info[0][15].extra.emots` 提取图片表情；只接受 B 站 CDN 的 HTTPS URL，并保留文字/图片原始顺序。

B 站连接关闭、读取失败、认证被拒或长时间无数据时不会以“连接结束”终止：客户端会轮换网关，刷新短时 token 与主机列表后退避重连，并将重连状态写入系统消息。

B 站正式发送在 `danmaku/bilibili.rs`：仅 `POST /msg/send` 的单条普通文本；后端重验本机发送授权、`SESSDATA` / `bili_jct`、房间号和文本，按房间保守冷却。携带 Cookie 的写请求禁止跟随重定向，且不自动重试或生成本地回显。发布构建不装载 MCP bridge，避免本机自动化桥绕过本机发送授权或用户主动操作的 UI 入口。

斗鱼发送由 `danmaku/douyu.rs` 处理：需要本机保存的 `acf_username`、`acf_stk`、`acf_ltkid` Cookie 字段，可通过扫码登录或手动输入保存；短时认证会话写入前会校验单条、单行且最多 100 个 UTF-16 单元的文本，并按房间保守冷却 3 秒。虎牙发送由 `danmaku/huya.rs` 处理：需要手动保存含数字账号 ID（`yyuid` 或 `udb_uid`）及不透明登录凭据（`udb_n` 或 `udb_cred`）的本机 Cookie，解析房间元数据后校验单条、单行且最多 30 个 UTF-16 单元的文本再写入。两者均不会记录、导出或上传 Cookie，不会对不确定的写入自动重试，也不会生成乐观本地事件；正常房间弹幕连接仍是回显的唯一依据。

这两项本机 Cookie 发送功能是刻意收窄的用户能力，不表示斗鱼或虎牙已向 rLive 授予公开应用写入 API。一次本机写入结果不代表上游一定接受；用户仍需在有权发言的房间完成真实服务验证，并自行遵守平台条款、审核规则和当地法律。

前端：

- `useDanmakuConnection`：哔哩哔哩 / 虎牙 / 斗鱼 / 抖音 / Twitch 进房 `danmaku_connect`；前后端 epoch 栅栏保证切房时过期 connect / disconnect 不能覆盖新房间；本机抖音签名服务不可用时会返回明确启动提示，Twitch 使用匿名 IRC，快手仍呈现“不支持实时弹幕”状态
- `DanmakuPanel`：按 `requestAnimationFrame` 合批、限制等待队列、非平滑自动滚动的消息列表；统一隐藏进场提示及可选礼物，右侧列表保留每条通过筛选的消息；B 站、斗鱼、虎牙房间的播放器功能栏中间都挂载本机账号状态控制的单条发送框：B 站另需显式本机发送授权，斗鱼支持扫码/手动 Cookie，虎牙支持手动 Cookie
- `CanvasDanmaku` + `danmakuEngine`：顶部向下分配飘屏轨道；普通聊天同样按内容进行 5 秒聚合；B 站图片表情由小型 LRU 图片/位图缓存按原始顺序绘制，尚未加载时保留文字回退；无活跃项目时不再请求动画帧，消息/设置/尺寸变化时恢复；显示区域、行数和字重实时生效
- `SuperChatPanel` + `superChat.ts`：仅 `super_chat`，将安全校验后的 B 站主色/底色用于金额标题带，并负责金额/时长、去重和有界帧合批
- `DanmakuSettingsPanel`：房间侧栏的 Simple Live 风格即时设置；`FollowPanel`：直播优先的关注列表与替换式直接路由切换，房间返回会回首页而非上一间直播间
- `danmaku/filter`：预编译屏蔽词、有界内容聚合器与飘屏文案

设置字段（SQLite / `AppSettings`）：`danmaku_area`、`danmaku_line_count`、`danmaku_opacity`、`danmaku_font_size`、`danmaku_font_weight`、`danmaku_speed`、`danmaku_filter_repeats`、`danmaku_filter_gifts`、`danmaku_shield_words`、`bilibili_danmaku_send_enabled`、`iptv_custom_m3u_url`。Cookie 独立保存在 `cookies` 表；配置导出还会排除 `bilibili_danmaku_send_enabled` 与 `iptv_custom_m3u_url`，导入时保留这些本机私有值，避免非受信配置启用发送或替换私有节目源地址。抖音签名服务地址固定在代码中，不写入设置。

## 6. 构建与交付

- 开发：WSL `/home/.../rLive`  
- 运行：Windows `D:\dev\rLive` → `rlive.exe`  
- 一键：`./scripts/build-windows-from-wsl.sh`  

Release：`lto = "thin"`、`panic = "abort"`，故后端 panic 会导致进程退出，站点解析必须避免未处理 panic。

## 7. 扩展建议

| 目标 | 建议入口 |
|------|----------|
| 抖音分页 | 在有可靠、合规的网页签名/会话方案后接入 `partition/detail/room/v2`，不要用 SSR offset 伪分页 |
| 抖音弹幕 | 已通过固定本机签名服务实现；扩展消息类型时在 `danmaku/douyin.rs` 增加最小 protobuf 字段解析 |
| 快手弹幕 | 需要独立的公开协议调研；当前不建立实时弹幕连接 |
| 更多 SC 字段 | 扩展 `DanmakuEvent` 与 B 站 SUPER_CHAT 解析 |
