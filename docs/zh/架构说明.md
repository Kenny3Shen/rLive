# rLive 架构说明

## 1. 总体结构

```
┌─────────────────────────────────────────────┐
│  React UI (中文)                              │
│  首页 / 关注 / 分类 / 历史 / 设置 / 房间页      │
│  mpegts.js 播放 · Canvas 弹幕 · SC 面板        │
└──────────────────┬──────────────────────────┘
                   │ Tauri commands / events
┌──────────────────▼──────────────────────────┐
│  Rust (src-tauri)                             │
│  LiveSite · stream_proxy · danmaku WS · DB    │
└─────────────────────────────────────────────┘
```

| 目录 | 职责 |
|------|------|
| `src/` | 前端：页面、播放控制、弹幕引擎、设置 |
| `src-tauri/src/sites/` | 各站点 HTTP / 签名 / 房间解析 |
| `src-tauri/src/danmaku/` | 弹幕 WebSocket 与协议解析 |
| `src-tauri/src/stream_proxy.rs` | 本机流媒体代理（CORS / Referer） |
| `src-tauri/src/db/` | SQLite：关注、历史、设置、Cookie |
| `scripts/` | WSL 同步与 Windows 构建 |

## 2. 播放路径

1. `LiveSite::get_play_urls` 拿到带 headers 的 FLV/HLS 地址。  
2. 前端请求 `stream_proxy_start`，Rust 在 `127.0.0.1` 起本地服务。  
3. 浏览器访问 `http://127.0.0.1:<port>/...`，代理向上游带正确 UA/Referer。  
4. `mpegts.js` 以 MSE 播放。  

离开房间时停止代理与播放器，避免孤儿进程与黑屏状态。播放控制以透明层叠放在画面底部，播放闲置后自动隐藏，指针、点击或键盘操作会再次显示。

## 3. 站点模块

| 模块 | 说明 |
|------|------|
| `sites/bilibili/` | 房间、画质、播放、弹幕 token |
| `sites/huya/` | 移动端页 `HNF_GLOBAL_INIT`、anticode、FLV |
| `sites/douyu/` | betard / homeH5Enc、Boa + CryptoJS 签名、getH5Play |
| `sites/douyin.rs` | SSR 分类/首屏列表、Cookie 会话、房间详情/画质/播放、登录搜索 |
| `sites/kuaishou.rs` | 占位 |
| `sites/registry.rs` | 元数据 + `is_ready` |

**斗鱼签名注意：** Boa 需 polyfill `escape` / `unescape` / `String.prototype.substr`，且 CryptoJS 挂到 `globalThis`。

**虎牙注意：** 解析 HTML 中的 JSON 时必须按 UTF-8 字符边界处理，避免中文页 panic。

**抖音注意：** `DouyinSite` 从账号库注入用户 Cookie，并在未提供 `ttwid` 时临时访问直播首页建立会话。推荐与分类读取直播页 SSR/RSC 数据；公开 SSR 的偏移参数不可靠，因此只公开首屏并返回 `has_more = false`，避免重复房间。房间详情优先尝试网页接口，受风控时回退 SSR；播放 URL 只保存在房间 `raw` 的临时数据中。搜索调用官方网页直播搜索接口，需要完整登录 Cookie。实时 WebSocket/protobuf 弹幕尚未实现。

## 4. 弹幕模块

| 文件 | 协议 |
|------|------|
| `danmaku/bilibili.rs` | 二进制帧 + zlib/brotli + JSON cmd |
| `danmaku/douyu.rs` | STT + 小端帧；`native-tls`；端口 8501–8506；借用式逐包解析与进场包早期丢弃 |
| `danmaku/huya.rs` | TARS join + uri=1400 聊天 |
| `danmaku/tars.rs` | 最小 TARS 编解码 |
| `danmaku/mod.rs` | 按站点启动/断开，事件名 `danmaku` |

`DanmakuEvent` 带可选 `SuperChatInfo`。哔哩哔哩 `SUPER_CHAT_MESSAGE` 会在 Rust 层校验并提取消息 ID、金额、币种、主/副背景色、时长，随后通过 Tauri 事件传给前端。

前端：

- `useDanmakuConnection`：仅哔哩哔哩 / 虎牙 / 斗鱼进房 `danmaku_connect`；前后端 epoch 栅栏保证切房时过期 connect / disconnect 不能覆盖新房间；抖音和快手呈现“不支持实时弹幕”状态
- `DanmakuPanel`：按 `requestAnimationFrame` 合批、限制等待队列、非平滑自动滚动的消息列表；统一隐藏进场提示，以及可选的礼物与重复聊天
- `CanvasDanmaku` + `danmakuEngine`：顶部向下分配飘屏轨道；无活跃项目时不再请求动画帧，消息/设置/尺寸变化时恢复；显示区域、行数和字重实时生效
- `SuperChatPanel` + `superChat.ts`：仅 `super_chat`，安全色板、金额/时长、去重和有界帧合批  
- `DanmakuSettingsPanel`：房间侧栏的 Simple Live 风格即时设置；`FollowPanel`：直播优先的关注列表与直接路由切换  
- `danmaku/filter`：预编译屏蔽词、重复匹配器与飘屏文案  

设置字段（SQLite / `AppSettings`）：`danmaku_area`、`danmaku_line_count`、`danmaku_opacity`、`danmaku_font_size`、`danmaku_font_weight`、`danmaku_speed`、`danmaku_filter_repeats`、`danmaku_filter_gifts`、`danmaku_shield_words`。

## 6. 构建与交付

- 开发：WSL `/home/.../rLive`  
- 运行：Windows `D:\dev\rLive` → `rlive.exe`  
- 一键：`./scripts/build-windows-from-wsl.sh`  

Release：`lto = "thin"`、`panic = "abort"`，故后端 panic 会导致进程退出，站点解析必须避免未处理 panic。
