# 抖音弹幕签名服务接入

rLive 可以连接抖音实时弹幕，但 WSS 地址有短时签名。应用不包含签名算法；请配置你自己运行或明确信任的签名服务。这样 Cookie 和签名逻辑都保持在你选择的边界内。

## 设置地址

在「设置 → 账号 → 抖音实时弹幕」填入**完整请求地址**，例如：

```text
http://127.0.0.1:18080/sign
```

安全规则：仅接受 `https://…`，或 `http://localhost`、`http://127.0.0.1`、`http://[::1]` 等本机回环地址。HTTP 公网地址会被拒绝，防止把保存的 Cookie 明文交给网络服务。

rLive 不跟随签名服务返回的 HTTP 重定向；服务必须在配置的端点直接返回响应。这样 307 / 308 也无法把请求中的 Cookie 转发到其他地址。

## 请求契约

rLive 以 JSON `POST` 调用配置的地址：

```json
{
  "roomId": "7666175273884879635",
  "liveId": "522864404974",
  "cookie": "sessionid=…; ttwid=…; msToken=…"
}
```

- `roomId` 是内部实际房间 ID；`liveId` 是 `live.douyin.com/{liveId}` 的网页房间 ID。
- `cookie` 是用户在 rLive 本机账号设置中保存的抖音 Cookie；为空时仍会传空字符串，服务可匿名签名。
- 不要记录请求体、Cookie、最终带签名 WSS URL 或签名参数。

## 响应契约

服务需返回 HTTP 2xx 和下列 JSON：

```json
{
  "wssUrl": "wss://example.douyin.com/webcast/im/push/v2/?…&signature=…",
  "headers": {
    "Cookie": "ttwid=…",
    "User-Agent": "Mozilla/5.0 …",
    "Origin": "https://live.douyin.com"
  },
  "heartbeat": {
    "intervalMs": 10000
  }
}
```

- `wssUrl` 必须是 `wss://`；签名失效或连接重进时 rLive 会重新请求服务。
- `headers` 可选。rLive 仅转发 `Cookie`、`User-Agent`、`Origin`、`Referer` 和 `X-*` 请求头；不会接受 `Host`、`Connection`、`Upgrade` 或 `Sec-WebSocket-*` 覆盖。
- `heartbeat.intervalMs` 可选，默认 10 秒，并被限制在 3–60 秒之间。

连接后 rLive 发送标准心跳，处理 gzip `PushFrame`，收到 `needAck` 时回传 ack，并解析普通聊天、表情聊天、礼物、点赞、进场和常见社交事件。

## 失败处理

| 提示 | 处理 |
|------|------|
| 缺少签名服务 | 保存完整端点后重新进入房间 |
| HTTP / 响应格式错误 | 检查服务是否返回上述 JSON，勿在错误日志中打印敏感参数 |
| WSS 连接失败 | 确认 URL 未过期、服务返回的 Cookie/UA/Origin 与签名一致；重新进房会重新签名 |
| 抖音风控 | 更新网页登录 Cookie、降低请求频率，遵守平台条款 |

该接口是一个传输契约，不指定或分发任何绕过签名/风控的实现。
