# 2.0 严格断代

## 目标与边界

rLive 2.0 将应用自身的数据格式和 IPC 协议固定为当前版本，明确不再兼容任何旧版本的应用数据。这里的断代范围包括 SQLite 数据库、设置记录、profile、局域网同步协议、localStorage、录制目录配置和录制 bundle。

浏览器/WebView 能力差异、直播平台接口回退、网络故障恢复、播放器重建、音频采集 fallback 和第三方库补丁属于当前运行环境支持，继续保留，不属于版本数据兼容。

## 2.0 断代规则

- 应用版本为 `2.0.0`。
- SQLite 使用 `PRAGMA user_version = 3`。空白数据库创建当前 schema；已有版本 `1`、`2`、未知版本，或无版本但已经包含表的数据库返回 `db_schema_unsupported`，不会迁移、补列或改写。
- 设置记录按当前 `AppSettings` 严格解析。损坏 JSON、未知字段和缺少必填字段返回 `settings_schema_unsupported`，不再静默恢复默认值；删除 `recording_auto_follow` 兼容别名，`recording_ass` 为必填对象。
- profile 固定为 `version: 2`，拒绝旧版本、缺少版本、未知字段和缺少 2.0 portable 字段。发送授权、ASR 本机开关和私有 M3U 等本机字段继续不进入 profile，由当前设备显式初始化。
- 局域网同步固定使用 `/rlive-sync/v2/profile` 和 `X-rLive-Sync-Version: 2`。旧路径或旧响应返回 `lan_sync_protocol_error`。
- 设置和多画面 localStorage 使用 `rlive-settings-v2`、`rlive-multi-room-v2`。旧 key 不读取、不双写、不迁移，也不自动删除。
- 录制目录配置使用 `recording-storage-v2.json`，`schemaVersion` 必须为 `2`。旧 `recording-storage.json` 仅记录 warning 并忽略，不读取、不删除。
- 录制 `metadata.json` 必须包含 `schema_version: 2`，且拒绝未知字段。旧版本、缺字段或损坏 metadata 的 bundle 在扫描时跳过并记录 warning，不自动删除。
- 新录制继续由 FFmpeg 写入 FLV keyframe index；2.0 不再为旧 FLV 补索引，也不再自动修复旧录制。
- 现行的录制目录切换和 bundle 整体迁移仍然支持，但这不是旧版本格式迁移。

## 升级前处理

升级到 2.0 前，应在旧版本中完成以下操作：

1. 从设置中导出当前版本支持的 profile。
2. 单独备份旧 `rlive.db` 和录制目录。
3. 安装 2.0 后使用新数据目录导入 profile。
4. 旧数据库、旧 profile、旧 localStorage、旧录制配置和旧录制 bundle 不应直接交给 2.0；需要读取旧录制时仍使用旧版本或外部工具。

2.0 不会删除这些旧文件，因此用户可以自行保留、备份或处理；应用不会提供隐式转换路径。

## 继续保留的运行时容错

- AudioWorklet 失败后的 ScriptProcessor、WebKit Fullscreen、剪贴板和 Android WebView 方向处理。
- B 站接口回退、Twitch 广告播放列表恢复、播放线路重建、网络重试和 IPTV 手动重试。
- `danmu.js` 当前版本补丁，以及播放器协议不兼容时的完整重建。

## 发布门槛

- `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 和 `src-tauri/Cargo.lock` 根包均为 `2.0.0`。
- 新 DB 创建、旧 DB 拒绝、严格设置/Profile/LAN 校验、新 localStorage key、旧录制 metadata 跳过和新录制索引均有自动化测试。
- `bun run check`、`bun test tests/`、`bun run build` 和 Rust 测试通过。
- 发布说明明确数据库断代、旧录制跳过行为、备份要求和不支持旧版本的范围。
