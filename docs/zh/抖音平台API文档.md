# 抖音平台 API 文档

更新时间：2026-07-27。本页说明 rLive 对抖音直播网页数据、播放和实时弹幕的接入边界；它不是抖音开放平台或直播 SDK 的官方开发文档。

## 能力总览

| 能力 | 状态 | rLive 行为 |
| --- | --- | --- |
| 分类、推荐 | 已支持 | 匿名 SSR 数据可靠支持首屏；后续浏览器验签分页不显示为“加载更多”。 |
| 搜索 | 已支持 | 需要完整登录 Cookie；仅在上游成功返回时展示结果。 |
| 房间详情与播放 | 已支持 | 解析网页和回流接口，提供上游实际下发的清晰度与播放地址。 |
| 账号 | 已支持 | 可扫码登录或手动保存 Cookie；匿名浏览会建立短时网页会话。 |
| 实时弹幕接收 | 已支持 | 通过用户配置的签名服务取得短时 WSS 地址，接收聊天、礼物、点赞、进场等事件。 |
| 弹幕发送 | 未支持 | 现有签名只用于接收连接，不能推导为写入权限。 |

## rLive 接入接口

抖音同样提供统一的列表、搜索、房间、清晰度和播放接口。匿名推荐和分类的 SSR 页面目前只可靠提供首屏，因此 rLive 不伪造偏移翻页，也不会用保存的 Cookie 调用依赖浏览器验签与 cursor 的后续分页接口；界面不会显示不可用的「加载更多」。

短房间号会先解析 SSR 房间页中的内部房间号，再使用公开 reflow 接口取得播放数据；该请求不携带 `.douyin.com` Cookie 或 `msToken`，避免向其他域重放登录态，也避免受浏览器验签保护的网页进房接口返回 `code=101`。播放地址为短时网页数据，刷新房间或播放失败后应重新获取。

## 签名服务与弹幕

抖音实时弹幕连接地址受短时签名保护。rLive 不内置逆向签名算法，也不随应用附带签名服务。请在「设置 → 账号 → 抖音实时弹幕」填写你自行运行或明确信任的**完整**服务地址，例如：

```text
http://127.0.0.1:18080/sign
```

为保护有效网页会话，服务地址只允许 HTTPS，或 `localhost`、`127.0.0.1`、`::1` 上的 HTTP；地址中不能包含账号、密码或片段。请求永不跟随重定向。本机 HTTP 服务不走全局代理；HTTPS 服务遵循用户显式配置的代理。兼容服务须返回当前房间可用的短时 WSS 地址；rLive 随后完成心跳、确认帧和入站事件解码。

完整登录 Cookie 能提高房间和签名会话的可用性。连接时，rLive 只会把本次有效会话交给用户配置的签名服务，且不会在日志、前端缓存或配置导出中保存 Cookie、短时 WSS URL 或服务地址。配置导入也不会覆盖当前设备上的签名服务地址。

### 服务协议

应用向该地址发出 JSON `POST` 请求，字段为 `roomId`、`liveId` 和 `cookie`。兼容服务返回 `wssUrl`（或 `wss_url`），可选返回 `headers` 对象和 `heartbeat.intervalMs`（或 `heartbeat.interval_ms`）。返回地址必须是安全的 `wss://` 地址；这些值只在本次连接中使用，既不会显示在界面，也不会写入日志。

### 诊断记录

此前实现把地址强制写死为 `127.0.0.1:18080/sign`，但安装包未提供对应服务，也没有设置入口，因此未另行启动该服务的用户会在进房时立即失败。当前实现恢复了可见的本机配置入口，且在未配置、地址不安全、连接失败和响应无效时分别给出可操作的提示；这不会分发或模拟签名/风控绕过逻辑。

签名服务能够建立接收连接，不代表具有以用户身份发送聊天的能力。rLive 当前没有抖音弹幕发送入口；只有在平台提供适用于桌面客户端的正式互动授权、审核与限频契约后，才应重新评估。

## 限制与安全

Cookie、短时签名 URL 和上游原始响应均不写入日志或前端缓存。二维码、搜索等网页接口可能返回浏览器访问验证页；应用会使用用户显式配置的 HTTP(S) 代理，但不会伪造签名或自动完成验证。访问验证、Cookie 时效、地区和平台风控仍可能导致列表、搜索、房间或播放失败；应用会保留已验证的首屏结果，而不是重复或伪造数据。
