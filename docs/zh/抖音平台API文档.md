# 抖音平台 API 文档

更新时间：2026-07-27。本页说明 rLive 对抖音直播网页数据、播放和实时弹幕的接入边界；它不是抖音开放平台或直播 SDK 的官方开发文档。

## 能力总览

| 能力 | 状态 | rLive 行为 |
| --- | --- | --- |
| 分类、推荐 | 已支持 | 匿名 SSR 数据可靠支持首屏；有效网页登录态可尝试平台实际分页。 |
| 搜索 | 已支持 | 需要完整登录 Cookie；仅在上游成功返回时展示结果。 |
| 房间详情与播放 | 已支持 | 解析网页和回流接口，提供上游实际下发的清晰度与播放地址。 |
| 账号 | 已支持 | 可扫码登录或手动保存 Cookie；匿名浏览会建立短时网页会话。 |
| 实时弹幕接收 | 已支持 | 通过固定本机签名服务取得短时 WSS 地址，接收聊天、礼物、点赞、进场等事件。 |
| 弹幕发送 | 未支持 | 现有签名只用于接收连接，不能推导为写入权限。 |

## rLive 接入接口

抖音同样提供统一的列表、搜索、房间、清晰度和播放接口。匿名推荐和分类的 SSR 页面目前只可靠提供首屏，因此 rLive 不伪造偏移翻页。保存完整 Cookie 后，适配器才会尝试抖音网页自身的分页接口；只有上游实际返回下一页时，界面才显示「加载更多」。

房间详情优先使用网页房间数据，并在可恢复错误时刷新短时网页会话后重试；必要时回退到 SSR 解析。播放地址为短时网页数据，刷新房间或播放失败后应重新获取。

## 本机签名服务与弹幕

抖音实时弹幕连接地址受短时签名保护。rLive 不内置逆向签名算法，固定请求：

```text
http://127.0.0.1:18080/sign
```

该请求只允许 loopback 地址、不使用全局代理、也不跟随重定向。兼容的本机服务须返回当前房间可用的短时 WSS 地址；rLive 随后完成心跳、确认帧和入站事件解码。完整登录 Cookie 能提高房间和签名会话的可用性，但不会上传到签名服务以外的远程位置。

签名服务能够建立接收连接，不代表具有以用户身份发送聊天的能力。rLive 当前没有抖音弹幕发送入口；只有在平台提供适用于桌面客户端的正式互动授权、审核与限频契约后，才应重新评估。

## 限制与安全

Cookie、短时签名 URL 和上游原始响应均不写入日志或前端缓存。网页接口的访问验证、Cookie 时效、地区和平台风控可能导致列表、搜索、房间或播放失败；应用会保留已验证的首屏结果，而不是重复或伪造数据。

- 弹幕连接与帧解析：`src-tauri/src/danmaku/douyin.rs`
- 本机签名服务调用：`src-tauri/src/commands/danmaku.rs`
