# rLive 用户指南

## 1. 简介

rLive 是桌面端直播聚合客户端，可在同一应用内浏览、搜索、观看多平台直播，并接收弹幕。界面以中文为主，风格接近 Simple Live 桌面端。

当前站点状态：

| 站点 | 列表 / 搜索 | 播放 | 弹幕 |
|------|-------------|------|------|
| 哔哩哔哩 | ✓ | ✓ | ✓（建议配置 Cookie；正式支持单条发送，需本机授权） |
| 虎牙 | ✓ | ✓ | ✓ |
| 斗鱼 | ✓ | ✓ | ✓ |
| 抖音 | 首屏推荐 / 分类；搜索需登录 Cookie | ✓ | ✓（需签名服务） |
| 快手 | 推荐 / 分类 / 游戏分区搜索 | ✓ | 暂不支持 |

抖音公开网页的服务端渲染列表当前仅稳定提供首屏。应用不会伪造“加载更多”，以避免重复房间；保存完整登录 Cookie 后可使用抖音直播搜索。

抖音实时弹幕使用公开 WSS 帧协议，但连接地址由短时签名保护。rLive 不内置逆向签名算法；请在「设置 → 账号 → 抖音实时弹幕」配置你自行运行或信任的签名服务完整地址。为保护 Cookie，服务只允许 HTTPS，或本机回环地址的 HTTP。详见[签名服务接入](抖音弹幕签名服务.md)。

快手使用公开推荐、分类和房间初始状态数据。搜索只会匹配游戏分区名称并展示该分区直播间；未匹配时返回空列表，不会冒充主播搜索。首版优先选择 H.264 播放地址，实时弹幕暂不支持。

## 2. 安装与启动

### Windows（推荐）

1. 使用构建产物：`D:\dev\rLive\src-tauri\target\release\rlive.exe`  
2. 或从源码在 Windows 上执行 `scripts\build-windows.ps1`。  
3. 双击运行即可；**不需要**单独安装 mpv。

### 从源码开发

见仓库根目录 `README.md`：`bun install` → `bun run tauri dev`。

## 3. 界面结构

| 区域 | 说明 |
|------|------|
| 左侧栏 | 首页、关注、分类、历史、设置；「设置」上方的单一太阳 / 月亮按钮可在亮色与暗色模式间轮换 |
| 顶栏 | 站点切换、搜索（主播 / 房间号 / 标题）；切换平台时内容区会用短暂渐入过渡，关注页的站点筛选同样居中显示，并额外提供「全部平台」 |
| 房间页 | 左侧纯图标返回、直播间标题、播放器、右侧主播信息，以及「弹幕 / SC / 关注 / 设置」标签 |

## 4. 观看直播

1. 首次启动默认打开哔哩哔哩；之后可在顶栏选择站点。
2. 从「分类」点击分区会打开独立直播列表页；搜索页可切换「全部 / 主播 / 房间号 / 标题」。
3. 房间顶栏左侧提供纯图标返回，内部打开的房间会回到来源页，直接打开房间链接则回到首页；右侧栏顶部显示主播头像、用户名、所属平台和当前热度。
4. 播放器控制条透明叠放在视频底部。播放期间闲置一段时间会自动隐藏；移动、点击或键盘操作即可再次显示。展开音量、清晰度或线路选项时，控制条会保持显示；焦点位于画面时，可用 `Space` / `K` 播放或暂停、`M` 静音、`F` 全屏。
5. 刷新位于暂停左侧，会重新获取流元数据并重建播放会话；音量按钮展开竖向滑杆。
6. 清晰度与线路是控制条右侧的独立选项框（有多路时），仅显示当前选择项。
7. 右侧栏、飘屏与全屏均使用图标开关；收起右栏后再次打开，聊天和 SC 列表仍会保留。
8. 默认清晰度可在「设置 → 播放」中选最高 / 中间 / 最低。
9. 抖音可匿名查看推荐/分类首屏并进入房间播放；搜索需要先保存完整网页 Cookie。若要接收抖音弹幕，还需配置签名服务地址；连接后会解析普通聊天、表情聊天、礼物、点赞、进场与常见社交提示。快手可浏览推荐、分类和游戏分区并进入房间播放；搜索仅匹配游戏分区名称。

播放技术说明：应用通过本机 HTTP 代理转发直播流，前端用 `mpegts.js` 播放，避免跨域与部分 CDN 限制。

## 5. 弹幕

### 5.1 连接

进入哔哩哔哩、虎牙、斗鱼或已配置签名服务的抖音直播间后，应用会自动连接该站点的弹幕服务。右侧列表显示连接状态与消息；画面上方可显示飘屏弹幕。

- **哔哩哔哩**：请在「设置 → 哔哩哔哩 Cookie」粘贴浏览器 Cookie 并保存，否则可能无法拿到弹幕 token。连接意外中断后会自动轮换服务器、刷新 token 并重连；系统消息会显示重连进度。
- **虎牙 / 斗鱼**：一般无需 Cookie。斗鱼弹幕使用系统 TLS（Windows 为 SChannel），以兼容其 RSA 加密套件。
- **抖音**：填写签名服务完整端点后可连接实时弹幕；应用会把进房时建立的临时会话一并交给该服务。保存完整 Cookie 可用于搜索并提高房间/签名可用性。服务会返回短时 WSS URL；断线重进会重新签名。请只使用自己运行或明确信任的服务。
- **快手**：当前会明确显示“暂不支持实时弹幕”，不会反复尝试失败连接；已支持浏览与播放能力不受影响。

### 5.2 发送 B 站弹幕

这是默认关闭的正式功能，以避免误发。需要同时满足下列条件，播放器功能栏中间才会启用输入框：

1. 在「设置 → 账号」启用「B 站发送弹幕」；
2. 保存包含 `SESSDATA` 与 `bili_jct` 的有效 B 站 Cookie；
3. 当前位于 B 站房间。

只支持单条、普通滚动、白色文本。点击发送或按 Enter 会直接提交；后端还会校验 Cookie、房间号、控制字符、80 字符上限，并按房间施加 3 秒冷却。发送请求不会携带 Cookie 跟随重定向。不会批量、循环、定时、自动回复、自动重试或乐观插入本地消息。输入框会显示权限、提交成功或失败状态；提交后请等待 WebSocket 回显，超时会提示“发送状态未知”，请到直播间核实。

### 5.3 弹幕设置

路径：进入任意直播间后，使用右侧「弹幕 / SC / 关注 / **设置**」中的 **设置** 标签。设置保存在本机，对后续房间同样有效。

| 项 | 说明 |
|----|------|
| 显示区域 | 飘屏可使用的视频高度（10%–100%） |
| 显示行数 | 自动安排轨道，或固定为 1–20 行 |
| 不透明度 | 飘屏文字透明度，拖动实时预览，松手保存 |
| 字号 / 字重 | 影响飘屏与右侧列表基础字号；字重提高亮画面可读性 |
| 速度 | 飘屏滚动速度（逻辑 1–10） |
| 相同内容合并 | 仅飘屏：5 秒内合并所有用户发送的相同普通聊天，并显示次数，例如「加油 ×100」；右侧列表逐条显示 |
| 礼物过滤 | 可隐藏斗鱼等平台的礼物通知，不影响 SC |
| 屏蔽词 | 每行一词，输入即过滤；聊天、SC 与飘屏共用，并会自动保存 |

所有显示参数在房间内即时生效：滑块拖动时立即预览，松开后保存；开关与字重即时保存。

高弹幕量房间会按动画帧合并列表与 SC 更新，并限制等待队列大小；未显示的聊天 / SC Tab 仅保留有界队列，不会持续重绘，切换回来也不重置列表。Canvas 在没有活跃飘屏时停止请求动画帧，收到新消息、调整设置或改变尺寸时自动恢复，以降低 CPU 占用；轨道从顶部依次向下分配。斗鱼的高频进场包与伪装成聊天的“xxx 进入直播间”文本都会在 Rust 层丢弃；所有站点的进场事件也会在前端统一隐藏。

### 5.4 消息类型

| 类型 | 表现 |
|------|------|
| 普通聊天 | 列表 + 飘屏 |
| B 站图片表情 | 与普通聊天一样显示；平台随消息下发图片 URL，应用只加载校验过的 B 站 CDN 资源，并保留文字与表情顺序；飘屏图片加载中或不可用时回退显示原始文字 |
| 进场 | 默认隐藏，避免高频“xxx 进入直播间”干扰 |
| 礼物 | 列表角标「礼物」 |
| 醒目留言 SC | 列表角标「SC」+ 飘屏置顶强调 + **SC 面板** |
| 系统 | 连接状态等，仅列表 |

### 5.5 醒目留言（SC）

房间右侧切换到 **SC / 醒目留言** 标签，仅展示 `super_chat` 类型消息（目前来自哔哩哔哩）。  
SC 使用紧凑、中性的卡片，不使用整卡边框/着色或左侧竖条；不同金额档位的安全校验颜色显示在发送者昵称标签背景上，同时保留金额、币种与醒目时长。屏蔽词同样作用于 SC。无 SC 时显示「等待醒目留言…」。

## 6. 关注与历史

- **关注**：在房间内关注主播，可打标签；右侧「关注」会把直播中的主播排在前面，点击可直接切换房间，保留当前标签，无需先退出。通过这里切换后，房间左上角返回会直接回首页，而不会回到上一间直播间。关注页顶栏可筛选「全部平台」或任一平台；列表上方的状态筛选仅有「全部 / 直播中 / 未开播」。页面与房间内列表右下角的浮动按钮可刷新开播状态。
- **历史**：进入过的房间会记入历史，可从历史快速再进。  

## 7. 设置摘要

| 分区 | 内容 |
|------|------|
| 外观 | 侧栏「设置」上方只有一个太阳 / 月亮按钮；每次点击在亮色与暗色模式间轮换 |
| 默认清晰度 | 进房优先档位 |
| 网络代理 | 可选 HTTP(S) 代理，如 `http://127.0.0.1:7890` |
| 哔哩哔哩 Cookie | 只读 API / 接收弹幕；发送功能另需 `SESSDATA` 与 `bili_jct` |
| B 站发送弹幕 | 默认关闭；只支持用户主动发送的单条普通文本与 3 秒冷却 |
| 抖音 Cookie | 可选：匿名浏览会自动建立临时 `ttwid` 会话；完整登录 Cookie 可用于直播搜索、提高房间解析可用性，并可交给签名服务创建弹幕会话 |
| 抖音签名服务 | 实时弹幕使用；必须是 HTTPS，或本机回环 HTTP 的完整端点 |
| 弹幕设置（房间内） | 见上文；不再放在全局设置页 |
| 配置导入导出 | 关注、标签、历史和可移植设置；**不含 Cookie、抖音签名服务地址或本机 B 站发送授权** |

Cookie、抖音签名服务地址和本机 B 站发送授权都只保存在本机 SQLite。导入配置不会覆盖后两项；请在目标设备重新配置，勿提交 Cookie 到 Git 或分享。

## 8. 常见问题

**Q: 斗鱼弹幕提示 HandshakeFailure？**  
A: 请使用包含 `native-tls` 修复后的版本；旧版 rustls 无法与斗鱼弹幕服握手。

**Q: 哔哩哔哩无弹幕？**  
A: 检查 Cookie 是否有效、是否含 `SESSDATA` 等；匿名时部分房间仍可能受限。

**Q: 虎牙进房闪退？**  
A: 请使用已修复 UTF-8 解析的版本；旧版在中文房间页可能 panic。

**Q: 抖音搜索提示需要登录？**  
A: 在「设置 → 抖音 Cookie」粘贴完整网页端登录 Cookie 后重试。分类、推荐首屏和房间播放不要求手动登录，但网页风控可能仍要求稍后重试。

**Q: 抖音弹幕提示缺少签名服务？**
A: 在「设置 → 账号 → 抖音实时弹幕」填写完整签名端点。rLive 不内置或上传逆向签名算法；请使用自己运行或明确信任的 HTTPS / 本机服务。

**Q: B站发送框为什么不可用？**
A: 它默认关闭。先在设置启用「B 站发送弹幕」，并保存包含 `SESSDATA` 和 `bili_jct` 的 Cookie；功能仅在 B 站房间显示。

**Q: 黑屏无声？**  
A: 尝试换线路/清晰度；确认代理设置未阻断 CDN；退出再进同一房间时应用会刷新播放地址。

## 9. 合规提示

以公开列表、播放信息与接收弹幕为主。B 站正式支持用户主动发起的单条普通文本发送；不提供送礼、支付、批量/定时/自动发送、录制或官方登录写流程。请遵守平台条款与当地法律。
