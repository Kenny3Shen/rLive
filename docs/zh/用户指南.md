# rLive 用户指南

## 1. 简介

rLive 是桌面端直播客户端，可在同一应用内浏览、搜索、观看多平台直播，并接收弹幕。

当前站点状态：

| 站点 | 列表 / 搜索 | 播放 | 弹幕 |
|------|-------------|------|------|
| 哔哩哔哩 | ✓ | ✓ | ✓（单条发送需启用本机统一发送开关及有效 Cookie） |
| 虎牙 | ✓ | ✓ | ✓（单条发送需启用本机统一发送开关及有效 Cookie） |
| 斗鱼 | ✓ | ✓ | ✓（个人直播间已成功发送；单条发送仍需本机统一发送开关、完整 Cookie，并按 `chatres` 与真实回显处理） |
| 抖音 | 匿名首屏推荐 / 分类；搜索需登录 Cookie | ✓ | ✓（本地签名直连） |
| 快手 | 推荐 / 分类 / 游戏分区搜索 | ✓ | 暂不支持 |
| Twitch | 首屏直播列表 / 分类 / 搜索 | HLS | ✓（匿名 IRC） |

抖音公开网页的服务端渲染列表当前仅稳定提供首屏。应用不会用 SSR 偏移参数或保存的 Cookie 伪造“加载更多”，以避免重复房间和绕过网页访问验证。保存完整登录 Cookie 后可使用抖音直播搜索，但二维码登录、搜索等网页接口仍可能要求浏览器访问验证。

抖音实时弹幕使用公开 WSS 帧协议，连接地址由短时 MSSDK 签名保护。rLive 在本机计算签名并直连官方 WSS，无需配置外部签名服务。匿名 `ttwid` 会话或完整登录 Cookie 可提高连接可用性。接入边界详见[抖音平台 API 文档](抖音平台API文档.md)。

快手使用公开推荐、分类和房间初始状态数据。搜索只会匹配游戏分区名称并展示该分区直播间；未匹配时返回空列表，不会冒充主播搜索。首版优先选择 H.264 播放地址，实时弹幕暂不支持。

Twitch 支持直播列表、分类、搜索、房间、HLS 播放与匿名 IRC 弹幕。其公开浏览接口仅可靠提供首屏结果，因此应用不提供翻页，以避免重复结果或绕过接口完整性校验。

## 2. 安装与启动

### Windows（推荐）

1. 使用构建产物：`D:\dev\rLive\backend\target\release\rlive.exe`  
2. 或从源码在 Windows 上执行 `scripts\build-windows.ps1`。  
3. 双击运行即可；**不需要**单独安装 mpv。

### 从源码开发

见仓库根目录 `README.md`：`bun install` → `bun run tauri dev`。

## 3. 界面结构

| 区域 | 说明 |
|------|------|
| 左侧栏 | 首页、关注、分类、历史、IPTV、设置；「设置」上方的单一太阳 / 月亮按钮可在亮色与暗色模式间轮换 |
| 顶栏 | 首页显示站点切换与搜索（主播 / 房间号 / 标题）；其他页面不显示搜索按钮。切换平台时内容区会用短暂渐入过渡，关注页的站点筛选同样居中显示，并额外提供「全部平台」 |
| 房间页 | 左侧纯图标返回、直播间标题、播放器、右侧主播信息，以及「弹幕 / SC / 关注 / 设置」标签 |

## 4. 观看直播

1. 首次启动默认打开哔哩哔哩；之后可在顶栏选择站点。
2. 从「分类」点击分区会打开独立直播列表页；搜索页可切换「全部 / 主播 / 房间号 / 标题」。
3. 房间顶栏左侧提供纯图标返回，内部打开的房间会回到来源页，直接打开房间链接则回到首页；右侧栏顶部显示主播头像、用户名、所属平台和当前热度。
4. 播放器控制条透明叠放在视频底部。播放期间闲置一段时间会自动隐藏；移动、点击或键盘操作即可再次显示。展开音量、清晰度或线路选项时，控制条会保持显示；焦点位于画面时，可用 `Space` / `K` 播放或暂停、`M` 静音、`F` 全屏。
5. 刷新位于暂停左侧，会重新获取流元数据并重建播放会话；音量按钮展开竖向滑杆。
6. 清晰度与线路是控制条右侧的独立选项框（有多路时），仅显示当前选择项。
7. 右侧栏、飘屏与全屏均使用图标开关；收起右栏后再次打开，聊天和 SC 列表仍会保留。点击一条普通弹幕可选择带图标的「复制」或「+1」操作：复制会写入剪贴板；在发送条件已就绪的 B 站、斗鱼或虎牙房间，「+1」会提交完全相同的一条文本，不会附加“+1”。本机提交不等于送达，列表和飘屏只以平台真实回显为准。
8. 默认清晰度可在「设置 → 播放」中选最高 / 中间 / 最低。
9. 抖音可匿名查看推荐/分类首屏并进入房间播放；搜索需要先在「设置 → 账号」通过扫码登录或手动输入保存完整网页 Cookie。推荐和分类不会显示“加载更多”：应用不伪造 SSR 翻页，也不绕过抖音网页访问验证。房间会优先由 SSR 取得内部房间号，再通过公开 reflow 数据解析播放信息。实时弹幕会在本机签名后直连，并解析普通聊天、表情聊天、礼物、点赞、进场与常见社交提示。快手可浏览推荐、分类和游戏分区并进入房间播放；搜索仅匹配游戏分区名称。Twitch 支持直播列表、分类、搜索、房间、HLS 播放与匿名 IRC 弹幕；受公开接口限制，浏览仅可靠支持首屏，不提供翻页。
10. 侧栏「IPTV」先打开频道发现首页，不会在进入时默认打开或播放第一个流。可加载 IPTV-org 官方日更的中文、中国大陆、东亚或综合公开频道分表；如需自定义源，请在「设置 → 网络」保存你有权使用的 HTTP(S) M3U 地址，随后首页会显示「自定义源」。频道名/分类支持多关键词搜索、热门分类快捷筛选和按需展开列表。点击频道后才进入独立的沉浸式 `/iptv/play` 播放页，并使用 HLS、MPEG-TS 或 FLV 路径；返回会回到保留筛选条件的频道列表。自定义地址只保存在当前设备，不写入路由、历史或配置导入导出；节目可用性、地区限制和授权以频道来源为准。

播放技术说明：应用通过本机 HTTP 代理转发直播流，前端用 `mpegts.js` 播放，避免跨域与部分 CDN 限制。

## 5. 弹幕

### 5.1 连接

进入哔哩哔哩、虎牙、斗鱼、抖音或 Twitch 直播间后，应用会自动连接该站点的弹幕服务。右侧列表显示连接状态与消息；画面上方可显示飘屏弹幕。

- **哔哩哔哩**：在「设置 → 账号 → 哔哩哔哩」选择「扫码登录」或「手动输入」保存 Cookie，否则可能无法拿到弹幕 token。扫码使用手机端确认后只会将 Cookie 保存到本机。连接意外中断后会自动轮换服务器、刷新 token 并重连；系统消息会显示重连进度。
- **虎牙 / 斗鱼**：接收弹幕一般无需 Cookie。单条发送还需在「设置 → 账号」最上方启用「启用发送功能」并保存对应本机 Cookie。斗鱼支持扫码或手动输入保存完整 Cookie；当前网页对齐的发送实现已在个人直播间成功验证。每次运行仍以 `chatres(res=0)` 判断平台接收，并以正常收弹幕连接的真实回显决定展示，详见[斗鱼平台 API 文档](斗鱼平台API文档.md)。斗鱼弹幕使用系统 TLS（Windows 为 SChannel），以兼容其 RSA 加密套件。
- **抖音**：在「设置 → 账号 → 抖音」可扫码登录或手动输入保存 Cookie；完整 Cookie 可用于登录态搜索，并改善弹幕会话可用性，但不绕过网页访问验证或开启列表翻页。若二维码返回验证页，请检查应用代理后重试，或在官方网页完成验证后复制完整 Cookie。实时弹幕在本机完成 MSSDK 签名后直连官方 WSS，断线重进会重新签名。
- **Twitch**：弹幕通过匿名 IRC WebSocket 连接。
- **快手**：当前会明确显示“暂不支持实时弹幕”，不会反复尝试失败连接；已支持浏览与播放能力不受影响。

### 5.2 发送 B站、斗鱼与虎牙弹幕

这是默认关闭的本机授权，以避免误发。在「设置 → 账号」最上方的「弹幕发送」中启用「启用发送功能」后，才会同时允许 B 站、斗鱼和虎牙的手动单条发送与房间右侧自动发送控制；授权开关只保存在当前设备，不会随配置导出或导入，但自动发送的开关、文本与发送间隔仅属于当前房间会话且绝不保存。它不是登录状态：每个平台仍须保存自己的有效 Cookie，并分别通过房间、文本、冷却和平台服务端校验；条件不完整时，该平台房间的发送框与自动发送控制均保持禁用。斗鱼旧协议已替换为当前网页认证与结果确认状态机，并已在个人直播间成功验证；每一条消息仍只在平台确认和真实回显后显示。

播放器功能栏中间的输入框仍是每次只提交一条普通文字弹幕的手动操作。点击发送、按 Enter 或对一条弹幕使用「+1」都会直接提交同一条文本；不提供批量发送、自动回复、礼物/支付或对不确定写入的自动重试。本机提交或平台 `chatres` 都不替代房间真实回显。

在房间右侧「设置」的「自动发送弹幕」仅适用于 B 站、斗鱼和虎牙。共用本机授权、Cookie/可发送状态和文本校验均就绪后，开启时会立即发送首段。文本会将换行和连续空白压缩为一个空格，再按 grapheme 拆分：每段最多 15 个用户可见字符，且不超过当前平台的 UTF-16 上限；片段按顺序发送，末段后从首段继续。发送请求不会重叠，后续发送起始至少相隔发送间隔；该会话参数默认 20 秒，可在 20–3600 秒间调整，修改会重排下一次发送。单个 grapheme 无法容纳在平台上限内时会显示校验错误。编辑文本、切换房间（同时清空该会话文本）、离开页面、关闭应用或任意发送失败都会立即停用本会话自动发送并显示原因；失败片段不会自动重试。

- **哔哩哔哩**：需要包含 `SESSDATA` 与 `bili_jct` 的有效 Cookie。只支持普通滚动、白色文本；后端会校验 Cookie、房间号、控制字符、当前网页端默认的 20 个 UTF-16 码元上限，并按房间施加 3 秒冷却。官方网页会按账号/服务端下发该上限；rLive 暂以调研到的默认值执行。发送请求不会携带 Cookie 跟随重定向。
- **斗鱼**：在「设置 → 账号 → 斗鱼」中可扫码登录或手动保存完整 Cookie。发送会校验数字房间号、非空单行文本与保守的按房间 3 秒冷却；当前实现使用当前网页的登录后加密协商、稳定设备身份、统一代理和 `chatres` / `error` 解析，且已在个人直播间成功验证。完整 Cookie 还需包含账号、设备和弹幕会话字段；缺失时会明确拒绝，而不会伪造设备 ID 或借用普通 JWT。仅在收到 `chatres(res=0)` 并看到真实回显后视为成功，详见[斗鱼平台 API 文档](斗鱼平台API文档.md)。
- **虎牙**：在「设置 → 账号 → 虎牙」中手动保存包含数字账号 ID（`yyuid` 或 `udb_uid`）及不透明登录凭据（`udb_n` 或 `udb_cred`）的 Cookie；当前不提供扫码登录。发送前会校验解析出的房间、非空、单行且不超过 30 个 UTF-16 单元的文本，并施加短暂的本机冷却。

这三项发送能力只使用当前设备保存的 Cookie。Cookie 不会被记录到日志、导出或上传给其他服务。列表与飘屏仅在收到真实回显后显示；斗鱼还将 `chatres` 作为平台接收信号，与本机提交和房间展示分开报告。

### 5.3 平台真实回显

发送 command 在本机成功返回不会生成本地列表项或飘屏。右侧弹幕栏与飘屏只显示通过正常房间连接收到的平台真实回显，并保留平台原有样式；超时或发送失败仍应以平台直播间的实际状态为准。斗鱼将本地提交、`chatres(res=0)` 和真实回显区分为不同阶段，未知状态不会自动重试。

### 5.4 弹幕设置

路径：进入任意直播间后，使用右侧「弹幕 / SC / 关注 / **设置**」中的 **设置** 标签。显示设置保存在本机，对后续房间同样有效；自动发送是例外，只属于当前房间会话。

| 项 | 说明 |
|----|------|
| 显示区域 | 飘屏可使用的视频高度（10%–100%） |
| 显示行数 | 自动安排轨道，或固定为 1–20 行 |
| 不透明度 | 飘屏文字透明度，拖动实时预览，松手保存 |
| 字号 / 字重 | 影响飘屏与右侧列表基础字号；字重提高亮画面可读性 |
| 速度 | 飘屏滚动速度（逻辑 1–10） |
| 相同内容合并 | 仅飘屏：5 秒内合并所有用户发送的相同普通聊天，并显示次数，例如「加油 ×100」；右侧列表逐条显示 |
| 礼物过滤 | 可隐藏斗鱼等平台的礼物通知，不影响 SC |
| 屏蔽词 | 每行一词，输入即过滤；聊天、SC 与飘屏共用，并会自动保存 |
| 自动发送弹幕（B 站 / 斗鱼 / 虎牙） | 默认关闭的当前会话开关、文本与发送间隔；间隔默认 20 秒，可设为 20–3600 秒；满足发送条件后立即发送首个经过校验的片段，修改间隔会重排下一次发送 |

所有显示参数在房间内即时生效：滑块拖动时立即预览，松开后保存；开关与字重即时保存。

高弹幕量房间会按动画帧合并列表与 SC 更新，并限制等待队列大小；未显示的聊天 / SC Tab 仅保留有界队列，不会持续重绘，切换回来也不重置列表。Canvas 在没有活跃飘屏时停止请求动画帧，收到新消息、调整设置或改变尺寸时自动恢复，以降低 CPU 占用；轨道从顶部依次向下分配。斗鱼的高频进场包与伪装成聊天的“xxx 进入直播间”文本都会在 Rust 层丢弃；所有站点的进场事件也会在前端统一隐藏。

### 5.5 消息类型

| 类型 | 表现 |
|------|------|
| 普通聊天 | 列表 + 飘屏 |
| B 站图片表情 | 与普通聊天一样显示；平台随消息下发图片 URL，应用只加载校验过的 B 站 CDN 资源，并保留文字与表情顺序；飘屏图片加载中或不可用时回退显示原始文字 |
| 进场 | 默认隐藏，避免高频“xxx 进入直播间”干扰 |
| 礼物 | 列表角标「礼物」 |
| 醒目留言 SC | 列表角标「SC」+ 飘屏置顶强调 + **SC 面板** |
| 系统 | 连接状态等，仅列表 |

### 5.6 醒目留言（SC）

房间右侧切换到 **SC / 醒目留言** 标签，仅展示 `super_chat` 类型消息（目前来自哔哩哔哩）。  
SC 使用紧凑的付费留言卡片：发送者头像与名称位于浅色身份区，金额与「置顶」时长保持醒目；经安全校验的 B 站金额档位主色与底色构成下方正文带，完整显示消息。头像缺失、被拦截或加载失败时显示名称首字母；应用不请求用户资料接口。屏蔽词同样作用于 SC。B 站房间无 SC 时显示「还没有醒目留言」；其他平台会明确提示暂未接入 SC。

## 6. IPTV

从左侧栏进入「IPTV」后会到达 `/iptv` 频道发现首页：默认提供 IPTV-org 官方日更的中文语言、中国大陆、东亚和综合公开频道分表。自定义 HTTP(S) M3U 地址只能在「设置 → 网络」保存；配置完成后首页会将其显示为「自定义源」，不再提供自由填写地址的入口。该地址只保存在当前设备，不写入路由、历史或配置导入导出。首页只展示来源、分类、搜索与频道列表，进入时不会挂载播放器或默认播放第一个流。内置源不再使用超过应用安全上限的全球总表；支持多关键词按频道名/分组筛选，精确与前缀匹配优先展示，常用分组可一键选择，长列表按需展开。点击频道后才会进入独立、沉浸式的 `/iptv/play` 播放页，通过本机代理加载 HLS、MPEG-TS 或 FLV 流，以处理嵌套 HLS 清单、分片和常见跨域限制；使用返回会回到保留来源、分类与搜索条件的频道列表。

节目内容与可用性由上游 M3U 来源决定；应用仅解析并播放配置的流地址。

## 7. 关注与历史

- **关注**：在房间内关注主播，可打标签；右侧「关注」会把直播中的主播排在前面，点击可直接切换房间，保留当前标签，无需先退出。通过这里切换后，房间左上角返回会直接回首页，而不会回到上一间直播间。关注页顶栏可筛选「全部平台」或任一平台；列表上方的状态筛选仅有「全部 / 直播中 / 未开播」。页面与房间内列表右下角的浮动按钮可刷新开播状态。
- **历史**：进入过的房间会记入历史，可从历史快速再进。

## 8. 设置摘要

| 分区 | 内容 |
|------|------|
| 外观 | 侧栏「设置」上方只有一个太阳 / 月亮按钮；每次点击在亮色与暗色模式间轮换 |
| 默认清晰度 | 进房优先档位 |
| 网络代理 | 可选 HTTP(S) 代理，如 `http://127.0.0.1:7890` |
| 本地诊断日志 | Windows 发布版写入 `%APPDATA%\rlive\logs\rlive.log`，单文件超过 2 MiB 会保留上一份；日志只记录脱敏失败信息，不写入成功过程、Cookie、令牌或弹幕正文 |
| IPTV 自定义 M3U | 仅在「设置 → 网络」保存有权使用的 HTTP(S) 地址；IPTV 首页仅显示已配置的「自定义源」，地址不写入路由、历史或配置包 |
| 哔哩哔哩 Cookie | 可扫码登录或手动输入；用于只读 API / 接收弹幕，发送功能另需 `SESSDATA` 与 `bili_jct` |
| 弹幕发送 | 位于「账号」页最上方；默认关闭的本机统一开关，同时控制 B 站、斗鱼和虎牙的单条普通文本发送；各平台仍须各自满足 Cookie、房间、文本和冷却校验 |
| 斗鱼 Cookie | 可扫码登录或手动输入；发送需完整的账号、设备和弹幕会话字段。当前网页对齐的发送状态机已在个人直播间验证；运行时仍以 `chatres` 和真实回显判定结果，不能仅凭输入框可用确认送达 |
| 虎牙 Cookie | 当前仅支持手动输入；发送普通弹幕需要 `yyuid` 或 `udb_uid`，以及 `udb_n` 或 `udb_cred` |
| 抖音 Cookie | 可扫码登录或手动输入；匿名浏览会自动建立临时 `ttwid` 会话；完整登录 Cookie 可用于直播搜索和弹幕连接，但不绕过网页访问验证或提供列表翻页 |
| 关于 | 提供项目 GitHub 主页跳转 |
| 弹幕设置（房间内） | 见上文；不再放在全局设置页 |
| 配置导入导出 | 关注、标签、历史和可移植设置；**不含 Cookie、自定义 M3U 地址或本机统一弹幕发送授权** |

Cookie、自定义 M3U 地址和本机统一弹幕发送授权都只保存在本机 SQLite。导入配置不会覆盖这些私有项。请勿提交 Cookie 或私有节目源地址到 Git 或分享。

## 9. 常见问题

**Q: 斗鱼弹幕提示 HandshakeFailure？**  
A: 请使用包含 `native-tls` 修复后的版本；旧版 rustls 无法与斗鱼弹幕服握手。

**Q: 哔哩哔哩无弹幕？**  
A: 检查 Cookie 是否有效、是否含 `SESSDATA` 等；匿名时部分房间仍可能受限。

**Q: B 站二维码过期或扫后未登录？**
A: 点击「刷新二维码」后重新扫描，并在手机端确认登录；网络异常时可切换到「手动输入」粘贴浏览器 Cookie。

**Q: 虎牙进房闪退？**  
A: 请使用已修复 UTF-8 解析的版本；旧版在中文房间页可能 panic。

**Q: 抖音搜索提示需要登录？**  
A: 在「设置 → 账号 → 抖音」扫码登录，或粘贴完整网页端登录 Cookie 后重试。分类、推荐首屏和房间播放不要求手动登录；推荐和分类当前不提供加载更多。若扫码返回浏览器访问验证页，请检查应用代理后重试，或在已完成验证的网页端复制完整 Cookie。

**Q: 抖音弹幕无法连接？**
A: 先确认房间仍在直播，并尝试重新进入房间以刷新签名与网页会话。若已登录，可在「设置 → 账号 → 抖音」检查 Cookie 是否有效。网络代理异常、地区限制或平台风控仍可能导致连接失败。

**Q: B站发送框为什么不可用？**
A: 先在「设置 → 账号」最上方启用「启用发送功能」，再保存包含 `SESSDATA` 和 `bili_jct` 的 Cookie；发送框只会在 B 站房间显示。

**Q: 斗鱼发送框为什么不可用，或点击后没有弹幕？**
A: 先检查「启用发送功能」和完整本机登录态；斗鱼发送还需要账号、稳定设备和弹幕会话字段。当前实现会分别报告本地提交、平台拒绝和未确认；只有 `chatres(res=0)` 加正常收弹幕连接的真实回显才算成功。请勿对未知状态重复发送，详见[斗鱼平台 API 文档](斗鱼平台API文档.md)。

**Q: 斗鱼发送失败后如何收集诊断信息？**
A: 查看 `%APPDATA%\rlive\logs\rlive.log` 中脱敏的失败阶段与错误码，并以平台真实回显为准；不要分享 Cookie、令牌、签名或弹幕正文。协议、限制与验证记录见[斗鱼平台 API 文档](斗鱼平台API文档.md)。

**Q: 虎牙发送框为什么不可用？**
A: 先在「设置 → 账号」最上方启用「启用发送功能」，再在「虎牙」中手动保存同时包含 `yyuid` 或 `udb_uid`，以及 `udb_n` 或 `udb_cred` 的有效 Cookie 后重新进入房间；虎牙当前不提供扫码登录。

**Q: 黑屏无声？**  
A: 尝试换线路/清晰度；确认代理设置未阻断 CDN；退出再进同一房间时应用会刷新播放地址。
