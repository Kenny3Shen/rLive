# rLive 用户指南

本篇讲安装、界面、观看直播、弹幕、字幕、关注与历史，以及常见问题。第一次使用 rLive 从这里开始，装好后按「观看直播」一节即可上手。专题内容在单独文档里：

- [录制与回放](录制与回放.md)：桌面端实时录制、录制库回放、ASS 弹幕导出
- [IPTV 与投屏](IPTV与投屏.md)：IPTV 频道浏览播放、DLNA 投屏
- [本地语音字幕](本地语音字幕.md)、[播放器技术文档](播放器技术文档.md)：实现细节与边界
- [开发指南](开发指南.md)：从源码运行与构建

## 1. 安装与启动

从 GitHub Release 下载对应平台的安装包，无需额外安装播放器。

| 平台 | 安装包 | 说明 |
|------|--------|------|
| Windows（推荐） | `rLive_<版本>_windows-x64-setup.exe` | 按当前用户安装，无需管理员权限；`.msi` 为按机器安装 |
| macOS | `rLive_<版本>_macos-arm64.dmg` / `-x64.dmg` | 拖入「应用程序」；未做签名与公证，见下 |
| Linux | `.deb` / `.rpm` / `.AppImage` | 三种产物都含桌面本地字幕所需的 CPU 运行库 |

macOS 首次打开会提示无法验证开发者：在「系统设置 → 隐私与安全性」点击「仍要打开」，或执行 `xattr -cr /Applications/rLive.app` 后再打开。字幕运行库方面，Windows 首次启用本地语音字幕时会下载约 `212 MiB` 运行库及所选模型；macOS 与 Linux 已内置 CPU 运行库，只下载模型。

### 数据保存在哪里

默认写入可执行文件所在的可写安装目录，包含 `rlive.db`（配置、Cookie、关注和历史）、`logs/`、`cache/images/`、`models/` 和 `asr-runtime/`。目录不可写时自动回退到系统应用数据目录：Windows `%APPDATA%\rlive`、macOS `~/Library/Application Support/rlive`、Linux `~/.local/share/rlive`。实际位置可在设置中查看。

> [!WARNING]
> 从 1.x 升级到 2.0 及以后版本前，先用旧版本导出 profile 并备份数据库与录制目录。2.0 起不读取旧数据库、旧 profile、旧 localStorage、旧录制配置或旧录制 bundle，也不提供隐式迁移或旧录制回放。

## 2. 界面结构

| 区域 | 说明 |
|------|------|
| 左侧栏 | 主导航为首页、关注、IPTV；桌面端另有「多画面」和「录制」，底部依次是亮 / 暗模式、历史、设置。移动端不区分横竖屏一律隐藏多画面、录制、历史与亮 / 暗模式快捷切换，可见入口（首页、关注、IPTV、设置）平分底栏宽度，亮暗模式在设置页外观分区切换，历史从「设置 → 观看记录」进入 |
| 顶栏 | 首页显示站点切换与搜索入口；搜索页与分类页同样复用平台页签，搜索筛选支持「全部 / 主播 / 房间号 / 标题」。桌面端这两页的返回按钮在平台页签最左侧，移动端使用系统返回手势 |
| 首页分类条 | 平台页签下方是钉在顶部的分区条：首项「推荐」是推荐信息流，其后是各分区；右侧网格图标按钮打开完整分区目录，桌面跳到独立的分类页（同搜索一样占一条路由，头部有返回按钮），移动端弹出底部抽屉。选中分区后同页替换为该分区的直播列表，分类条保持可见，可连续换区。移动端分区多于一屏时横滑查看；桌面端不显示横向滚动条，装不下时条带两侧出现箭头按钮逐屏翻动，到头的那一侧变灰。键盘用左右方向键和 Home / End 在分区间移动焦点，回车或空格确认 |
| 房间页 | 左侧纯图标返回、直播间标题、播放器、右侧主播信息，以及「弹幕 / 关注 / 设置」标签 |

## 3. 观看直播

首次启动默认打开哔哩哔哩，之后可在顶栏选择站点。分区浏览并入首页：选中的分区写入地址栏 `?cat=` 参数并带上所属平台，因此分享链接能还原到同一平台的同一分区，切换平台则各自记住自己的选择。分类条上的标签直接用分区名（如「网游」「手游」），完整的「全部 X」只出现在分类目录里。移动端横滑始终用于切换平台，换分区走分类条或底部抽屉；在分区里按一次系统返回键回到推荐流。房间顶栏左侧返回：内部打开的房间回到来源页，直接打开房间链接则回到首页；右侧栏顶部显示主播头像、用户名、平台图标、房间号和当前热度。

| 站点 | 列表 / 搜索 | 播放 | 弹幕 |
|------|-------------|------|------|
| [哔哩哔哩](B站平台API文档.md) | ✓；搜索含未开播主播 | ✓ | 收发（发送需开关 + 有效 Cookie） |
| [虎牙](虎牙平台API文档.md) | ✓；搜索含未开播主播 | ✓ | 收发（发送需开关 + 完整 Cookie） |
| [斗鱼](斗鱼平台API文档.md) | ✓；搜索含未开播主播 | ✓ | 收发（发送需开关 + 完整 Cookie） |
| [抖音](抖音平台API文档.md) | 推荐 / 分类可分页；搜索需登录 Cookie，只有在播房间 | ✓ | 只接收，不支持发送 |
| [Twitch](Twitch平台API文档.md) | 直播列表 / 两级分类 / 搜索分页；搜索含未开播频道 | HLS | 只接收（匿名 IRC） |

抖音推荐来自网页端首页 feed，匿名可用，每次刷新返回一批轮换房间；分类通过本地签名分页，首屏失败时回退 SSR。搜索需先在「设置 → 账号 → 抖音」保存完整登录 Cookie。Twitch 分类是「游戏类型 → 分区」两级（类型名沿用平台自己的英文标签，如 FPS、Just Chatting）；「加载更多」按主播语言分片翻页，排序因此变为分片内按观众数降序的分段拼接，冷门分区某一页可能为空，继续加载即可。点分类条上的类型名会聚合该类型下的分区，翻页深度约十页。播放中遇到插播广告播放列表会自动尝试备用档位，优先保留完整清晰度。

桌面端把鼠标停在直播卡片上约 0.6 秒，封面上会淡入静音低画质预览；移开鼠标、进入房间或关闭「设置 → 播放 → 悬停卡片预览」即结束。触摸设备和系统开启「减少动态效果」时不启用。移动端按住卡片约半秒弹出操作抽屉：复制链接、复制房间号、关注主播、浏览器打开；关注页的直播与 IPTV 卡片长按弹出同款抽屉，用于移至分组和取消关注。点按卡片本身即进入房间，Android 返回键会先收起抽屉。

### 搜索

顶栏搜索按关键词查平台的主播与直播间，筛选支持「全部 / 主播 / 房间号 / 标题」。哔哩哔哩、虎牙、斗鱼、Twitch 的结果同时包含**在播和未开播**的主播：在播房间始终排在前面，未开播的卡片封面上标「未开播」角标、不显示热度，也不触发桌面端悬停预览。未开播的卡片没有直播标题，主标题位置显示主播名。

排序作用于已加载的全部结果，因此「加载更多」取回的在播房间会插到前面已有的未开播结果之前。点开未开播的房间只能看到房间信息，取不到播放地址。

抖音搜索只返回正在直播的房间，没有未开播主播；直接输入完整房间号查询时，无论平台都会显示该房间的真实开播状态。

### 播放器操作

控制条透明叠放在视频底部，闲置一段时间自动隐藏，移动、点击或按键即可再次显示；展开音量、清晰度或线路时保持显示。焦点在画面时可用 `Space` / `K` 播放或暂停、`M` 静音、`F` 全屏、`↑` / `↓` 每次调节 5% 音量（按住可连续调节；静音时按 `↑` 会从 0 开始，一次按键即出声）。

- 刷新位于暂停左侧，重新获取流元数据并重建播放会话。
- 音量只有一个入口，点击展开竖向滑杆，静音按钮在滑杆底部。
- 桌面端「网页全屏」把画面铺满应用窗口：隐藏房间上下两栏与右侧栏，只保留应用标题栏（窗口的最小化 / 关闭入口）。它不进入系统全屏，因此其他窗口仍可切换；按 `Esc`、点顶部 HUD 左侧的返回箭头或再次点击退出。已在系统全屏时不显示该按钮。退出后右侧栏的弹幕队列与滚动位置保持原样。
- 「仅播声音」保持音频、隐藏视频与弹幕字幕画面并释放屏幕常亮，再次点击恢复。音视频复用同一地址，因此不保证减少流量。
- 清晰度和线路在控制条右侧的播放设置中，线路只显示平台名称或「线路 N」。手动选择后按平台和直播间记在本机（最多最近 100 个房间），下次优先匹配相同来源，缺失时回退线路序号。卡顿只用于本地遥测，不会自动切换线路。
- 默认清晰度与「软切换」在「设置 → 播放」中调整。软切换默认开启，同协议换源保留播放器，失败或跨协议时自动完整重建。

全屏会遮住应用顶栏，因此画面顶部出现一层 HUD：最左侧是返回箭头，点击退出全屏回到窗口化布局（系统全屏与网页全屏叠加时一次只退一层，与 `Esc` 的分层习惯一致）；其后是直播间标题、主播头像与名称、房间号和热度，右上角是「更多房间操作」（复制房间链接与播放直链、关注、加入多画面）。关注与多画面需要应用界面，选择后会先退出全屏。

移动端全屏时画面左侧中部有锁定按钮：锁定后单击、双击与左右两侧的滑动手势全部失效，控制条与顶部 HUD 一并收起，Android 返回键也不再退出全屏，适合握持时防误触。锁定按钮本身也会在短暂无操作后休眠淡出，不会长期遮挡画面；此时轻触画面空白处（或按 Android 返回键）只会把锁定按钮唤回来，不会展开控制条，再点按钮即可解锁。退出全屏或切换房间会自动解锁。

移动端画面支持纵向连续手势：左半边调亮度，右半边调音量，拖动时中央 HUD 显示图标与百分比。Android 亮度写入当前窗口，离开房间、切换房间或进入后台时恢复；音量写入系统媒体音量，与硬件音量键共享档位，离开播放页后不会自动恢复。iOS / 移动浏览器的亮度使用只影响画面的遮罩回退，音量只修改当前 `<video>`。

### 桌面多画面

多画面仅支持桌面端，最多同时打开 6 个直播间；移动端不显示入口。可从左侧栏进入，也可在直播卡片右键菜单选「加入多画面」，或在房间顶栏选「加入并打开多画面」。添加弹窗支持选择关注、历史，或输入平台和房间号。

- 布局可选 2 画面（左右等分）、4 画面（「主画面靠左」或「四画面均分」2×2）、6 画面（主画面占左下 2×2）。已有直播间超过目标布局容量时需先移除多余房间。
- 拖动画面左上角把手可移入空槽或与另一画面交换；双击副画面或点「设为主画面」直接与主画面交换。
- 每路有独立播放/暂停、刷新、移除、静音和音量。首个直播间默认音量 80%，之后加入的副路默认静音且音量 0%；切换主副会解除新主的静音（音量为 0% 时恢复 80%）并静音全部副画面。
- 画面弹幕（含 SC）、本地字幕和弹幕发送只挂在主画面，其中画面弹幕默认关闭，可在主画面控制栏开启。主画面控制栏的「全屏」只放大主画面，按 `Esc` 或顶部 HUD 左侧的返回箭头退出。

顶栏右侧的「时钟同步」让各路播放同一时刻的内容，有三种方式：关闭（默认，各路各自贴近直播边缘）、手动（每路按 -5 s 到 +20 s 偏移滑杆延后，另有「按最慢画面对齐」一键填充）、自动（用各路自身时钟持续对齐，HLS 显示「精确时钟」，FLV 只能估算并显示「估算时钟」，滑杆用于微调）。每路顶部显示「延后 x.xs」，悬停可看时钟类型与偏差。同步只对齐到秒级，跨平台仍可能存在固定偏差，用偏移滑杆修正；开启时每路多保留约 30–40 秒回看缓冲，内存占用相应增加；切换同步方式会重建播放器并短暂黑屏。布局、槽位、房间元数据、各路音量与同步设置保存在当前设备的 localStorage，不进入配置导入导出。

## 4. 弹幕

### 4.1 连接

进入哔哩哔哩、虎牙、斗鱼、抖音或 Twitch 直播间后会自动连接弹幕服务。右侧列表显示连接状态与消息，画面上方可显示飘屏弹幕（图标按钮切换：文本气泡表示开启，关闭气泡表示关闭）。

- **哔哩哔哩**：在「设置 → 账号 → 哔哩哔哩」扫码登录或手动输入保存 Cookie，否则可能拿不到弹幕 token。连接中断会自动轮换服务器、刷新 token 并重连，系统消息显示进度。
- **虎牙 / 斗鱼**：接收一般无需 Cookie，发送另需配置（见 4.2）。两者都支持扫码或手动输入。
- **抖音**：完整 Cookie 可用于登录态搜索并改善弹幕会话可用性，但不绕过网页访问验证。二维码返回验证页时，检查应用代理后重试，或在官方网页完成验证后复制完整 Cookie。
- **Twitch**：匿名 IRC WebSocket，只接收。

### 4.2 发送弹幕（B 站 / 斗鱼 / 虎牙）

发送默认关闭以避免误发。在「设置 → 账号」最上方的「弹幕发送」启用「启用发送功能」后，才允许这三个平台的手动单条发送与自动发送控制。该授权只保存在当前设备，不随配置导出导入。它不是登录状态：每个平台仍须保存自己的有效 Cookie，并通过房间、文本、冷却和平台服务端校验；条件不完整时发送框保持禁用。

| 平台 | 发送前提 |
|------|----------|
| 哔哩哔哩 | Cookie 含 `SESSDATA` 与 `bili_jct`；只支持普通滚动白色文本，上限 20 个 UTF-16 码元，按房间 3 秒冷却 |
| 斗鱼 | 完整 Cookie 需含账号、设备和弹幕会话字段，缺失会明确拒绝；数字房间号、非空单行文本、按房间 3 秒冷却 |
| 虎牙 | Cookie 需含数字账号 ID（`yyuid` 或 `udb_uid`）及登录凭据（`udb_n` / `udb_cred` / 扫码产生的 `udb_biztoken`）；文本非空、单行、不超过 30 个 UTF-16 单元 |

> **本机提交不等于送达。** 列表与飘屏只显示通过正常房间连接收到的平台真实回显，并保留平台原有样式。斗鱼把本地提交、`chatres(res=0)` 和真实回显区分为不同阶段，未知状态不会自动重试。超时或失败以平台直播间的实际状态为准。

播放器功能栏中间的输入框每次只提交一条普通文字弹幕，不提供批量发送、自动回复、礼物/支付或自动重试。房间标题栏右侧（移动端「更多房间操作」、全屏右上角「更多操作」）可开启「自动发送弹幕」：文本会把换行与连续空白压缩为一个空格，再按 grapheme 拆分，每段最多 20 个用户可见字符且不超过平台 UTF-16 上限，片段顺序循环发送；发送间隔默认 20 秒，可在 10–3600 秒间调整，修改会重排下一次发送。编辑文本、切换房间、离开页面、关闭应用或任意发送失败都会立即停用本会话自动发送并显示原因。这三项能力只使用当前设备保存的 Cookie，Cookie 不会写入日志、导出或上传给其他服务。

### 4.3 弹幕操作

点击列表中一条普通弹幕可选择「复制」「收藏」「+1」或「屏蔽」。「+1」在发送条件已就绪的房间提交完全相同的文本，不附加「+1」；「屏蔽」按昵称立即隐藏该用户后续与已显示的全部消息。

画面上正在飘动的弹幕也可操作，提供「复制」「收藏」「+1」（屏蔽只在列表提供）。点击一条弹幕即固定它并显示操作菜单，其余弹幕照常飘动；再次点击这条弹幕、点击画面其他位置，或固定超过 20 秒后自动恢复飘动。拖动音量或亮度时不会误固定，全屏时菜单自动放大。

### 4.4 弹幕设置

路径：进入直播间后使用右侧「弹幕 / 关注 / **设置**」中的设置标签，或「设置 → 播放与弹幕」。显示设置保存在本机、对后续房间同样有效；自动发送与定时关闭只属于当前房间会话。滑块拖动时实时预览、松手保存，开关即时保存。

| 项 | 说明 |
|----|------|
| 显示区域 | 普通滚动飘屏可用的视频高度（10%–100%，默认 25%），从画面顶部开始；不影响固定在播放器顶部的 SC 与自己发送的弹幕 |
| 不透明度 | 普通飘屏与 SC 共用的文字透明度（默认 80%） |
| 弹幕字号 | 只影响播放器飘屏（桌面默认 20 px，移动端默认 16 px），右侧列表固定 14 px |
| 字体描边 | 飘屏与 SC 共用的黑色文字轮廓，0–1.5 px 按 0.5 px 调整，默认关闭 |
| 滚动速度 | 普通滚动弹幕的匀速移动速度（50–200 px/s，默认 100 px/s） |
| 相同内容合并 | 仅飘屏：窗口内合并相同普通聊天并显示次数（如「加油 ×100」）；默认 10 秒，可调 0–30 秒，0 为关闭。右侧列表仍逐条显示 |
| 礼物信息过滤 | 默认开启；隐藏各平台礼物通知及抖音「点赞 × 数量」等互动通知，不影响 SC |
| 屏蔽词 | 「消息过滤 → 管理」中逐条添加、编辑或删除，立即生效；聊天、SC 与飘屏共用，单条最多 30 字符，忽略大小写去重 |
| 屏蔽用户 | 从弹幕列表选「屏蔽」或在「消息过滤」中管理；按昵称隐藏聊天、礼物与 SC，单条最多 30 字符、区分大小写，最多 500 个 |
| 醒目留言（B 站） | 位于「消息过滤」，默认开启；在播放器顶部固定显示 SC |
| 自动发送弹幕 | 当前会话的开关、文本与发送间隔（10–3600 秒，默认 20 秒），见 4.2 |
| 定时关闭 | 在播放器「更多操作」中设置 1–1,440 分钟倒计时；到点自动退出 rLive，关闭菜单不会中断，取消后立即停止 |

消息分为普通聊天（列表 + 飘屏）、图片表情（B 站表情与 Twitch 表情，与普通聊天一样显示，只加载校验过的平台 CDN 资源并保留文字与表情顺序，图片不可用时回退原始文字）、进场（默认隐藏）、礼物（列表角标「礼物」）、醒目留言 SC（列表角标「SC」+ 播放器顶部固定显示）和系统消息（仅列表）。高弹幕量房间会合并列表更新并限制等待队列。

B 站醒目留言按金额固定分档着色：30 元蓝色、50 元蓝灰色、100 元柠檬黄、500 元泥巴黄、1000 元水红色、2000 元及以上红色，介于两档之间取不高于该金额的最高档；金额缺失或低于 30 元时使用平台下发颜色。SC 不受「显示区域」限制、不参与合并，最多同时显示 3 条并按平台提供的持续时长退出。

## 5. 本地语音字幕

Tauri 桌面端使用 sherpa-onnx streaming Zipformer 在本机生成中英双语直播字幕；Android 和 iOS 暂不支持，也不显示相关设置。

1. 进入「设置 → 播放 → 语音字幕」，开启流式字幕。VAD（静音端点检测）与自动标点默认开启，可独立关闭。
2. 等待模型下载：约 `488 MiB`（关闭自动标点）或约 `550 MiB`（默认），Windows 首次启用另需约 `212 MiB` 运行库。
3. 进入直播间，点击播放器控制栏的字幕图标显示或关闭字幕。

可选项：「本地热词」用于主播名、游戏名等专有名词；「说话人区分」默认关闭，首次开启再下载约 `27 MiB` 声纹模型，final 字幕会带匿名「说话人 N」编号。「更新间隔」可在 `0.2–1.0 秒`按 `0.1 秒`调整（默认 `0.2 秒`），「字幕字号」`12–48 px`（默认 `20 px`）。悬停或键盘聚焦字幕图标可在「字幕设置」浮层切换说话人区分、配置原文和译文语言。字幕翻译默认关闭，开启后只把 final 文字批量发送到 Google 翻译，partial 不发送，并继承「设置 → 网络」的应用代理。Windows x86_64 可在「推理后端」选择「自动 / CUDA / CPU」，自动模式优先 NVIDIA CUDA，不可用时回退 CPU 并显示实际 provider 和原因；Linux 与 macOS 固定使用 CPU。直播音频只在当前设备的 WebView 与 Rust 进程之间传递，不上传，也不保存音频或字幕历史。构建方式、性能参数与已知边界见[本地语音字幕](本地语音字幕.md)。

## 6. 关注与历史

关注页顶栏只有「直播关注 / IPTV 频道」一级页签并显示数量。直播关注在桌面端左侧栏顶部提供平台和直播状态两个选择框，移动端放在分组条上方；平台筛选会写入地址栏参数。

- 分组：桌面用「直播分组」侧栏，移动端用横向分组条，可新建、重命名和删除，删除后其中主播移至「未分组」。首次关注主播时可选「未分组」、已有分组或当场新建。
- 归组：拖动整张卡片进入目标分组，或用右键菜单「移至分组」；移动端长按卡片弹出抽屉。
- 桌面端右键正在直播的关注卡片可直接「开启录制」或勾选「自动录制」，见[录制与回放](录制与回放.md)。
- 房间右侧的「关注」标签把直播中的主播排在前面，并在平台名称后用时钟图标显示已开播时长，点击卡片可直接切换房间。移动端下拉刷新开播状态，桌面端用右下角刷新按钮。

历史页的入口在「设置 → 观看记录」，桌面端左侧栏底部另有历史快捷图标；移动端底栏不再占用一个目的地，进入后顶栏左侧有返回按钮，按一次系统返回键回到设置。历史页把所有已启用平台的记录合并为按日期排列的时间线，顶部可切换「观看历史」与「弹幕历史」，支持按平台、关键词以及今天、昨天、近 7 天、近 30 天或指定日期组合筛选，筛选状态保留在页面地址中。右上角清空按钮只清空当前显示的整条时间线，不受平台筛选影响，执行前要求确认。观看历史最多保留最近 2,000 个不同直播间，超限后淘汰最早记录。卡片点按即回到房间、右侧按钮删除记录，不提供右键或长按菜单；封面取进入房间时保存的直播间封面，平台未提供时回退平台图标。B 站、斗鱼和虎牙成功发送的弹幕会记录当时的直播间标题、主播名称和房间号，这些字段可参与搜索，也可从记录重新进房。本地录制独立存放在侧栏「录制」中，不混入观看历史。

## 7. 录制、IPTV 与投屏

桌面端可在直播间或 IPTV 播放页实时录制，并在侧栏「录制」中回放、导出 ASS 弹幕字幕，见[录制与回放](录制与回放.md)。侧栏「IPTV」是频道发现页，点击频道才进入独立播放页；DLNA 投屏在房间工具入口中，见[IPTV 与投屏](IPTV与投屏.md)。

## 8. 设置摘要

| 分区 | 内容 |
|------|------|
| 外观 | 桌面侧栏「设置」上方有太阳 / 月亮按钮（仅桌面端）；「设置 → 外观配置 → 亮暗模式」提供跟随系统（默认）、浅色、深色三档，跟随系统时实时切换 |
| 播放 | 默认清晰度（进房优先档位）、软切换（默认开启）、线路记忆（最多最近 100 个房间）、悬停卡片预览（仅桌面端，默认开启） |
| 多画面 / 本地录制 | 均仅桌面端；多画面状态保存在设备 localStorage，录制设置见[录制与回放](录制与回放.md) |
| 应用数据位置 | 新安装优先使用可写安装目录，不可写时回退系统应用数据目录，由程序自动选择，不提供运行中迁移 |
| 本地语音字幕 | 仅桌面端；模型下载量、VAD / 标点 / 说话人开关、热词、更新间隔与字号见第 5 节 |
| 网络 | 可选 HTTP(S) 代理，如 `http://127.0.0.1:7890`；IPTV 自定义 M3U 地址也在此保存，且不写入路由、历史或配置包 |
| 账号 Cookie | B 站、斗鱼、虎牙、抖音均可扫码登录或手动输入；「弹幕发送」总开关位于该页最上方 |
| 本地诊断日志 | 写入应用数据目录的 `logs/rlive.log`，单文件超过 2 MiB 保留上一份；只记录脱敏失败信息，不写成功过程、Cookie、令牌或弹幕正文。时间戳按系统本地时区记录并带上 UTC 偏移，如 `2026-08-31T00:11:31.667820+08:00`。在「设置 → 关于 rLive → 运行日志」可查看、复制、清空，桌面端还可打开日志目录 |
| 本地图片缓存 | 头像、分类图标、缩略图和弹幕表情跨重启复用，直播封面不入缓存以保证画面最新。在「设置 → 数据管理 → 本地缓存」查看目录、文件数与占用，可打开目录或清除，清除不影响关注、历史或其他配置 |
| 局域网同步 | 同一局域网内两台设备通过一次性地址和 6 位配对码直接传输并合并可移植配置，见下文 |
| 配置导入导出 | 含主播关注、标签、内置公开源 IPTV 关注、IPTV 自定义分组、历史和可移植设置；**不含 Cookie、自定义 M3U 地址及其频道关注、多画面槽位/音量、弹幕发送授权、ASR 相关开关与热词** |
| 观看记录 | 概览「账号与数据」分组中的入口，点击进入历史页（观看历史 / 弹幕历史），见第 6 节 |
| 关于 | 当前版本、GitHub 主页、免责声明与「运行日志」入口；启动时自动检查 GitHub Release，可在「当前版本」手动检查 |

局域网同步：在「设置 → 数据管理 → 局域网同步」中，发送设备先创建同步会话，接收设备再输入发送端显示的地址和 6 位配对码。会话有效期 5 分钟，成功下载一次后立即关闭；连续 5 次输错配对码会锁定会话，需重新创建。rLive 只在发送设备当前的私有 IPv4 网卡上临时监听，接收端只连接私网或回环 IP，不使用系统代理，也不跟随重定向，请仅在可信局域网中使用。同步范围与配置导入导出一致，且是合并而非镜像，不会删除接收设备独有的关注和历史。无法连接时确认会话仍在倒计时内、地址与配对码无误，并允许系统防火墙中的 rLive 入站连接；访客 Wi-Fi、AP 隔离或客户端隔离会阻止设备互访，需切换到普通局域网重试。

设备私有项不参与同步：Cookie、自定义 M3U 地址及其频道关注、多画面槽位与音量、弹幕发送授权、ASR 相关开关、热词、更新间隔和字幕翻译设置只保存在本机 SQLite，导入配置不会覆盖。请勿把 Cookie、私有节目源地址或热词配置提交到 Git 或分享。

## 9. 常见问题

**Q: 黑屏无声？** A: 尝试换线路或清晰度，确认代理设置未阻断 CDN；退出再进同一房间时应用会刷新播放地址。

**Q: 哔哩哔哩无弹幕？** A: 检查 Cookie 是否有效、是否含 `SESSDATA` 等；匿名时部分房间仍可能受限。

**Q: B 站二维码过期或扫后未登录？** A: 点击「刷新二维码」后重新扫描并在手机端确认；网络异常时可切换到「手动输入」粘贴浏览器 Cookie。

**Q: 发送框为什么不可用？** A: 先在「设置 → 账号」最上方启用「启用发送功能」，再确认该平台 Cookie 满足 4.2 表格中的要求后重新进入房间。发送框只在 B 站、斗鱼、虎牙房间显示。

**Q: 斗鱼发送失败后如何收集诊断信息？** A: 查看应用数据目录 `logs/rlive.log` 中脱敏的失败阶段与错误码，并以平台真实回显为准；不要分享 Cookie、令牌、签名或弹幕正文。协议与限制见[斗鱼平台 API 文档](斗鱼平台API文档.md)。

**Q: 抖音搜索提示需要登录？** A: 在「设置 → 账号 → 抖音」扫码登录，或粘贴完整网页端登录 Cookie 后重试。分类、推荐和房间播放不要求手动登录。若扫码返回访问验证页，检查应用代理后重试，或在已完成验证的网页端复制完整 Cookie。

**Q: 抖音弹幕无法连接？** A: 先确认房间仍在直播，并重新进入房间以刷新签名与网页会话；已登录时检查 Cookie 是否有效。网络代理异常、地区限制或平台风控仍可能导致失败。

**Q: 语音字幕支持 GPU 吗？** A: 只有 Windows x86_64 支持 NVIDIA CUDA，可在设置中选「自动」或「CUDA」，检测不到兼容 GPU、驱动或依赖时回退 CPU 并显示实际 provider。需要 Compute Capability 6.1 及以上、CUDA 11.x 和 x86-64 cuDNN 8.x。macOS、Linux 与移动端不支持 CUDA 字幕，详见[本地语音字幕](本地语音字幕.md)。

**Q: 语音字幕延迟较高或偶尔跳过内容？** A: 「更新间隔」调到 `0.2 秒`刷新最快，`0.3–0.5 秒`可减少 IPC 调用；慢设备只保留最新待处理分块，不会无限排队。配置热词会增加解码开销，性能不足时减少热词数量。字幕字号只影响渲染，不改变推理性能。

**Q: 说话人编号为什么变化或没有显示？** A: 这是每个播放会话内的匿名声纹聚类，不是姓名识别；切房、换媒体源或关闭字幕会从「说话人 1」重新编号。过短语句可能无法提取声纹，音乐、噪声和多人同时说话也会降低准确率。

**Q: 录制、IPTV 或投屏的问题？** A: 见[录制与回放](录制与回放.md)与[IPTV 与投屏](IPTV与投屏.md)的常见问题。
