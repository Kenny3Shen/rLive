# AcFun 接入说明

AcFun 提供直播、视频与文章三个内容区。直播使用现有站点切换、房间、关注与观看历史流程；视频和文章从「视频」入口选择 AcFun 后进入，保留独立的稿件标识和数据模型。

## 使用入口

- 直播：在「直播」顶部选择 AcFun，浏览直播列表、分类或搜索，然后打开房间。直播画质、线路和实时弹幕沿用现有控制栏及消息列表。
- 视频：在「视频」首页 `/video` 顶部 Shell 选择 AcFun，再在下方内容导航行选择「视频」，浏览全站热门日榜、频道与搜索结果，打开稿件播放；多 P 视频可在播放页选集，右侧栏「评论」页签可查看主评论、楼中楼和回复，「弹幕」页签按时间展示当前分 P 的视频弹幕。「最热」先置顶上游返回的热门评论，后续仍按时间列表分页；「最新」使用时间列表。
- 文章：在 `/video` 顶部 Shell 选择 AcFun，再在下方内容导航行切到「文章」，浏览分类或搜索，点击条目进入应用内阅读。宽窗口在正文右侧查看只读评论；窄窗口可通过阅读区右上角的常驻评论按钮或文章信息中的评论计数按钮打开评论抽屉，查看主评论、回复预览和楼中楼。

上述 Bilibili / AcFun 平台切换与内容导航行用于视频首页；直播页、侧栏、视频播放页和文章阅读页保持各自原有布局。AcFun 直播入口仍只在直播页提供，不进入视频页的 Bilibili / AcFun 平台切换。

文章分类条首项「综合」展示全部文章；选择真实子分区后只浏览该分区，再点「综合」会清除筛选。综合入口不使用空分区 ID，后端仅返回上游导航中真实的文章子分区。

视频和文章列表复用 B 站视频卡片的呈现组件：16:9 封面、封面内统计、固定两行标题与日期／作者行保持一致，列表不显示介绍性文案或重复页标题。文章摘要留在详情页，卡片只展示标题与必要元数据。

视频播放页沿用现有沉浸式布局：宽窗口左侧为无留白的黑色舞台，右侧详情栏在 `lg` 为 320px、`xl` 为 340px；窄窗口按视频实测画幅排列舞台和下方详情。顶部 HUD 和底部控制栏共用现有尺寸、定位与显隐规则。作者、标题、统计和可折叠简介放在详情信息卡中，多 P 稿件另有选集卡。桌面底部操作栏与 HUD 菜单提供复制原链接和在浏览器中打开；加载及错误阶段保留返回入口。

视频详情栏的选集标题、当前位置与总数、行高、悬停和当前项状态，以及评论页签、主评论、回复预览、展开回复、UP 标识、头像、时间、排序、加载和空状态，均与 B 站共用视觉规格。文章评论复用这套主评论与楼中楼展示组件和基础样式。AcFun 多 P 稿件继续使用 `P1` 等平台标识，选集计数显示当前位置和总数；评论回复仍按 AcFun 游标续载，发送评论、点赞、打开作者投稿等能力保持现有边界。

视频弹幕复用 B 站的画面渲染器、虚拟列表和显示设置，支持滚动、顶部和底部弹幕。暂停或缓冲时停在当前媒体时间，倍速与拖动进度跟随视频；切换清晰度保留位置，切换分 P 使用该 P 的独立时间轴。底部控制栏和顶部 HUD 的「更多操作」均提供弹幕开关；侧栏「设置」调整显示区域、外观与屏蔽词，非全屏时也可从 HUD 的「弹幕设置」直接进入。点击画面中的弹幕可复制、收藏到本机，列表条目可跳转到对应时间；AcFun 不提供发送入口。弹幕请求失败会在侧栏提供重试，不阻止视频播放。

观看历史与 B 站共用「历史 → 视频」入口，按稿件去重，保存最后观看的分 P 和秒数。从浏览或搜索打开未看完的稿件时优先续播上次的 P；明确指定另一 P 时尊重选择。进度不足 3 秒不保存，距离片尾不足 5 秒视为看完并从头播放。播放期间每 5 秒最多写入一次，暂停、播完、换 P 和离页补记最后进度。

多 P 稿件在底部控制栏提供「播放下一个」，顶部 HUD 的「更多操作」提供上一 P 和下一 P。播放设置的倍速选项复用 B 站现有倍率和菜单控件，「自动切集」「循环播放」与 B 站共用本地偏好和现有开关行样式；更多操作沿用 B 站的四列磁贴，不另设布局。开启自动切集后播完进入下一 P，最后一 P 保持结束；循环播放优先重复当前 P。手动选集从头播放该 P，不继承上一 P 的进度。

## 数据与播放路径

所有上游 API 请求由 Rust 发起，并遵循应用的代理设置。列表与详情在前端使用 TanStack Query 缓存；播放地址只为当前播放会话取得，离开时释放本机代理。

AcFun 首页只挂载一份内容页面，避免在 B 站四个保活页签面板中重复渲染。两个方向的平台切换都先提交目标路由、顶部平台选中态和下方内容导航行及加载占位，下一帧再提交当前内容；B 站其余面板等内容页签就绪后补齐，减少平台切换时的集中渲染。

视频使用 `dougaId`，分 P 使用 `videoId`，文章使用 `articleId`，全部通过 IPC 按字符串传递。它们不映射为 Bilibili 的 BV/CID，也不复用 B 站账号、评论或下载接口。

| 能力           | 公开数据来源                                        | 处理方式                                                                  |
| -------------- | --------------------------------------------------- | ------------------------------------------------------------------------- |
| 直播列表和分类 | `live.acfun.cn` 的公开列表接口                      | 归一化为 `models::live`，通过 `LiveSite` 使用                             |
| 直播详情和取流 | 公开房间元数据、匿名 visitor 会话与 `startPlay`     | 会话留在后端，FLV 源交给现有 `mpegts.js` 播放路径                         |
| 直播实时弹幕   | `startPlay` 返回的弹幕凭据与 WebSocket 通道         | Rust 完成鉴权、协议解码与批量事件分发，列表和画面沿用通用渲染             |
| 视频热门日榜   | `POST /rest/pc-direct/rank/channel`                 | 全站日榜最多 100 条，按本地页码分批展示                                   |
| 视频频道列表   | `POST /rest/pc-direct/channel/resource/query/match` | 按频道、页码和发布时间获取稿件                                            |
| 视频和文章搜索 | `GET /rest/pc-direct/search/{video\|article}`       | 使用上游 `pCursor` 分页，保留稿件类型                                     |
| 视频详情和播放 | `www.acfun.cn/v/ac{id}` 的 `window.videoInfo`       | 读取分 P 与 `ksPlayJson`，HLS 通过现有 Rust `stream_proxy` 改写清单与分片 |
| 视频弹幕       | `POST /rest/pc-direct/new-danmaku/list`             | 使用分 P 的 `videoId` 作为 `resourceId`，`resourceType=9`；每页请求 200 条，沿 `pcursor` 拉取至 `no_more`，按弹幕 ID 去重与毫秒位置排序 |
| 视频和文章主评论 | `GET /rest/pc-direct/comment/list`                  | `sourceId` 分别使用视频或文章 ID，统一使用 `sourceType=3`；`commentCount` 含主评论与回复，最热模式先置顶热门评论，后续按时间分页 |
| 视频和文章楼中楼 | `GET /rest/pc-direct/comment/sublist`               | 按根评论的页码继续加载，上游每页 10 条，`total` 是该楼回复数；页面前端使用不透明游标传递页码 |
| 文章列表       | `POST /rest/pc-direct/article/feed`                 | 按文章分类与真实游标加载                                                  |
| 文章正文       | 详情页的 `window.articleInfo`                       | 将 `parts/content` 转换为安全的结构化正文块                               |

文章评论通过独立 IPC `acfun_article_get_comments` 和 `acfun_article_get_comment_replies` 接入，复用视频评论的返回模型、主评论与楼中楼组件及共享样式；前端缓存按资源类型和资源 ID 隔离，切换文章、视频资源或评论排序时不会混用列表，并会收起已展开的楼中楼。

视频弹幕通过 `acfun_video_get_danmaku` 接入，Rust 先核对分 P 是否属于当前稿件，再完整获取时间轴；缓存按稿件和分 P 隔离。末页仍可包含弹幕，不能先丢弃数据再判断 `no_more`。游标重复、响应字段无效或超过 500 页均明确返回错误，不把不完整的时间轴当作成功。高级弹幕的原始文本沿普通滚动方式展示，不执行代码或复现平台的特殊动画。

视频历史复用 `video_history_*` IPC 和表，`kind=acfun`、`oid=dougaId`，最后观看的 `videoId` 放在独立字符串列 `part_id`；B 站的 `bvid/ep_id/aid` 在 AcFun 记录中为空，`cid` 为 0。数据库 v9 为旧视频历史补上空 `part_id`，旧配置导入时该字段默认空值，已有 B 站历史仍可正常读取。

文章以段落、标题、图片、链接、引用、列表和代码块展示。页面脚本、事件属性、嵌入播放器及不安全 URL 不进入前端，不把平台 HTML 直接注入 DOM。正文复杂排版可能与官方网页有差异。

阅读页不显示「AcFun 文章」顶部 Shell 横栏，返回按钮固定在阅读区左上角，不随正文滚动，加载和错误时也可返回。宽窗口将正文 `max-w-3xl` 阅读区与右侧评论栏分开：评论栏在 `lg` 为 320px、`xl` 为 340px，正文和评论各自滚动。窄窗口不常驻评论栏，阅读区右上角提供与返回按钮同外观的 44px 常驻评论按钮，滚动到长文中间或底部仍可打开；文章信息中的评论计数按钮也保留，两个入口共用同一覆盖式评论抽屉。手机使用底部抽屉，较窄桌面使用右侧抽屉，关闭后不再发起评论或回复请求。正文保持约 45 个汉字的行宽，窄窗口使用 16px、宽窗口使用 17px 字号，并按标题、段落和图片分别安排留白。正文图片按自然比例居中，不限制长图高度；代码块仅在自身内部横向滚动。重复标题或正文首段的摘要、同一资源的重复封面会省略，其余内容保留。

段落支持安全的行内文本与链接，并保留粗体、斜体及 `<br>` 换行。行内元素不会拆成额外段落；原有纯文本段落仍可显示。标准正文标题保留层级并置于文章主标题之下，不根据短段落猜测标题。

`/rest/pc-direct/search/video` 的 `contentId`（也等于搜索结果中的 `id`）才是打开 `/v/ac{contentId}` 和读取评论时使用的 `sourceId`；同一项里的 `videoId` 是内部分 P ID，不能当作稿件标识。搜索入口优先使用 `contentId` 或 `id`，缺失时才回退其他字段。

封面、头像与文章图片通过现有图片代理处理，允许的 AcFun 图片 CDN 后缀为 `acfun.cn`、`aixifan.com`、`yximgs.com`、`kwimgs.com`，补上平台 Referer 并复用磁盘缓存。媒体地址走流代理，不走图片代理。

## 当前边界

- 支持公开可观看内容，不绕过付费直播门票、付费稿件、登录或地区限制。
- AcFun 账号登录、直播与视频弹幕发送、评论互动尚未接入；直播与视频弹幕支持查看，视频弹幕另可本地复制与收藏。直播消息列表只展示聊天，不展示礼物、点赞和进场事件；评论中的表情目前以 `[表情]` 纯文本占位，不提供富表情渲染。
- B 站视频的下载、字幕、短视频和作者关注仍属于 B 站能力，AcFun 不套用这些接口；观看历史与续播使用本地共享存储，平台及分 P 标识独立保存。
- 文章提供应用内阅读和只读评论，不接入评论发布、点赞、回复发送、收藏、投稿或编辑功能。
- 接口与 CDN 均由上游维护，字段变化、内容删除或临时网络错误会显示可重试的错误；不以空列表掩盖接口失败。
- 直播标题匹配补充来自当前首批最多 60 个在播房间；主播搜索可按上游结果翻页，不保证标题搜索覆盖全部房间。
