# AcFun 第一期接入

AcFun 提供直播、视频与文章三个内容区。直播使用现有站点切换、房间、关注与观看历史流程；视频和文章从「视频」入口选择 AcFun 后进入，保留独立的稿件标识和数据模型。

## 使用入口

- 直播：在「直播」顶部选择 AcFun，浏览直播列表、分类或搜索，然后打开房间。直播画质和线路沿用现有控制栏。
- 视频：在「视频」首页 `/video` 顶部 Shell 选择 AcFun，再在下方内容导航行选择「视频」，浏览全站热门日榜、频道与搜索结果，打开稿件播放；多 P 视频可在播放页选集。
- 文章：在 `/video` 顶部 Shell 选择 AcFun，再在下方内容导航行切到「文章」，浏览分类或搜索，点击条目进入应用内阅读。

上述 Bilibili / AcFun 平台切换与内容导航行用于视频首页；直播页、侧栏、视频播放页和文章阅读页保持各自原有布局。AcFun 直播入口仍只在直播页提供，不进入视频页的 Bilibili / AcFun 平台切换。

文章分类条首项「综合」展示全部文章；选择真实子分区后只浏览该分区，再点「综合」会清除筛选。综合入口不使用空分区 ID，后端仅返回上游导航中真实的文章子分区。

视频和文章列表复用 B 站视频卡片的呈现组件：16:9 封面、封面内统计、固定两行标题与日期／作者行保持一致，列表不显示介绍性文案或重复页标题。文章摘要留在详情页，卡片只展示标题与必要元数据。

视频播放页沿用现有沉浸式布局：宽窗口左侧为无留白的黑色舞台，右侧详情栏在 `lg` 为 320px、`xl` 为 340px；窄窗口按视频实测画幅排列舞台和下方详情。顶部 HUD 和底部控制栏共用现有尺寸、定位与显隐规则。作者、标题、统计和可折叠简介放在详情信息卡中，多 P 稿件另有选集卡。桌面底部操作栏与 HUD 菜单提供复制原链接和在浏览器中打开；加载及错误阶段保留返回入口。

## 数据与播放路径

所有上游 API 请求由 Rust 发起，并遵循应用的代理设置。列表与详情在前端使用 TanStack Query 缓存；播放地址只为当前播放会话取得，离开时释放本机代理。

AcFun 首页只挂载一份内容页面，避免在 B 站四个保活页签面板中重复渲染。两个方向的平台切换都先提交目标路由、顶部平台选中态和下方内容导航行及加载占位，下一帧再提交当前内容；B 站其余面板等内容页签就绪后补齐，减少平台切换时的集中渲染。

视频使用 `dougaId`，分 P 使用 `videoId`，文章使用 `articleId`，全部通过 IPC 按字符串传递。它们不映射为 Bilibili 的 BV/CID，也不复用 B 站账号、评论或下载接口。

| 能力           | 公开数据来源                                        | 处理方式                                                                  |
| -------------- | --------------------------------------------------- | ------------------------------------------------------------------------- |
| 直播列表和分类 | `live.acfun.cn` 的公开列表接口                      | 归一化为 `models::live`，通过 `LiveSite` 使用                             |
| 直播详情和取流 | 公开房间元数据、匿名 visitor 会话与 `startPlay`     | 会话留在后端，FLV 源交给现有 `mpegts.js` 播放路径                         |
| 视频热门日榜   | `POST /rest/pc-direct/rank/channel`                 | 全站日榜最多 100 条，按本地页码分批展示                                   |
| 视频频道列表   | `POST /rest/pc-direct/channel/resource/query/match` | 按频道、页码和发布时间获取稿件                                            |
| 视频和文章搜索 | `GET /rest/pc-direct/search/{video\|article}`       | 使用上游 `pCursor` 分页，保留稿件类型                                     |
| 视频详情和播放 | `www.acfun.cn/v/ac{id}` 的 `window.videoInfo`       | 读取分 P 与 `ksPlayJson`，HLS 通过现有 Rust `stream_proxy` 改写清单与分片 |
| 文章列表       | `POST /rest/pc-direct/article/feed`                 | 按文章分类与真实游标加载                                                  |
| 文章正文       | 详情页的 `window.articleInfo`                       | 将 `parts/content` 转换为安全的结构化正文块                               |

文章以段落、标题、图片、链接、引用、列表和代码块展示。页面脚本、事件属性、嵌入播放器及不安全 URL 不进入前端，不把平台 HTML 直接注入 DOM。正文复杂排版可能与官方网页有差异。

阅读页不显示「AcFun 文章」顶部 Shell 横栏，返回按钮固定在阅读区左上角，不随正文滚动，加载和错误时也可返回。正文保持约 45 个汉字的行宽，窄窗口使用 16px、宽窗口使用 17px 字号，并按标题、段落和图片分别安排留白。正文图片按自然比例居中，不限制长图高度；代码块仅在自身内部横向滚动。重复标题或正文首段的摘要、同一资源的重复封面会省略，其余内容保留。

段落支持安全的行内文本与链接，并保留粗体、斜体及 `<br>` 换行。行内元素不会拆成额外段落；原有纯文本段落仍可显示。标准正文标题保留层级并置于文章主标题之下，不根据短段落猜测标题。

封面、头像与文章图片通过现有图片代理处理，允许的 AcFun 图片 CDN 后缀为 `acfun.cn`、`aixifan.com`、`yximgs.com`、`kwimgs.com`，补上平台 Referer 并复用磁盘缓存。媒体地址走流代理，不走图片代理。

## 第一期边界

- 支持公开可观看内容，不绕过付费直播门票、付费稿件、登录或地区限制。
- AcFun 账号登录、实时直播弹幕和发送、视频弹幕与评论互动尚未接入；上游下发的弹幕和评论统计只展示为统计数字。
- B 站视频的下载、字幕、短视频、作者关注和续播记录仍属于 B 站能力，AcFun 本期不套用这些接口。
- 文章提供应用内阅读，不接入评论、收藏、投稿或编辑功能。
- 接口与 CDN 均由上游维护，字段变化、内容删除或临时网络错误会显示可重试的错误；不以空列表掩盖接口失败。
- 直播标题匹配补充来自当前首批最多 60 个在播房间；主播搜索可按上游结果翻页，不保证标题搜索覆盖全部房间。
