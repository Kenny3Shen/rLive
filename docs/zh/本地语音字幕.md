# 本地语音字幕（CrispASR）

## 功能与模型

rLive 的直播语音字幕完全在本机运行，后端使用 [CrispASR](https://github.com/CrispStrobe/CrispASR) `0.8.25`（固定提交 `6e5bf7f`），模型使用 [`cstr/qwen3-asr-0.6b-GGUF`](https://huggingface.co/cstr/qwen3-asr-0.6b-GGUF) 中的 `qwen3-asr-0.6b-q4_k.gguf`。

- ASR 模型大小：`631,026,336` 字节（仓库标注约 631 MB）。
- 可选 VAD：CrispASR 上游默认的 Silero v6.2.0，`885,098` 字节（约 865 KiB）。
- 模型能力：30 种语言和 22 种中文方言，由 Qwen3-ASR 自动识别。
- 模型许可：Apache-2.0；CrispASR 许可见其上游仓库。
- 支持范围：Tauri 桌面客户端；Android 和纯浏览器开发页不提供本地 ASR。
- 隐私边界：直播 PCM 只发送到同进程 Rust command，不上传到 rLive 服务；字幕和音频不写入数据库。

首次在「设置 → 播放 → 语音字幕」启用时，应用会先确认约 631 MB 下载。文件下载到当前用户的数据目录：Windows 位于 `%APPDATA%\rlive\models\asr`，Linux 通常位于 `~/.local/share/rlive/models/asr`。关闭功能会释放模型内存，但保留已下载文件；再次启用不重复下载。

## 使用

1. 打开「设置 → 播放 → 语音字幕」。
2. 选择 GPU 或 CPU。没有编入 GPU 后端的产物会明确显示 CPU 回退，并禁用 GPU 选项。
3. 按需开启「语音活动检测（VAD）」。该选项默认关闭；首次开启会下载约 865 KiB 的 Silero 模型。
4. 在「字幕字号」中选择 `12–48 px`（默认 `20 px`）。该设置只改变播放器字幕叠加层，不影响弹幕字号；拖动时即时预览，松开后保存。
5. 开启「本地语音字幕」，确认下载并等待状态变为“模型已就绪”。
6. 进入正在播放的直播间，点击播放器控制栏的字幕图标（启用时为字幕框，停用时为带斜杠字幕框）。

切换 GPU / CPU 时，应用会在后台释放原会话并用新设备重新加载模型。切换 VAD 不会重新加载 Qwen3 会话：开启时只准备 Silero 模型，关闭时立即恢复普通转写。模型加载或转写失败时可从设置页重试；关闭总开关会同时停止采集并释放常驻模型内存。

## CPU 与 GPU 构建

CrispASR 的 CPU 后端始终编译。启用 CUDA、Vulkan 或 Metal feature 得到的是“GPU + CPU”二进制，不需要分别发布两个程序；设置中的 GPU / CPU 只决定运行时是否卸载 GPU 层。多个可用的 GPU 后端也可共同编入同一二进制：

```bash
# CPU
bun run tauri -- dev

# NVIDIA CUDA
bun run tauri -- dev --features asr-cuda

# Windows / Linux 跨厂商 Vulkan
bun run tauri -- dev --features asr-vulkan

# macOS Metal
bun run tauri -- dev --features asr-metal

# 同时编入 CUDA、Vulkan 和 CPU
bun run tauri -- dev --features asr-cuda,asr-vulkan
```

GPU 构建需要对应工具链：CUDA Toolkit、Vulkan SDK（含 Vulkan headers / shader compiler），或 Xcode Metal。只在运行时安装显卡驱动、但构建时没有启用 feature，并不会生成 GPU 后端。共同编入多个后端时，构建机必须同时安装对应工具链；CrispASR / ggml 运行时按 `CUDA > Metal > Vulkan > CPU` 选择已编译且可用的后端。目前 rLive 设置只提供 GPU / CPU，不提供具体 GPU 后端或设备编号选择。

Windows 的 CUDA 构建必须让 CMake 和 Visual Studio 的 CUDA MSBuild targets 使用同一个 Toolkit 根目录。`bun run tauri -- dev --features asr-cuda` 会自动从 `CUDA_PATH` 或 `nvcc.exe` 推导路径，并设置 `CUDA_PATH_V12_9` / `CudaToolkitDir`；如果 CUDA 安装在自定义目录，可在同一个终端显式设置：

```powershell
$env:CUDA_PATH = "D:\dev\CUDAToolkit"
$env:CUDA_PATH_V12_9 = $env:CUDA_PATH
$env:CudaToolkitDir = $env:CUDA_PATH
$env:Path = "$env:CUDA_PATH\bin;$env:Path"
bun run tauri -- dev --features asr-cuda
```

如果此前 CUDA 配置失败，包装脚本会识别缺失的 `CMakeCUDACompiler.cmake` 并自动清理 `crispasr-sys` 的失败缓存后重试。

Windows 脚本默认使用 `auto`：优先检测 `nvcc`，其次检测 Vulkan SDK / `glslc`，否则构建 CPU 版本。也可明确指定：

```powershell
.\scripts\build-windows.ps1 -AsrBackend cuda
.\scripts\build-windows.ps1 -AsrBackend vulkan
.\scripts\build-windows.ps1 -AsrBackend cpu
```

## 实时链路与性能策略

```text
video 音轨
  → Web Audio 双声道混合为单声道
  → 自适应 1–8 秒窗口（初始 6 秒，0.25 秒重叠）
  → 16 kHz f32 PCM
  → Tauri command
  → 可选 Silero VAD（无语音时直接返回）
  → 常驻 CrispASR Qwen3 session
  → 播放器字幕叠加层
```

- 模型仅加载一次；每个片段在 Rust 阻塞线程池执行，不占用 Tauri 异步调度线程。单个 CrispASR session 仍保持串行，符合上游文档关于 context 非线程安全的约束。
- VAD 开启时先调用 CrispASR `crispasr_vad_slices`。没有检测到语音的片段不会进入 Qwen3，可减少静音、音乐间隙和等待画面的无效推理，并降低静音幻觉；有语音时再用 `crispasr_session_transcribe_vad` 裁剪、拼接并重映射时间戳。
- VAD 预检与带 VAD 转写会执行两次轻量检测；CrispASR 会缓存 Silero 上下文。相对 Qwen3 推理，这点开销很小，并换取了可靠的纯静音跳过。
- CPU/GPU 模式都通过 Rust `available_parallelism()` 自动读取当前进程可用的逻辑处理器数，不再固定限制为 8/4 线程；单路 session 内由 ggml 进行 intra-op 多线程，避免启动多个模型副本争抢内存。
- 前端只保留一个正在处理的任务和最新待处理片段。设备速度低于实时速度时会跳过过期中间片段，不会形成无限队列或持续增加内存。
- 窗口根据最近几次转写的 RTF（推理耗时 / 音频时长）、排队等待和丢弃情况调整：连续有余量时从 6 秒逐步降至 1 秒以降低首字幕延迟；RTF 接近或超过实时速度、或发生背压时逐步升至 8 秒以摊薄 speech-LLM 的固定开销。使用滞回计数，避免窗口在相邻档位间抖动。
- 实时解码 token 上限设为 256，避免异常长输出占用唯一 session；该限制不影响常规 1–8 秒字幕，但仍应通过目标语种样本检查截断率。
- 采集器使用可复用的单声道 scratch buffer 和滚动 PCM buffer，减少每个音频回调的数组合并和临时分配。
- PCM Base64 编码直接读取 `Float32Array` 底层小端字节，避免逐采样复制。
- 模型下载 URL 固定到 Hugging Face 仓库提交，并在原子替换前校验精确文件长度，不会加载不完整下载。

## 已知边界

- 这是低延迟分段字幕，不是逐字 token 流式解码；Qwen3 session API 当前仍按窗口完成一次推理后更新字幕。窗口会根据设备速度在 1–8 秒间自适应。
- CPU 性能取决于指令集、内存带宽和直播语种。机器无法实时处理时，应用优先保持直播播放与 UI 响应。
- 当前只展示转写文本，不提供翻译、说话人分离、字幕文件导出或历史保存。
- GPU 模式仍需要足够显存；加载失败时可切换 CPU 后重试。
- VAD 适合语音与静音交替的直播；持续音乐、环境声或阈值附近的轻声可能被过滤。需要保留所有声音片段时可在设置中关闭。

### 与 CrispASR streaming/concurrency 的关系

CrispASR 的 streaming 文档将 `step`、滚动窗口和静音终止分开控制；本地 Qwen3 集成目前使用自适应批窗口实现同样的低延迟背压语义。固定提交中的通用 `crispasr_session_stream_open` 并不是 Qwen3 的增量音频编码接口，因此不能仅通过调用它获得真正的 token/encoder streaming。若要把 Qwen3 的 CLI `--live` 能力接到 Rust/Tauri，需要先按[Qwen3-ASR Streaming C API 暴露流程](Qwen3-ASR-Streaming-C-API.md)扩展上游 C ABI。

CrispASR concurrency 文档要求一个 session/context 不要被多个线程同时驱动。rLive 因此选择“一个常驻 session + 自动探测的 intra-op 线程数”，而不是并行创建多个 631 MB 模型副本。只有在未来需要同时识别多个独立音频源且内存足够时，才应评估多 session worker；单路直播不应这样做。
