# 本地语音字幕（CrispASR + Qwen3-ASR）

rLive 用 [CrispASR](https://github.com/CrispStrobe/CrispASR) `v0.8.48` 运行 Qwen3-ASR 0.6B，在本机生成字幕，直播间、IPTV、多画面与 B 站视频（VOD）共用同一条管线。想启用功能看「使用步骤」，关心磁盘与算力开销看「模型与下载量」和「参数」，遇到识别不准或翻译失败看「已知边界」。

- 音频链路在整体架构中的位置：[架构说明](架构说明.md#6-本地语音字幕路径) 第 6 节
- 桌面构建与运行命令：[开发指南](开发指南.md)

仅支持 Tauri 桌面客户端。Android 与 iOS 不提供本地 ASR，也不展示字幕设置或播放器入口；Android Rust target 会排除 ASR 代码。

## 数据边界

- 音频 PCM 只在当前设备的 WebView 与 Rust 进程之间传递，不上传到 rLive 服务。
- 模型、热词、声纹 embedding 与字幕文本都留在本地。VOD 的本地字幕同样在本机识别，不会把音轨交给任何外部字幕服务。
- 字幕翻译默认关闭。用户主动开启后，只有已定稿的文字会经 `google-translate-api-x` 的 `batchexecute` 端点发送到 Google 翻译；实时 partial、PCM、声纹与热词不会发送。
- `asr_provider`、`asr_vad_enabled`、`asr_punctuation_enabled`、`asr_speaker_diarization_enabled`、`asr_hotwords` 与 `asr_translation_*` 都是设备本地设置，不随配置包导入导出，避免另一台设备意外下载模型、覆盖本地领域词或代替用户同意向 Google 发送字幕。

## 模型与下载量

安装包不含任何 ASR 运行库。首次启用时按平台下载 CrispASR 预编译运行库，再下载模型。所有文件都钉在固定版本（GitHub release `v0.8.48`、Hugging Face 固定 commit），下载时核对精确字节数与 SHA-256。

| 用途 | 文件 | 大小 |
| ---- | ---- | ---- |
| 语音识别 | `qwen3-asr-0.6b-q4_k.gguf`（`cstr/qwen3-asr-0.6b-GGUF`） | `631,026,336` 字节（约 `602 MiB`） |
| VAD 分句 | `ggml-silero-v6.2.0.bin`（`ggml-org/whisper-vad`） | `885,098` 字节（约 `0.8 MiB`） |
| 可选说话人声纹 | `titanet-large.gguf`（`cstr/titanet-large-GGUF`） | `44,612,960` 字节（约 `43 MiB`） |

| 平台 | 运行库包 | 下载大小 | 默认总下载量 |
| ---- | -------- | -------- | ------------ |
| Windows x86_64（无可用 NVIDIA GPU） | `libcrispasr-windows-x86_64.tar.gz` | 约 `56 MiB` | 约 `658 MiB` |
| Windows x86_64（有可用 NVIDIA GPU） | `crispasr-windows-x86_64-cuda126.zip`（自带 CUDA 12.6 cudart / cuBLAS） | 约 `680 MiB`，解压后约 `1.5 GiB` | 约 `1.25 GiB` |
| Linux x86_64 | `libcrispasr-linux-x86_64.tar.gz` | 约 `22 MiB` | 约 `624 MiB` |
| Linux aarch64 | `libcrispasr-linux-arm64.tar.gz` | 约 `17 MiB` | 约 `619 MiB` |
| macOS Apple Silicon | `libcrispasr-macos-arm64.tar.gz` | 约 `9 MiB` | 约 `611 MiB` |

- 「默认总下载量」含识别模型与 VAD 模型。开启「说话人区分」再加约 `43 MiB`；关闭 VAD 少约 `0.8 MiB`。
- 自动标点不需要额外模型：Qwen3-ASR 本身输出标点，关闭开关时在 Rust 侧去掉标点。
- Windows 按推理后端与硬件选包：后端为「自动」或「CUDA」且检测到可用 NVIDIA GPU 时下载 CUDA 包，否则下载 CPU 包；选 CPU 不探测 GPU，也不下载 CUDA 包。CUDA 包同样能跑 CPU，装过之后切到 CPU 不再下载 CPU 包。每个进程只能加载一个运行库包：已用 CPU 包加载过字幕时，切到 CUDA 会提示重启应用，重启后再下载 CUDA 包。
- Intel Mac、Windows ARM 与不支持 AVX2 / FMA / F16C 的 x86_64 CPU 没有可用运行库，设置页显示「不支持」并禁用开关。

运行库只解出加载所需的文件（库本身、依赖的 ggml / OpenBLAS / OpenMP / CUDA 库与许可证），版本化的 `.so` / `.dylib` 直接改名为 soname / install name，不保留符号链接。解压先进暂存目录，写入版本标记后整体改名到正式目录；中途失败不会留下半成品。

存放位置：模型在应用数据目录的 `models/asr`，运行库在 `crispasr-runtime/<包名>`（数据目录见[用户指南](用户指南.md)「数据保存在哪里」）。关闭功能会释放常驻会话，但保留已下载文件。运行库就绪后会删除 `crispasr-runtime` 下的其他条目，即换包或升级后的旧包目录与旧版本的半截归档；Windows 上仍被占用的旧 DLL 删不掉时只记日志，下次再清。

断点续传：下载边写边存进 `.part`（运行库为 `crispasr-runtime/<包名>-<归档名>.part`，模型为 `models/asr/<文件名>.<SHA-256 前 8 位>.part`）。连接中断后带 `Range` 从已写入处续传，状态显示「网络中断，正在续传…」；连续 5 次没有新数据才报错。关闭功能、换设置或重试用尽时保留 `.part`，下次启用先校验已有部分再续传。服务端不支持 `Range` 时从头重下；内容与预期不符（分段对不上或 SHA-256 不符）时删除 `.part`，若它来自之前的下载则自动从头再下一次。文件名带版本信息，换了固定版本不会续传旧数据，不再属于任何模型的 `.part` 在下次下载前删除。

从旧版升级：首次需要下载时会删除 sherpa-onnx 时代的资产，即 `models/asr` 下的 Zipformer、CT-Transformer 标点、CAMPPlus 声纹与 `hotwords.txt`，以及版本标记为 `sherpa-onnx*` 的 Windows `asr-runtime` 目录，合计约 `900 MiB`。删除失败只记日志，不阻断启用。

会话按需加载与释放：开启设置只准备**资产**（必要时下载/解压），不加载识别会话；首次在某处开启字幕时才加载运行库与模型。Windows 的 NVIDIA GPU 探测发生在启用时，不在应用启动路径上。运行库每个进程只加载一次；字幕全部关闭、且没有任何播放器在消费字幕满 `2 分钟`后，会话被空闲释放（状态回到 `idle`），模型文件保留在磁盘，下次开启字幕时按需重载。

首次下载状态依次为 `downloading`（运行库与各模型共用一条累计进度）、`extracting`（解压运行库）、`loading`、`ready`；已启用但会话未加载（或已被空闲释放）时为 `idle`。下载、解压与模型加载都不在 WebView 主线程执行；失败后可在设置页重试。

## 使用步骤

1. 打开「设置 → 播放 → 语音字幕」。
2. 开启「语音字幕」，确认下载并等待模型就绪。确认框会显示本机需要下载的体积。
3. 按需在「本地热词」点「管理」逐条添加主播名、游戏名或频道专有词。
4. 分别设置「VAD（静音端点检测）」「自动标点」和「说话人区分」；说话人区分首次开启需额外下载约 `43 MiB` 声纹模型。
5. 设置「更新间隔」（`0.2–1.0 秒`，默认 `0.2 秒`，步长 `0.1 秒`）。它只决定音频送往 Rust 的分块大小；在途文本的刷新节奏由识别调度决定（见「参数」）。
6. 设置「字幕字号」（`12–48 px`，默认 `20 px`）。
7. 进入直播间、多画面主画面或 IPTV 播放页，点击播放器控制栏中的字幕图标，在来源菜单选择「字幕（本地）」；选择「关闭字幕」会停止本地字幕。B 站视频（VOD）沿用相同的来源选择逻辑，并额外列出片源提供的 CC 字幕。
8. 「字幕（本地）」下方直接显示「字幕设置」项，可切换「说话人区分」、开启「字幕翻译」，并选择原文与译文语言；两侧均支持 `auto`，字幕翻译默认关闭。
9. 字幕开启后，直播间画面内字幕区域右下角固定有「在独立窗口显示字幕」按钮（位置不随字幕长短变化，字幕过期后仍保留；直播间字幕背景也固定尺寸、不随文字伸缩：宽度跟随视频画面（约为画面宽的 92%，竖屏流或带黑边时随画面收窄，首帧前按播放器宽度计），未开翻译时高 3 行（定稿 2 行 + 识别中 1 行），开启「字幕翻译」时高 5 行（再加译文 2 行），按字号缩放并以屏幕高度的 45% 封顶；文字贴底排布，超出时裁掉最早的行）：点击后打开一个可移动、可缩放的独立字幕窗口，按时间顺序显示本次运行内所有已定稿语句与译文。再次点击只会聚焦已有窗口，不会创建第二个。关闭窗口不影响播放页字幕，重新打开会恢复本次运行的全部对话。独立窗口用虚拟滚动渲染，历史再长也只绘制可视区附近的行。

显示行为：识别中的文本以较浅颜色显示。VAD 开启时按停顿提交稳定字幕，语句越长所需停顿越短，长句会在较短的换气处断开；关闭 VAD 时按最长 `12 秒`语句切分。在途文本只覆盖当前语句最近几秒，语句结束时整句重新识别后定稿，因此定稿文本可能与在途文本略有不同。说话人区分会在稳定字幕前显示「说话人 1：」一类匿名编号，短句与临界声纹沿用最近稳定标签，实时 partial 不标注说话人。稳定字幕与当前实时语句自动分行，叠加层最多两行并在宽度不足时换行。

独立字幕窗口与画面内叠加层是两份视图：叠加层继续按 `12 秒`过期、只显示最近两行；窗口保留整场对话，不随叠加层过期或播放页卸载清空。换房间时插入一条带房间标题与时间的分隔条，而不是清空历史；换清晰度或线路仍属同一房间，不会重复插入。译文异步到达后回填到对应原文下方，即使到达时叠加层已经过期。窗口底部以弱化样式显示当前在途假设，用户上滚查看历史后停止自动跟随，并显示「回到最新」按钮。顶栏右侧的「清空」按钮在确认后删除已保存的全部字幕与译文，识别继续进行，下一句重新带出房间分隔条；没有记录时按钮禁用。窗口状态只保存在内存中，应用退出后不保留。

## 推理后端与平台差异

| 平台 | provider | 说明 |
| ---- | -------- | ---- |
| Windows x86_64 | 设置页可选「自动 / CUDA / CPU」 | 自动与 CUDA 在检测到可用 GPU 时使用 CUDA，否则回退 CPU 并在状态里说明原因 |
| Linux x86_64 / aarch64 | 固定 CPU | 运行库自带 OpenBLAS 与 OpenMP，只依赖系统 glibc / libstdc++ |
| macOS Apple Silicon | 固定 CPU | 包内含 Metal 后端，目前不启用 |
| Android / iOS | 无 ASR | — |

Windows 的 GPU 检测只加载 NVIDIA 驱动的 `nvcuda.dll`，读取第一块 GPU 的 Compute Capability 与驱动支持的 CUDA 版本：要求 Compute Capability `6.0–9.x`（GTX 10 系列 Pascal 到 Hopper）且驱动支持 CUDA `12.0` 以上。CUDA 12.6 的 cudart 与 cuBLAS 随运行库包下载，不需要安装 CUDA Toolkit 或 cuDNN。Blackwell（Compute Capability `10.x` 起，如 RTX 50 系列）不在该包支持范围，会回退 CPU。

线程与并发：运行时通过 Rust `available_parallelism()` 读取可用逻辑处理器数，识别最多 `8` 线程；Silero VAD `1` 线程，TitaNet 声纹固定 `4` 线程，二者都在 CPU 上运行。识别、VAD、声纹与会话释放都经同一把互斥锁串行驱动，避免同一 native 对象被并发调用。

## 参数

| 参数 | 默认值 | 说明 |
| ---- | ------ | ---- |
| PCM 采样率 | `16,000 Hz` | Qwen3-ASR 与 Silero VAD 的输入格式 |
| 更新间隔 | `0.2 秒` | 范围 `0.2–1.0 秒`，步长 `0.1 秒` |
| 分块重叠 | `0 秒` | 调度器按连续时间轴累积音频，禁止重复送入 |
| 识别语言 | 自动 | 不指定语言，由 Qwen3-ASR 自行判断；普通话、英语及中英混合效果最好 |
| VAD 帧 | `32 ms`（512 采样） | 每帧增量打分，不重复处理已打分的音频 |
| VAD 阈值 | 进入 `0.5`，退出 `0.35` | 滞回判定，介于两者之间保持当前状态 |
| 停顿定稿 | 已说出不足 `5 秒`：`0.8 秒`静音；`5–10 秒`：`0.5 秒`；`10 秒`以上：`0.3 秒` | 语句越长停顿越短；语句前保留约 `0.2 秒`、语句后补约 `0.2 秒` |
| 最短语句 | 约 `0.25 秒`语音 | 更短的片段（咳嗽、按键声）直接丢弃 |
| 最长语句 | `12 秒` | 到达上限时在最后约 `3 秒`内找 VAD 概率最低的一帧切分 |
| 在途刷新 | GPU 每 `0.5 秒`看最近 `6 秒`；CPU 每 `1 秒`看最近 `4 秒` | 只在有新的语音帧时刷新；定稿始终解码整句 |
| 本地热词 | 最多 `100` 个 | 在设置里逐条添加，单项不超过 `80` 个 Unicode 字符；以逗号拼接后作为提示词上下文 |
| 自动标点 | 开启 | 保留模型输出的标点；关闭后去掉中英文标点，英文单词之间的空格保留 |
| 说话人声纹 | 语句中段至多 `4 秒` | 短于 `0.6 秒`的语句沿用最近标签 |
| 说话人匹配阈值 | `0.55` | 声纹与本会话质心的余弦相似度 |
| 说话人切换滞回 | `0.68` | 临界相似度沿用最近稳定编号 |
| 说话人数量 | 最多 `8` | 匿名编号从 `1` 开始，切房重置 |
| stable 字幕保留 | `12 秒` | 新 final 会刷新计时器 |
| 可见 stable 长度 | 最多 `90` 个 Unicode 字符 | 从前端移除较旧内容 |
| 字幕行数 | 最多 `2` 行 | final 与 partial 分行，长文本按宽度换行 |
| 字幕字号 | `20 px` | 范围 `12–48 px` |
| 翻译队列 | 最多 `4` 个 final 批次 | 同批多个 segment 合并为一次 `batchexecute` |

## 识别链路

```text
video 音轨 → AudioWorklet 原声直通 + 声道混合 → 0.2–1.0 秒无重叠 PCM 分块
  → 降采样 16 kHz little-endian f32 → Base64 / Tauri asr_transcribe
  → Rust 调度器（asr/stream.rs）：Silero VAD 逐帧打分 → 滞回分句
      → 语句进行中：有界窗口重解码 → partial
      → 语句结束：整句交给 Qwen3-ASR（可选热词提示词）→ final
  → 仅 final：可选 TitaNet 声纹 + 在线匿名质心聚类
  → 播放器字幕叠加层（final 与 partial 自动分行）
  → 可选：final 文本 → Tauri HTTP → Google 翻译 → 原文 / 译文双层字幕
  → 直播间可选：final / 译文 / 在途文本 → Tauri 事件 → 独立字幕窗口
```

- Qwen3-ASR 是离线 encoder-decoder，每次解码都要重编码整段输入。调度器因此只让在途假设看最近几秒，耗时不随语句变长而增长；定稿时才解码整句。
- 音频不含 WAV 头，也不是 MP3/AAC 容器；前端把原始 `f32` 字节编码为 Base64，Rust 解码为 `Vec<f32>` 后送入调度器。
- 每次 command 返回刚完成的 `segments` 与当前 `partial`。声纹只处理 final。
- 切换房间、切换媒体源或关闭字幕时调用 `asr_reset_stream`，同时清空缓冲音频、VAD 状态与说话人质心，下一会话重新从「说话人 1」编号。
- 背压：前端只保留一个正在执行的识别任务；执行期间到达的分块拼接到待发送音频之后，积压超过单次 IPC 上限（`2 MiB`，约 `32 秒`）时只保留最新部分。调度器依赖连续时间轴分句，因此不再丢弃中间分块。
- 翻译走独立队列，不阻塞识别；原文立即显示、译文异步补充。重复 `(from, to, text)` 使用内存 LRU 缓存；切房、关闭字幕或改语言后丢弃迟到结果。Tauri `http_fetch` 复用 Rust 应用代理路由（自动／关闭／自定义），不再由前端传代理地址；初始 URL 与每次重定向都受 Google 翻译白名单限制。Google 返回 `429` 时停止当前翻译队列且不重试，原字幕继续显示。

## 已知边界

- 模型面向普通话、英语及中英混合语音，也能识别粤语、日语等其他语言；直播音乐、人声重叠、强噪声和方言会降低准确率。
- CPU 上的延迟高于旧版流式 Zipformer：GTX 1070 Ti 机器 8 线程 CPU 实测首个在途文本约 `1.1 秒`、定稿约 `2.7 秒`。有可用 NVIDIA GPU 时单次解码约 `0.1–0.4 秒`。
- 热词以提示词形式提供，越多每次解码的预填充开销越大，低性能设备应只保留必要的词。
- 说话人区分是匿名声纹聚类，不识别真实姓名，也不跨直播或跨应用启动保存身份。过短语句沿用最近标签；背景音乐与多人重叠讲话也可能误分。
- 已用 CPU 运行库包加载过字幕的进程不能直接换成 CUDA 包，需重启应用；macOS 与 Linux aarch64 尚未在真机验证。
- 默认用 `AudioWorklet` 在 Web Audio 渲染线程完成原声直通、单声道混合与分块，主线程只接收完整 PCM 分块。旧 WebView 不支持 worklet 或模块加载失败时自动回退 `ScriptProcessorNode`，两条路径保持相同的无重叠语义。
- 字幕翻译使用 Google 的非官方网页批处理接口，可能受网络、地区策略、限流或上游接口变更影响，不等同于 Google Cloud Translation SLA。`batchexecute` 与 final 批量合并可降低请求数和限流风险，但无法保证永不出现 `429`。Tauri HTTP 权限只允许访问 `https://translate.google.com/**`；纯浏览器开发页不提供翻译。
- 独立字幕窗口只有直播间提供入口，IPTV、多画面与 B 站 VOD 不显示该按钮；窗口展示的是直播间本次运行内的转录，应用重启后清空。窗口只通过 Tauri 事件接收内容，不调用任何应用命令（`main_window_only` 会拒绝非主窗口），因此它读取同源 `localStorage` 中的主题与字幕字号，不重新请求后端设置。窗口关闭后主窗口停止转发增量，但转录仍保留在内存中，重新打开会收到完整快照。字幕翻译迟到时译文仍会回填，但清空之前发出的翻译在清空后到达会被丢弃；关闭字幕或切换房间不会删除已有历史。清空同样只能以事件请求：窗口发 `asr-captions://clear`，主窗口清空转录后回发一份空快照，窗口不自行改本地列表。
