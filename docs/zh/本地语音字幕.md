# 本地语音字幕（sherpa-onnx Zipformer）

## 功能与模型

rLive 使用 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) `1.13.4` 在本机生成直播字幕。识别与标点使用两个固定的 CPU int8 模型，说话人区分使用一个按需启用的声纹模型：

- 中英双语流式识别：`sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20`，压缩包 `511,274,346` 字节。
- 中英标点恢复：`sherpa-onnx-punct-ct-transformer-zh-en-vocab272727-2024-04-12-int8`，压缩包 `64,717,756` 字节。
- 可选中英声纹：`3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx`，文件 `28,281,164` 字节。
- 首次启用合计下载约 `550 MiB`；模型解压后保存在应用数据目录，不会写入 SQLite。
- 开启「说话人区分」后合计约 `576 MiB`。该开关默认关闭，声纹模型未启用时不会下载或加载。
- 支持 Tauri 桌面客户端和 Android；纯浏览器开发页不提供本地 ASR。
- 直播 PCM 与字幕只在当前设备的 WebView 和 Rust 进程之间传递，不上传到 rLive 服务。

Windows 模型通常位于 `%APPDATA%\rlive\models\asr`，Linux 通常位于 `~/.local/share/rlive/models/asr`，Android 使用应用私有数据目录。关闭功能会释放常驻识别、标点和声纹会话，但保留已下载文件。

## 使用

1. 打开「设置 → 播放 → 语音字幕」。
2. 开启「流式语音字幕（Zipformer）」，确认下载并等待模型就绪。
3. 如需区分直播中的不同声音，开启「说话人区分」并等待约 `27 MiB` 声纹模型准备完成。
4. 将「字幕更新间隔」设为 `0.2–1.0 秒`，默认 `0.2 秒`，步长 `0.1 秒`。间隔越短，实时文本刷新越快；间隔越长，IPC 调用次数越少。
5. 将「字幕字号」设为 `12–48 px`，默认 `20 px`。
6. 进入直播间，点击播放器控制栏中的字幕图标。

Zipformer 会持续保留同一播放会话的解码状态，因此更新间隔不会截断识别上下文。识别中的文本以较浅颜色显示；检测到语句端点后，CT-Transformer 会恢复中英文标点并提交为稳定字幕。启用说话人区分时，稳定字幕会显示“说话人 1：”一类匿名编号；实时 partial 不标注说话人。稳定字幕与当前实时语句自动分行，叠加层最多保留两行并在容器宽度不足时自然换行。

首次下载的状态依次为 `downloading`、`extracting`、`loading` 和 `ready`。下载、bzip2 解压和模型加载均不在 WebView 主线程执行；设置页在解压期间保持可交互，无需 F5 重载。下载或加载失败后可在设置页重试。

## 音频与识别链路

```text
video 音轨
  → Web Audio 声道混合为单声道
  → 0.2–1.0 秒无重叠 PCM 分块
  → 降采样为 16 kHz little-endian f32
  → Base64 / Tauri asr_transcribe command
  → sherpa-onnx OnlineRecognizer + 长生命周期 OnlineStream
  → endpoint final / current partial
  → CT-Transformer 中英标点恢复
  → final PCM 的 CAMPPlus embedding + 在线匿名质心聚类（可选）
  → final 与 partial 自动分行的播放器字幕叠加层
```

音频不含 WAV 头，也不是 MP3/AAC 等容器。前端把原始 `f32` 字节编码为 Base64；Rust 解码为 `Vec<f32>` 后送入同一个 `OnlineStream`。分块之间不重叠，因为重复音频会被 streaming recognizer 当成新的采样再次识别。

`OnlineRecognizer` 使用 `greedy_search` 和 sherpa-onnx endpoint 规则：无文本尾静音 `2.4 秒`、有文本尾静音 `0.8 秒`、单次语句最长 `20 秒`。每次 command 会返回刚完成的 `segments` 与当前 `partial`。CAMPPlus 只处理 endpoint final 对应的缓存 PCM，embedding 经归一化后与本会话质心做余弦相似度匹配，最多维护 8 个匿名说话人。切换房间、切换媒体源或关闭字幕时调用 `asr_reset_stream`，同时清空解码状态、PCM 和说话人质心，下一会话重新从“说话人 1”编号。

前端只保留一个正在执行的任务和最新待处理分块。设备低于实时速度时不会形成无界队列，过期的待处理音频会被较新的分块替代，以优先保证播放与界面响应。

## 模型准备与完整性

识别模型和标点模型分别下载到 `.part` 临时文件，并按 GitHub Release 中的精确压缩包字节数校验。每个压缩包在 blocking 线程池中解压；中断留下的半成品目录会在下次准备前清理。可选 CAMPPlus 是直接下载的 ONNX 文件，同样先写 `.part` 并按 `28,281,164` 字节校验后原子替换。只有当前开关需要的文件都完整时，状态才会进入 `downloaded` 或 `ready`。

当前实现不提供模型切换、GPU provider 或 VAD 开关。Zipformer 自带在线 endpoint 检测，旧设置记录里的 `asr_vad_enabled` 只为兼容反序列化而保留，不再参与识别。`asr_speaker_diarization_enabled` 是设备本地设置，不随配置包导入导出。

## CPU 与构建

运行时通过 Rust `available_parallelism()` 读取当前进程可用的逻辑处理器数，Zipformer 最多使用 `8` 个线程，标点与 CAMPPlus 模型最多使用 `2` 个线程。识别、标点、声纹提取与模型释放都通过互斥锁串行驱动，避免同一 native 对象被并发调用。

桌面开发与构建：

```bash
bun install
bun run tauri dev
bun run tauri build
```

Windows 从 WSL 交付时使用：

```bash
./scripts/build-windows-from-wsl.sh
```

Android 仍通过 Tauri 原生命令构建，模型不会进入 APK：

```bash
rustup target add aarch64-linux-android
bun run tauri -- android build --ci --target aarch64 --apk
```

详细 Android SDK、NDK、签名与真机命令见[Android 开发与构建](Android开发-Windows.md)。

## 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| PCM 采样率 | `16,000 Hz` | Zipformer 输入格式 |
| 更新间隔 | `0.2 秒` | 设置范围 `0.2–1.0 秒`，步长 `0.1 秒` |
| 分块重叠 | `0 秒` | 长生命周期 stream 禁止重复送入音频 |
| 解码方法 | `greedy_search` | 控制实时 CPU 开销 |
| CPU 线程 | Zipformer 最多 `8`，标点最多 `2` | 不超过可用逻辑处理器数 |
| 说话人匹配阈值 | `0.55` | final embedding 与本会话质心的余弦相似度 |
| 说话人数量 | 最多 `8` | 匿名编号从 `1` 开始，切房重置 |
| stable 字幕保留 | `12 秒` | 新 final 会刷新计时器 |
| 可见 stable 长度 | 最多 `90` 个 Unicode 字符 | 从前端移除较旧内容 |
| 字幕行数 | 最多 `2` 行 | final 与 partial 分行，长文本按宽度换行 |

## 已知边界

- 当前模型面向普通话、英语及中英混合语音，直播音乐、人声重叠、强噪声和方言会降低准确率。
- CT-Transformer 会对实时 partial 重复计算标点；partial 本身会随新音频修正，只有 endpoint final 才视为稳定文本。
- 说话人区分是匿名声纹聚类，不会识别真实姓名，也不会跨直播或跨应用启动保存身份。
- 过短语句可能不足以提取 embedding，此时 final 保持无标签；背景音乐、强噪声和多人重叠讲话也可能造成漏标或误分。
- Android 开启说话人区分会在每次 endpoint 后增加 CPU、耗电和发热，默认关闭；低性能设备应优先保持关闭。
- `ScriptProcessorNode` 是当前 WebView 兼容路径；未来可迁移到 `AudioWorklet`，但必须保持原声输出、单声道混合、无重叠和有界背压语义。
