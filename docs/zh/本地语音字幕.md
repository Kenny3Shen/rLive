# 本地语音字幕（sherpa-onnx Zipformer）

rLive 用 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) `1.13.4` 在本机生成直播字幕。想启用功能看「使用步骤」，关心磁盘与算力开销看「模型与下载量」和「参数」，遇到识别不准或翻译失败看「已知边界」。

- 音频链路在整体架构中的位置：[架构说明](架构说明.md) 第 6 节
- 桌面构建与运行命令：[开发指南](开发指南.md)

仅支持 Tauri 桌面客户端。Android 与 iOS 不提供本地 ASR，也不展示字幕设置或播放器入口；Android Rust target 会排除 ASR 代码与 native runtime。

## 数据边界

- 直播 PCM 只在当前设备的 WebView 与 Rust 进程之间传递，不上传到 rLive 服务。
- 模型、热词文件、声纹 embedding 与字幕文本都留在本地。
- 字幕翻译默认关闭。用户主动开启后，只有 endpoint 已定稿的文字会经 `google-translate-api-x` 的 `batchexecute` 端点发送到 Google 翻译；实时 partial、PCM、声纹与热词不会发送。
- `asr_provider`、`asr_vad_enabled`、`asr_punctuation_enabled`、`asr_speaker_diarization_enabled`、`asr_hotwords` 与 `asr_translation_*` 都是设备本地设置，不随配置包导入导出，避免另一台设备意外下载模型、覆盖本地领域词或代替用户同意向 Google 发送字幕。

## 模型与下载量

| 用途 | 模型 | 大小 |
| ---- | ---- | ---- |
| 中英双语流式识别 | `sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20` | 压缩包 `511,274,346` 字节 |
| 中英标点恢复 | `sherpa-onnx-punct-ct-transformer-zh-en-vocab272727-2024-04-12-int8` | 压缩包 `64,717,756` 字节 |
| 可选中英声纹 | `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` | 文件 `28,281,164` 字节 |

- 默认（含自动标点）约 `550 MiB`；关闭「自动标点」只需约 `488 MiB`。
- Windows 首次启用还会下载约 `212 MiB` 运行库，因此默认总下载量约 `762 MiB`，关闭标点约 `700 MiB`。
- 开启「说话人区分」后合计约 `576 MiB`。该开关默认关闭，未启用时声纹模型不下载、不加载。
- 「VAD（静音端点检测）」不额外下载模型，使用 Zipformer 的端点规则。

存放位置：Windows 模型在 `%APPDATA%\rlive\models\asr`、运行库在 `%APPDATA%\rlive\asr-runtime`；Linux 模型通常在 `~/.local/share/rlive/models/asr`。关闭功能会释放常驻识别、标点和声纹会话，但保留已下载文件。

首次下载状态依次为 `downloading`、`extracting`、`loading`、`ready`。下载、bzip2 解压与模型加载都不在 WebView 主线程执行，设置页在解压期间保持可交互；失败后可在设置页重试。

完整性校验：Windows 运行库核对固定大小与 SHA-256 后解压；识别与标点模型先写 `.part`，按 GitHub Release 中的精确压缩包字节数校验；CAMPPlus 按 `28,281,164` 字节校验后原子替换；热词文件用独立 `.part` 原子替换。中断留下的半成品目录会在下次准备前清理。只有当前开关需要的文件都完整时，状态才进入 `downloaded` 或 `ready`。

## 使用步骤

1. 打开「设置 → 播放 → 语音字幕」。
2. 开启「流式语音字幕（Zipformer）」，确认下载并等待模型就绪。
3. 按需在「本地热词」点「管理」逐条添加主播名、游戏名或频道专有词。
4. 分别设置「VAD（静音端点检测）」「自动标点」和「说话人区分」；说话人区分首次开启需额外下载约 `27 MiB` 声纹模型。
5. 设置「更新间隔」（`0.2–1.0 秒`，默认 `0.2 秒`，步长 `0.1 秒`）。间隔越短实时文本刷新越快，越长 IPC 调用次数越少。
6. 设置「字幕字号」（`12–48 px`，默认 `20 px`）。
7. 进入直播间，点击播放器控制栏中的字幕图标。
8. 鼠标悬停或键盘聚焦字幕图标，在「字幕设置」浮层中可切换「说话人区分」、开启「字幕翻译」，并选择原文与译文语言；两侧均支持 `auto`。

显示行为：识别中的文本以较浅颜色显示。VAD 开启时按静音端点提交稳定字幕，关闭时按最长 `20 秒`语句切分。自动标点开启时由 CT-Transformer 恢复中英文标点，关闭后保留 Zipformer 原始文本。说话人区分会在稳定字幕前显示「说话人 1：」一类匿名编号，短句与临界声纹沿用最近稳定标签，实时 partial 不标注说话人。稳定字幕与当前实时语句自动分行，叠加层最多两行并在宽度不足时换行。更新间隔不会截断识别上下文，Zipformer 持续保留同一播放会话的解码状态。

## 推理后端与平台差异

| 平台 | 运行库交付 | provider |
| ---- | ---------- | -------- |
| Windows x86_64 | 首次启用时下载官方 `sherpa-onnx-v1.13.4-win-x64-cuda.tar.bz2`（构建期只用其导入库做延迟链接，Release 不附带 DLL） | 设置页可选「自动 / CUDA / CPU」 |
| Linux x86_64 | 构建期下载并链接官方 `sherpa-onnx-v1.13.4-linux-x64-shared-lib.tar.bz2`；DEB / RPM / AppImage 内置 `libsherpa-onnx-c-api.so`、`libonnxruntime.so` 及 CPU 运行库 | 固定 CPU-only，不打包也不探测 CUDA |
| macOS | 无需额外下载 | 固定 CPU |
| Android | 不交付 | 无 ASR |

Windows 自动模式会检查 NVIDIA 驱动与随应用构建的 ONNX Runtime CUDA provider，满足条件时让 Zipformer、CT-Transformer 与 CAMPPlus 使用 GPU，否则回退 CPU；选择 CUDA 但运行库不可用同样回退。设置页状态显示实际 provider 与回退提示。该包的 CUDA provider 含 `sm_61` 及 Turing/Ampere/Ada 内核，依赖 CUDA 11.x 与 x86-64 cuDNN 8.x（`cudnn64_8.dll`、`cudart64_110.dll`、`cublas64_11.dll` 等），因此 GTX 1070 Ti（6.1）可用，但不能与 CUDA 12 / cuDNN 9 DLL 混用。发布前应在 NVIDIA 与非 NVIDIA 机器分别验证实际 provider。`SHERPA_ONNX_GPU=0` 只用于在 Windows 另行构建 CPU-only 版本。

线程与并发：运行时通过 Rust `available_parallelism()` 读取可用逻辑处理器数；CPU provider 下 Zipformer 最多 `8` 线程，标点与 CAMPPlus 最多 `2` 线程。识别、标点、声纹提取与模型释放都通过互斥锁串行驱动，避免同一 native 对象被并发调用。VAD endpoint 规则始终由识别器 CPU 侧控制，没有独立 VAD ONNX 模型。

## 参数

| 参数 | 默认值 | 说明 |
| ---- | ------ | ---- |
| PCM 采样率 | `16,000 Hz` | Zipformer 输入格式 |
| 更新间隔 | `0.2 秒` | 范围 `0.2–1.0 秒`，步长 `0.1 秒` |
| 分块重叠 | `0 秒` | 长生命周期 stream 禁止重复送入音频 |
| 解码方法 | `greedy_search` | 控制实时 CPU 开销；配置热词时切换为小 beam 的 `modified_beam_search` |
| 热词分数 | `hotwords_score=2.0` | 经 `hotwords_file` 提供上下文偏置 |
| 本地热词 | 最多 `100` 个 | 在设置里逐条添加，单项不超过 `80` 个 Unicode 字符 |
| VAD | 开启 | 无文本尾静音 `2.4 秒`、有文本尾静音 `0.8 秒`；关闭时只保留最长 `20 秒`边界 |
| 自动标点 | 开启 | 按需加载 CT-Transformer；关闭后保留原始文本 |
| CPU 线程 | Zipformer 最多 `8`，标点与声纹最多 `2` | 不超过可用逻辑处理器数 |
| 说话人最短语句 | `0.6 秒` | 更短的 final 沿用最近标签 |
| 说话人匹配阈值 | `0.55` | final embedding 与本会话质心的余弦相似度 |
| 说话人切换滞回 | `0.68` | 临界相似度沿用最近稳定编号 |
| 说话人数量 | 最多 `8` | 匿名编号从 `1` 开始，切房重置 |
| stable 字幕保留 | `12 秒` | 新 final 会刷新计时器 |
| 可见 stable 长度 | 最多 `90` 个 Unicode 字符 | 从前端移除较旧内容 |
| 字幕行数 | 最多 `2` 行 | final 与 partial 分行，长文本按宽度换行 |
| 字幕字号 | `20 px` | 范围 `12–48 px` |
| 翻译队列 | 最多 `4` 个 final 批次 | 同批多个 segment 合并为一次 `batchexecute` |

## 识别链路

```text
video 音轨 → AudioWorklet 原声直通 + 声道混合 → 0.2–1.0 秒无重叠 PCM 分块
  → 降采样 16 kHz little-endian f32 → Base64 / Tauri asr_transcribe
  → sherpa-onnx OnlineRecognizer + 长生命周期 OnlineStream（可选 hotwords 偏置）
  → endpoint final / current partial（可选 VAD 静音端点）
  → 可选 CT-Transformer 标点 → 可选 CAMPPlus embedding + 在线匿名质心聚类
  → 播放器字幕叠加层（final 与 partial 自动分行）
  → 可选：final 文本 → Tauri HTTP → Google 翻译 → 原文 / 译文双层字幕
```

- 音频不含 WAV 头，也不是 MP3/AAC 容器；前端把原始 `f32` 字节编码为 Base64，Rust 解码为 `Vec<f32>` 后送入同一个 `OnlineStream`。分块之间不重叠，重复音频会被 streaming recognizer 当成新采样再次识别。
- 每次 command 返回刚完成的 `segments` 与当前 `partial`。CAMPPlus 只处理 endpoint final 对应的缓存 PCM。
- 切换房间、切换媒体源或关闭字幕时调用 `asr_reset_stream`，同时清空解码状态、PCM 与说话人质心，下一会话重新从「说话人 1」编号。
- 背压：前端只保留一个正在执行的识别任务和最新待处理分块，设备低于实时速度时过期音频被较新分块替代，优先保证播放与界面响应。
- 翻译走独立队列，不阻塞识别；原文立即显示、译文异步补充。重复 `(from, to, text)` 使用内存 LRU 缓存；切房、关闭字幕或改语言后丢弃迟到结果。Tauri HTTP 继承「设置 → 网络」中的应用代理。Google 返回 `429` 时停止当前翻译队列且不重试，原字幕继续显示。

## 已知边界

- 模型面向普通话、英语及中英混合语音；直播音乐、人声重叠、强噪声和方言会降低准确率。
- 说话人区分是匿名声纹聚类，不识别真实姓名，也不跨直播或跨应用启动保存身份。过短语句可能不足以提取 embedding，此时 final 保持无标签；背景音乐与多人重叠讲话也可能漏标或误分。
- 配置热词会切换 modified beam search 并增加识别开销，低性能桌面设备应按需启用。
- 默认用 `AudioWorklet` 在 Web Audio 渲染线程完成原声直通、单声道混合与分块，主线程只接收完整 PCM 分块。旧 WebView 不支持 worklet 或模块加载失败时自动回退 `ScriptProcessorNode`，两条路径保持相同的无重叠与有界背压语义。
- 字幕翻译使用 Google 的非官方网页批处理接口，可能受网络、地区策略、限流或上游接口变更影响，不等同于 Google Cloud Translation SLA。`batchexecute` 与 final 批量合并可降低请求数和限流风险，但无法保证永不出现 `429`。Tauri HTTP 权限只允许访问 `https://translate.google.com/**`；纯浏览器开发页不提供翻译。
