# 本地语音字幕（sherpa-onnx Zipformer）

## 功能与模型

rLive 使用 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) `1.13.4` 在本机生成直播字幕。识别、可选标点和可选说话人模型都在设备本地运行：

- 中英双语流式识别：`sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20`，压缩包 `511,274,346` 字节。
- 中英标点恢复：`sherpa-onnx-punct-ct-transformer-zh-en-vocab272727-2024-04-12-int8`，压缩包 `64,717,756` 字节。
- 可选中英声纹：`3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx`，文件 `28,281,164` 字节。
- 字幕模型首次启用默认下载约 `550 MiB`；关闭「自动标点」时只需约 `488 MiB` 的 Zipformer 识别模型。Windows 还会在首次启用时下载约 `212 MiB` 的运行库，因此默认总下载量约 `762 MiB`，关闭标点时约 `700 MiB`。
- 开启「说话人区分」后合计约 `576 MiB`。该开关默认关闭，声纹模型未启用时不会下载或加载。
- 「VAD（静音端点检测）」和「自动标点」默认开启，二者可以独立关闭；VAD 不额外下载模型，使用 Zipformer 的端点规则。
- 「本地热词」按行配置主播名、游戏名和频道专有词，最多 `100` 个，单项不超过 `80` 个 Unicode 字符。配置后使用 modified beam search 和本地 hotwords 文件增强专有名词偏置；未配置热词时继续使用更省资源的 greedy search。
- 仅支持 Tauri 桌面客户端；Android、iOS 不提供本地 ASR，也不展示字幕设置或播放器入口。
- 直播 PCM 始终只在当前设备的 WebView 和 Rust 进程之间传递，不上传到 rLive 服务。
- 字幕翻译默认关闭。用户主动开启后，只有 endpoint 已定稿的文字会通过 `google-translate-api-x` 的 `batchexecute` 批处理端点发送到 Google 翻译；实时 partial、PCM、说话人声纹和热词不会发送。

Windows 模型位于 `%APPDATA%\rlive\models\asr`，运行库位于 `%APPDATA%\rlive\asr-runtime`；Linux 模型通常位于 `~/.local/share/rlive/models/asr`。关闭功能会释放常驻识别、标点和声纹会话，但保留已下载文件。

## 使用

1. 打开「设置 → 播放 → 语音字幕」。
2. 开启「流式语音字幕（Zipformer）」，确认下载并等待模型就绪。
3. 按需配置「本地热词」，每行一个主播名、游戏名或频道专有词。
4. 分别设置「VAD（静音端点检测）」「自动标点」和「说话人区分」；说话人区分首次开启需额外下载约 `27 MiB` 声纹模型。
5. 将「字幕更新间隔」设为 `0.2–1.0 秒`，默认 `0.2 秒`，步长 `0.1 秒`。间隔越短，实时文本刷新越快；间隔越长，IPC 调用次数越少。
6. 将「字幕字号」设为 `12–48 px`，默认 `20 px`。
7. 进入直播间，点击播放器控制栏中的字幕图标。
8. 鼠标悬停或键盘聚焦字幕图标，在「字幕设置」浮层中可直接切换「说话人区分」、开启「字幕翻译」，并选择原文与译文语言；两侧均支持 `auto`。

Zipformer 会持续保留同一播放会话的解码状态，因此更新间隔不会截断识别上下文。识别中的文本以较浅颜色显示；VAD 开启时按静音端点提交稳定字幕，关闭时仍按最长 `20 秒`语句切分。自动标点开启时，CT-Transformer 恢复中英文标点；关闭后保留 Zipformer 原始文本。启用说话人区分时，稳定字幕会显示“说话人 1：”一类匿名编号；短句和临界声纹会沿用最近稳定标签，减少编号抖动；实时 partial 不标注说话人。稳定字幕与当前实时语句自动分行，叠加层最多保留两行并在容器宽度不足时自然换行。

首次下载的状态依次为 `downloading`、`extracting`、`loading` 和 `ready`。下载、bzip2 解压和模型加载均不在 WebView 主线程执行；设置页在解压期间保持可交互，无需 F5 重载。下载或加载失败后可在设置页重试。

## 音频与识别链路

```text
video 音轨
  → AudioWorklet 音频线程原声直通 + 声道混合
  → 音频线程生成 0.2–1.0 秒无重叠 PCM 分块
  → 降采样为 16 kHz little-endian f32
  → Base64 / Tauri asr_transcribe command
  → sherpa-onnx OnlineRecognizer + 长生命周期 OnlineStream
  → endpoint final / current partial（可选静音端点 VAD）
  → CT-Transformer 中英标点恢复（可选）
  → 本地 hotwords 文件上下文偏置（配置热词时启用 modified beam search）
  → final PCM 的 CAMPPlus embedding + 在线匿名质心聚类（可选）
  → final 与 partial 自动分行的播放器字幕叠加层
  → 可选：final 文本 → Tauri HTTP → Google 翻译 → 原文 / 译文双层字幕
```

音频不含 WAV 头，也不是 MP3/AAC 等容器。前端把原始 `f32` 字节编码为 Base64；Rust 解码为 `Vec<f32>` 后送入同一个 `OnlineStream`。分块之间不重叠，因为重复音频会被 streaming recognizer 当成新的采样再次识别。

`OnlineRecognizer` 未配置热词时使用 `greedy_search`；配置热词时切换为小 beam 的 `modified_beam_search`，每行 hotword phrase 通过 `hotwords_file` 和 `hotwords_score=2.0` 提供上下文偏置。VAD 开启时使用无文本尾静音 `2.4 秒`、有文本尾静音 `0.8 秒`、单次语句最长 `20 秒`；关闭 VAD 时只保留最长语句边界。每次 command 会返回刚完成的 `segments` 与当前 `partial`。标点模型只在开关开启时加载。CAMPPlus 只处理 endpoint final 对应的缓存 PCM；少于 `0.6 秒` 的短句沿用最近标签，其他 embedding 经归一化后与本会话质心做余弦相似度匹配，并使用 `0.55` 匹配阈值和 `0.68` 切换滞回，最多维护 8 个匿名说话人。切换房间、切换媒体源或关闭字幕时调用 `asr_reset_stream`，同时清空解码状态、PCM 和说话人质心，下一会话重新从“说话人 1”编号。

前端只保留一个正在执行的识别任务和最新待处理分块。设备低于实时速度时不会形成无界音频队列，过期的待处理音频会被较新的分块替代，以优先保证播放与界面响应。翻译使用另一条最多保留 4 个 final 批次的队列，不阻塞识别；同一批次中的多个 segment 会合并为一次 `batchexecute` 请求，原文立即显示，译文异步补充。重复 `(from, to, text)` 使用内存 LRU 缓存；切房、关闭字幕或修改语言后会丢弃迟到结果。Tauri HTTP 会继承「设置 → 网络」中的应用代理。Google 返回 `429` 时停止当前翻译队列且不盲目重试，原字幕继续显示；用户可稍后重新开启翻译，或更换应用代理后重试。

## 模型准备与完整性

Windows 安装包和便携 ZIP 都不内置 ASR DLL。首次启用时先下载官方 `sherpa-onnx-v1.13.4-win-x64-cuda.tar.bz2`，核对固定大小与 SHA-256 后解压到 `%APPDATA%\rlive\asr-runtime`；失败后可在设置页直接重试。识别模型和标点模型分别下载到 `.part` 临时文件，并按 GitHub Release 中的精确压缩包字节数校验；标点关闭时不会下载或加载标点压缩包。每个压缩包在 blocking 线程池中解压；中断留下的半成品目录会在下次准备前清理。可选 CAMPPlus 是直接下载的 ONNX 文件，同样先写 `.part` 并按 `28,281,164` 字节校验后原子替换。热词文件使用独立 `.part` 文件原子替换。只有当前开关需要的文件都完整时，状态才会进入 `downloaded` 或 `ready`。

Windows 和 Linux x86_64 桌面端在「推理后端」中提供「自动 / CUDA / CPU」选择。自动模式会检查 NVIDIA 驱动和随应用构建的 ONNX Runtime CUDA provider，满足条件时让 Zipformer、CT-Transformer 标点和 CAMPPlus 说话人模型使用 NVIDIA GPU，否则回退 CPU；设置页状态会显示实际使用的 provider 和回退提示。选择 CUDA 时若运行库不可用同样回退 CPU。当前 VAD 使用 Zipformer 的 CPU endpoint 规则，没有独立 VAD ONNX 模型。macOS 和 Linux 非 x86_64 桌面端固定使用 CPU。`asr_provider`、`asr_vad_enabled`、`asr_punctuation_enabled`、`asr_speaker_diarization_enabled`、`asr_hotwords` 和 `asr_translation_*` 都是设备本地设置；它们不随配置包导入导出，避免另一台设备意外下载模型、覆盖本地领域词或代替用户同意向 Google 发送字幕。

## 推理后端与构建

运行时通过 Rust `available_parallelism()` 读取当前进程可用的逻辑处理器数。CPU provider 下 Zipformer 最多使用 `8` 个线程；标点与 CAMPPlus 模型最多使用 `2` 个线程。CUDA provider 会传递给识别、标点和声纹模型；VAD endpoint 规则仍由识别器 CPU 侧控制。识别、标点、声纹提取与模型释放都通过互斥锁串行驱动，避免同一 native 对象被并发调用。

Windows 构建时使用官方 `sherpa-onnx-v1.13.4-win-x64-cuda.tar.bz2` 的导入库完成延迟链接，但 Release 不附带其中的 DLL；运行时由应用按需下载同一归档。该包的 ONNX Runtime CUDA provider 包含 `sm_61` 以及 Turing/Ampere/Ada 等架构的内核，并依赖 CUDA 11.x、x86-64 cuDNN 8.x（`cudnn64_8.dll`、`cudart64_110.dll`、`cublas64_11.dll` 等）；因此 GTX 1070 Ti（6.1）可以使用这个包，但不能与 CUDA 12/cuDNN 9 DLL 混用。64 位 NVIDIA 驱动、GPU 架构或 DLL 依赖不满足时，自动模式会回退 CPU。发布前应在 NVIDIA 和非 NVIDIA 机器分别验证实际 provider。`SHERPA_ONNX_GPU=0` 只适用于另行构建 CPU-only 版本；当前官方 Windows Release 固定按 CUDA-capable 归档动态下载。

Linux x86_64 构建默认下载并链接官方 `sherpa-onnx-v1.13.4-linux-x64-gpu.tar.bz2` shared runtime。Release 的 DEB、RPM、AppImage 与 Linux 便携 ZIP 都会内置 `libsherpa-onnx-c-api.so`、`libonnxruntime.so` 及 ONNX Runtime provider，无需用户另行安装 Sherpa ONNX；`target/release/rlive` 也会从同目录加载这些库。该包的 CUDA provider 仍依赖主机提供的 CUDA 11.x、x86-64 cuDNN 8.x（`libcudart.so.11.0`、`libcublas.so.11`、`libcublasLt.so.11`、`libcudnn.so.8`、`libcurand.so.10`、`libcufft.so.10` 等）和 NVIDIA 驱动；缺少任一依赖时自动模式会回退 CPU。Linux CUDA 接入尚未完成完整硬件和发行版测试，发布前应在 NVIDIA 与非 NVIDIA 机器分别验证实际 provider。Linux 构建可设置 `SHERPA_ONNX_GPU=0` 使用 CPU-only shared runtime；Windows 也支持同一开关。

桌面开发与构建：

```bash
bun install
bun run tauri dev
bun run tauri build
```

Windows 从 WSL 交付时使用：

```bash
cp scripts/windows-sync.conf.example scripts/windows-sync.conf
# 编辑 scripts/windows-sync.conf，设置 WINDOWS_SYNC_PATH
./scripts/build-windows-from-wsl.sh
```

Android 仍通过 Tauri 原生命令构建，但当前不提供语音字幕；Android Rust target 会排除 ASR 代码和 native runtime，也不会下载字幕模型：

```bash
rustup target add aarch64-linux-android
bun run tauri -- android build --ci --target aarch64 --apk
```

详细 Android SDK、NDK、签名与真机命令见[Android 开发与构建](Android开发-Windows.md)。

## 参数

| 参数             | 默认值                              | 说明                                                     |
| ---------------- | ----------------------------------- | -------------------------------------------------------- |
| PCM 采样率       | `16,000 Hz`                       | Zipformer 输入格式                                       |
| 更新间隔         | `0.2 秒`                          | 设置范围`0.2–1.0 秒`，步长 `0.1 秒`                 |
| 分块重叠         | `0 秒`                            | 长生命周期 stream 禁止重复送入音频                       |
| 解码方法         | `greedy_search`                   | 控制实时 CPU 开销                                        |
| VAD              | 开启                                | 静音端点`2.4 / 0.8 秒`；关闭时只保留最长 `20 秒`边界 |
| 自动标点         | 开启                                | 按需加载 CT-Transformer；关闭后保留原始文本              |
| CPU 线程         | Zipformer 最多`8`，标点最多 `2` | 不超过可用逻辑处理器数                                   |
| 本地热词         | 最多`100` 个                      | 每行一个 phrase；启用时使用 modified beam search         |
| 说话人匹配阈值   | `0.55`                            | final embedding 与本会话质心的余弦相似度                 |
| 说话人切换滞回   | `0.68`                            | 临界相似度沿用最近稳定编号                               |
| 说话人数量       | 最多`8`                           | 匿名编号从`1` 开始，切房重置                           |
| stable 字幕保留  | `12 秒`                           | 新 final 会刷新计时器                                    |
| 可见 stable 长度 | 最多`90` 个 Unicode 字符          | 从前端移除较旧内容                                       |
| 字幕行数         | 最多`2` 行                        | final 与 partial 分行，长文本按宽度换行                  |

## 已知边界

- 当前模型面向普通话、英语及中英混合语音，直播音乐、人声重叠、强噪声和方言会降低准确率。
- 自动标点只对实时 partial 和 endpoint final 调用 CT-Transformer；关闭后不产生额外标点模型 CPU 开销。
- 说话人区分是匿名声纹聚类，不会识别真实姓名，也不会跨直播或跨应用启动保存身份。
- 过短语句可能不足以提取 embedding，此时 final 保持无标签；背景音乐、强噪声和多人重叠讲话也可能造成漏标或误分。
- 配置热词会切换 modified beam search，并增加识别开销；低性能桌面设备应按需启用。
- 默认使用 `AudioWorklet` 在 Web Audio 渲染线程完成原声直通、单声道混合和分块，主线程只接收完整 PCM 分块，避免 `ScriptProcessorNode` 回调受 UI 长任务影响。旧 WebView 不支持 worklet 或模块加载失败时会自动回退到 `ScriptProcessorNode`，两条路径保持相同的无重叠与有界背压语义。
- 字幕翻译使用 Google 的非官方网页批处理接口，可能受网络、地区策略、限流或上游接口变更影响，也不等同于 Google Cloud Translation SLA。`batchexecute` 与 final 批量合并可降低请求数和 `translate_a/single` 常见的限流风险，但无法保证永不出现 `429`。Tauri HTTP 能绕过 WebView CORS、继承应用代理，且权限只允许访问 `https://translate.google.com/**`；纯浏览器开发页不提供翻译。
