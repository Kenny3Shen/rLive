# 本地语音字幕（CrispASR）

## 功能与模型

rLive 的直播语音字幕完全在本机运行，后端使用 [CrispASR](https://github.com/CrispStrobe/CrispASR) `0.8.25`（固定提交 `6e5bf7f`），模型使用 [`cstr/qwen3-asr-0.6b-GGUF`](https://huggingface.co/cstr/qwen3-asr-0.6b-GGUF) 中的 `qwen3-asr-0.6b-q4_k.gguf`。

- ASR 模型大小：`631,026,336` 字节（约 631 MB）。
- 可选 VAD：Silero v6.2.0，`885,098` 字节（约 865 KiB）。
- 模型由 Qwen3-ASR 自动识别语言；许可为 Apache-2.0，CrispASR 许可见上游仓库。
- 支持 Tauri 桌面客户端和 Tauri Android；纯浏览器开发页不提供本地 ASR。
- 直播 PCM 只在当前设备的 WebView 与 Rust 进程之间传递，不上传到 rLive 服务，也不写入数据库。

首次在「设置 → 播放 → 语音字幕」启用时，应用会确认约 631 MB 下载。Windows 文件位于 `%APPDATA%\\rlive\\models\\asr`，Linux 通常位于 `~/.local/share/rlive/models/asr`；Android 使用应用私有数据目录。关闭功能会释放模型内存，但保留已下载文件。

## CrispASR 输入格式

rLive 调用的是 CrispASR session C API，不是 CLI 的音频文件解码入口。`crispasr_session_transcribe` 接收一段连续的 `float*` PCM 与样本数：音频必须是 `16,000 Hz`、单声道 `f32` 样本，不带 WAV 头，也不是 MP3/AAC 等容器。前端先把 Web Audio 声道混合并降采样，再把 little-endian `f32` 原始字节编码为 Base64 通过 Tauri IPC 发送；Rust 解码成 `Vec<f32>` 后才把指针交给 CrispASR。启用 VAD 时，同一 PCM 还会以显式 `16,000 Hz` 采样率传给 Silero。

## 使用

1. 打开「设置 → 播放 → 语音字幕」。
2. 开启「本地语音字幕」，确认下载并等待“模型已就绪”。状态会显示自动检测到的 CPU 线程数。
3. 按需开启「语音活动检测（VAD）」。VAD 默认关闭；首次开启会下载约 865 KiB 的 Silero 模型。
4. 设置「语音字幕窗口」为 `1–6 秒`，默认 `1 秒`，滑动步长为 `0.1 秒`。窗口越短延迟越低，窗口越长上下文越完整、调用次数越少。
5. 设置「字幕字号」为 `12–48 px`，默认 `20 px`。字号只影响播放器字幕叠加层，不影响弹幕或推理。
6. 进入直播间后点击播放器控制栏字幕图标。启用识别期间图标保持稳定，不会因每个窗口的推理状态闪烁。

切换 VAD 会在下一窗口生效，不会重新加载 Qwen3 会话。模型加载或转写失败时可从设置页重试；关闭总开关会停止采集并释放常驻模型内存，但不会删除模型文件。

## CPU-only 构建

rLive 固定使用 CrispASR CPU 后端，不再编译或发布 CUDA、Vulkan、Metal 后端，也不提供 GPU/CPU 运行时选择。CrispASR/ggml 在编译期按目标平台选择可用 CPU 指令集；运行时通过 Rust `available_parallelism()` 读取当前进程可用的逻辑处理器数，ASR session 最多使用 8 个线程，Silero VAD 最多使用 2 个线程。可用线程少于上限时不会超额创建线程。

桌面开发与构建：

```bash
bun install
bun run tauri dev
bun run tauri build
```

Windows 从 WSL 交付时使用：

```bash
./scripts/build-windows-from-wsl.sh
```

脚本只使用 Visual Studio MSVC + CPU。Windows 下不应再传 `--features asr-cuda`、`asr-vulkan` 或 `asr-metal`；这些 feature 已从 rLive 移除。

## Android 构建

Android 构建需要 JDK 17、Android SDK（平台 36 和 Build Tools 36）、NDK 29.0.13846066、Rust target `aarch64-linux-android` 以及 Bun。确认 `ANDROID_HOME` 或 `ANDROID_SDK_ROOT` 已指向 SDK 后执行：

```bash
rustup target add aarch64-linux-android
bun run tauri -- android build --ci --target aarch64 --apk
```

Android 构建使用 Tauri 原生命令。若当前环境没有自动注入 NDK 的 CMake toolchain，可在执行命令前设置 `CRISPASR_ANDROID_NDK`、`CMAKE_TOOLCHAIN_FILE` 和 `CMAKE_GENERATOR`：

```bash
export CRISPASR_ANDROID_NDK="$ANDROID_NDK_HOME"
export CMAKE_TOOLCHAIN_FILE="$PWD/scripts/android-crispasr-toolchain.cmake"
export CMAKE_GENERATOR="Unix Makefiles"
```

CrispASR 的 `libcrispasr.so`、`libggml*.so` 和 OpenMP runtime 会由 `src-tauri/build.rs` staged 到 `src-tauri/gen/android/app/src/main/jniLibs/<abi>`，再由 Gradle 打进 APK。`--target aarch64` 的 APK 只包含 `arm64-v8a`；即使输出路径带有 `universal` flavor 名称，也不表示包含其他 ABI。release staging 会剥离 native 调试段，因此正常 APK 约 50–60 MB；631 MB 模型仍按需下载到应用私有目录，不会打包进 APK。

构建脚本会根据 Cargo 目标架构从 NDK 的对应目录选择 `libomp.so`。不要用 `arm` 目录的 32 位库覆盖 `arm64-v8a`，否则 Android 在加载 `libcrispasr.so` 时会因 ELF 格式不匹配而闪退。可用下面的命令在安装前检查：

```bash
APK=$(find src-tauri/gen/android/app/build/outputs/apk -name 'app-*-release*.apk' -type f | head -n 1)
file src-tauri/gen/android/app/src/main/jniLibs/arm64-v8a/*.so
"$ANDROID_HOME/build-tools/36.0.0/zipalign" -P 16 -c -v 4 "$APK"
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify --verbose "$APK"
```

只有 `app-*-release.apk` 可以直接用 `adb install`；AAB 是应用商店格式。未配置 release keystore 时 `--ci` 可能生成 unsigned APK，需要先签名。

如需指定 NDK：

```bash
export ANDROID_NDK_HOME="$ANDROID_SDK_ROOT/ndk/29.0.13846066"
bun run tauri -- android build --ci --target aarch64 --apk
```

## 实时链路

```text
video 音轨
  → Web Audio 双声道混合为单声道
  → 固定窗口（设置值 1–6 秒，步长 0.1 秒，默认 1 秒，0.25 秒重叠）
  → 降采样为 16 kHz f32 PCM
  → Tauri asr_transcribe command
  → 可选 Silero VAD（无语音时直接返回）
  → 常驻 CrispASR Qwen3 CPU session
  → 播放器字幕叠加层
```

每个窗口转写完成后立即更新字幕。前端只保留一个正在执行的任务和最新待处理窗口；慢设备不会形成无限队列，过期中间窗口会被丢弃以优先保持直播播放和界面响应。单个 CrispASR session 由互斥锁串行使用，线程数只用于 session 内部并行，避免创建多个模型副本。

VAD 开启时先调用 `crispasr_vad_slices`。没有检测到语音的窗口直接返回空结果，不启动 Qwen3 推理；有语音时再调用 `crispasr_session_transcribe_vad`，由 CrispASR 裁剪、拼接并映射时间戳。VAD 阈值保持上游默认值，窗口很短时仍可能过滤过短的声音。

当前 rLive 使用窗口级流式字幕，不是 Qwen3 的逐 token 输出。CrispASR CLI 的 `--live --flush-after 1` 会在每个 VAD segment 完成后立即打印一个 SRT 条目；这与 rLive“每个固定音频窗口完成即更新字幕”的消费语义相同，但 CLI 的 token callback 尚未成为稳定 C ABI。要实现真正的窗口内逐 token 字幕，需按[Qwen3-ASR Streaming C API 暴露流程](Qwen3-ASR-Streaming-C-API.md)扩展上游接口。

## 编译期参数（默认值）

以下是当前实现为实时字幕保留的默认参数。用户界面只开放窗口、VAD 开关和字幕字号；修改代码中的编译期参数后需要重新构建并重新验证目标设备。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| PCM 采样率 | `16,000 Hz` | CrispASR/Qwen3 输入格式 |
| 字幕窗口 | `1 秒` | 设置可调范围 `1–6 秒`，步长 `0.1 秒` |
| 窗口重叠 | `0.25 秒` | 降低词语在边界被切开的概率 |
| 最大新 token | `256` | 防止异常长输出占用唯一 session |
| CPU 线程 | ASR 最多 `8`，VAD 最多 `2` | 不超过 `available_parallelism()` 返回的可用逻辑处理器数 |
| VAD threshold | `0.5` | Silero 语音置信度阈值 |
| VAD speech padding | `30 ms` | 保留语音边界 |
| VAD chunk | `30 s` | 上游 Silero 分析块大小 |

窗口越短，首个字幕通常越早，但上下文和识别稳定性会下降，且 IPC/模型固定开销占比更高；窗口越长则相反。建议先使用默认 `1 秒`，在目标设备上观察字幕延迟、丢弃窗口和识别质量，再在设置中按 `0.1 秒`步长调整，不要通过修改编译期常量替代用户设置。

## 已知边界

- CPU 性能取决于指令集、内存带宽和语种。设备无法实时处理时，应用优先保持直播播放与 UI 响应。
- 当前只展示转写文本，不提供翻译、说话人分离、字幕文件导出或历史保存。
- VAD 适合语音与静音交替的直播；持续音乐、环境声或阈值附近的轻声可能被过滤，需要保留全部声音时可关闭 VAD。
- 这是窗口级分段字幕，不是逐字 token 流式解码；重叠窗口可能产生重复边界，前端会合并同一窗口内的片段文本。

CrispASR concurrency 文档要求一个 session/context 不要被多个线程同时驱动。rLive 因此选择“一个常驻 session + 自动探测并限制上限的 intra-op 线程数”，而不是并行创建多个 631 MB 模型副本。更多上游 streaming/concurrency 约束见 [CrispASR streaming](https://github.com/CrispStrobe/CrispASR/blob/main/docs/streaming.md) 和 [CrispASR concurrency](https://github.com/CrispStrobe/CrispASR/blob/main/docs/concurrency.md)。
