# 开发指南

从源码运行、检查和构建 rLive。第一次上手只需要读「环境要求」和「启动」两节；桌面 release 构建、FFmpeg 依赖和 Android 相关内容按需往下看。

- 平台适配与后端分层：[架构说明](架构说明.md)
- 打标签发布与产物核验：[发布流程](发布流程.md)
- Android 环境、构建与真机调试：[Android 开发与构建](Android开发与构建.md)

## 环境要求

| 依赖 | 用途 |
| ---- | ---- |
| [Rust](https://www.rust-lang.org/tools/install) | Tauri 后端 |
| [Bun](https://bun.sh/) | 前端依赖与脚本入口 |
| [Tauri 2 前置环境](https://v2.tauri.app/start/prerequisites/) | 各平台 WebView 与构建工具链 |
| clang / libclang | 桌面 `ffmpeg-next 9.0.0` 的 bindgen（`ffmpeg-sys-next` 同样固定 9.0.0，原因见 `src-tauri/Cargo.toml`） |
| FFmpeg headers + link libraries + 运行库 | 桌面录制；通过 `pkg-config` 或 `FFMPEG_DIR` 定位 |

Android 不编译桌面 FFmpeg、录制和本地 ASR 模块，因此不需要 FFmpeg 与 libclang 桌面配置。

## 启动

```bash
git clone https://github.com/Kenny3Shen/rLive.git
cd rLive
bun install
bun run tauri dev
```

`bun run dev` 只启动 Vite，可用于调试纯 UI。直播请求、本机代理、数据库和字幕依赖 Rust 后端，必须通过 Tauri 启动。

## 检查与构建

```bash
bun run check        # oxlint + 两个 tsconfig 的类型检查
bun test tests/      # 前端单元测试
bun run build        # tsc --noEmit + vite build
bun run tauri build  # 当前平台安装包
```

按改动风险选最聚焦的检查即可，不必每次全跑。Rust 格式和 lint 检查应覆盖测试目标：

```bash
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --lib --tests -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

### 单元测试夹具（`tests/helpers/`）

跨文件重复的测试装配集中在 `tests/helpers/`：`async.ts` 提供可控 Promise 与宏任务等待，`storage.ts` 提供独立内存存储与访问失败桩，`video.ts` 补齐视频条目的必填字段，`media.ts` 提供最小媒体状态。场景特有的默认值、微任务 tick 数、媒体副作用和断言保留在各测试中；精简时不以删除边界用例或改变时序换取行数。

### 真实主窗口验证

JS 浏览器夹具、独立 HTML 页面及测试媒体样本已移除。交互验证直接使用应用主窗口，接入方式见下文「桌面端实机调试」。

1. 同步源码并启动 Windows Debug 主窗口，通过 CDP 接入已有页面；从真实卡片、按钮进入目标功能，不新建标签页或用 `pushState` 跳过入口副作用。
2. 按改动检查正常、失败、快速重复操作和离页清理；播放器同时观察媒体时间、暂停状态、顶部与底部控制栏，以及控制台错误。播放页缩回动画结束时应同步移除旧页面，不能在取消动画后再延帧卸载；检查旧弹幕不闪回，并覆盖快速返回后重入及 `commitStyles()` 不可用的兼容路径。断言优先使用稳定的 `data-*` 标记与可访问名称，不依赖排版类名。
3. 触摸或 WebView 专属问题再到 Android 验证。长按用真机手动按住；事件探针、媒体查询、视口模拟在结束后恢复。发送评论、弹幕等写操作会触达真实账号，未经明确授权不要执行。

#### 播放弹层回归

在 Windows 主窗口通过真实入口进入目标页面，直接操作并断言以下场景；不保留独立 JS 回归夹具：

- 直播播放页：临时派发媒体失败事件，检查错误弹窗持续显示时「弹幕 / 关注 / 设置」可切换；结束时清除事件探针并关闭弹窗。
- 带章节的 B 站短视频：检查评论 dock 关闭时，紧凑竖屏/横屏点击章节能展开底部/右侧抽屉，选章跳转并收起，播放/暂停状态不变；结束时清除 CDP 视口模拟。稿件须有至少两章，不伪造平台数据。

主窗口验证覆盖响应式布局与点击，不替代 Android 真机触摸验证。

### React 生命周期约束

渲染期只读取用于界面的 state/props；长期事件回调需要的最新值在 `useLayoutEffect` 同步。HUD 的 `data-visible`、`aria-hidden`、`inert` 在提交后对齐，避免显隐计时器触发整页重渲染。外部媒体、ASR、IPC 会话的同步复位及动效提交快照可保留有说明的局部 lint 豁免，不关闭全局 React 规则。原生播放、系统全屏和触摸手势仍需客户端或真机验证。

## 应用图标

所有平台的图标由脚本从同一份矢量设计生成，`scripts/icon-design.ts` 是唯一的几何与配色来源：

```bash
bun run icons            # 重新生成全部图标资源
bun run icons:preview    # 输出遮罩预览图，默认 /tmp/rlive-icon-preview.png
```

设计遵循移动端裁剪安全约束：品牌内容（渐变环、播放三角、live 指示点）全部收在画布中心的圆形安全区内，只有满幅渐变背景会被遮罩裁掉，因此圆形、squircle、圆角矩形任意启动器形状都不会切到内容。Android 自适应图标前景把标记压在 108dp 画布的中心 60dp 圆内（官方安全区 66dp）。

| 产物 | 说明 |
| ---- | ---- |
| `src-tauri/icons/*.png`、`icon.ico`、`icon.icns` | Windows / Linux / macOS 圆角满幅图标；ICO 含 16–256px，ICNS 含 16–1024px |
| `src-tauri/icons/ios/*.png` | iOS 方形满幅图标，圆角由系统遮罩负责 |
| `src-tauri/icons/android/mipmap-*/` | 旧版启动图标（圆角 `ic_launcher`、圆形 `ic_launcher_round`）与自适应前景 |
| `src-tauri/icons/android/drawable/` | 自适应背景渐变矢量与 Android 13+ 主题图标单色层 |
| `src-tauri/icons/android/mipmap-anydpi-v26/` | `ic_launcher` 与 `ic_launcher_round` 的 `adaptive-icon` 定义 |
| `public/rlive.svg` | 前端 favicon 与标题栏图标 |

Android 资源会同时写入 `src-tauri/gen/android/app/src/main/res/`，改完可用 aapt2 验证能编译链接：

```bash
aapt2 compile --dir src-tauri/icons/android -o /tmp/icons.zip
```

> [!IMPORTANT]
> 不要用 `tauri icon` 重新生成，它会按位图缩放覆盖上述资源，丢掉安全区约束、单色层和圆形图标。改图标只改 `scripts/icon-design.ts` 再跑 `bun run icons`。

## Windows 开发（WSL 源码 + Windows 运行）

源码维护在 WSL，构建和运行在 Windows 侧的同步镜像目录（见[同步到 Windows 镜像](#同步到-windows-镜像)）。Windows 侧统一用 **PowerShell 7**（`pwsh`）：`scripts/build-windows.ps1` 与 `scripts/prepare-windows-ffmpeg.ps1` 头部都声明 `#Requires -Version 7.0`，在系统自带的 Windows PowerShell 5.1 上会直接报版本不匹配而拒绝运行。在镜像目录的 pwsh 中构建：

```powershell
pwsh -File .\scripts\build-windows.ps1   # release 构建
bun run tauri dev                         # 开发运行
```

`build-windows.ps1` 会自动调用 `vcvars64.bat` 并准备 FFmpeg 与 LLVM。手动执行 Cargo/Tauri 命令时，需要 Visual Studio 的 `x64 Native Tools` 环境（MSVC headers 与 Windows SDK），并至少设置：

```powershell
$env:LIBCLANG_PATH = "D:\dev\LLVM-22.1.8\bin"
$env:Path = "$env:LIBCLANG_PATH;$env:Path"
```

### FFmpeg 与 LLVM

`scripts/build-windows.ps1` 优先读取进程级或用户级的 `FFMPEG_DIR` 与 `LIBCLANG_PATH`，并把同时包含 `libclang.dll` 和 `clang.exe` 的 MSVC-compatible LLVM `bin` 目录加入当前构建进程的 `PATH`。把依赖放在开发盘时，可用完整 FFmpeg SDK `D:\dev\FFmpeg` 与独立 LLVM `D:\dev\LLVM-22.1.8\bin`，再设置对应环境变量。

未设置 `FFMPEG_DIR` 时，脚本才用 MSYS2 与 MinGW-w64 自建裁剪版 FFmpeg 9.0.2 shared SDK，并缓存到 `%LOCALAPPDATA%\rLive\build`；缺失的 MSYS2 工具链（`make`、`diffutils`、`mingw-w64-x86_64-gcc`、`mingw-w64-x86_64-nasm`、`mingw-w64-x86_64-pkgconf`）由脚本用 pacman 补齐。构建会校验官方 FFmpeg 源码 SHA-256，只启用录制用到的组件，并把 `avformat`、`avcodec`、`avutil`、LGPL 2.1 许可证和构建说明放到 `rlive.exe` 同目录。

> [!IMPORTANT]
> 不要把 Android NDK 的 LLVM 路径用于桌面构建。桌面目标需要 MSVC-compatible LLVM；Android 使用单独的 NDK clang 配置，Linux/WSL 下执行 `bun run tauri -- android ...` 时 `scripts/tauri.ts` 会自动注入 NDK 的 bindgen、`cc-rs` 和 linker 环境。

携带上游许可证不代表应用整体分发合规已经完成。

## 桌面端实机调试

前端在真实 WebView 里运行时（而非纯浏览器 + mock），才能复现 MSE、触摸合成、IPC
与代理转发的真实行为。Windows 与 Linux 的调试通道不同。

### Windows（WebView2 + CDP + playwright）

WebView2 支持 CDP：给 dev 进程注入 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`，WSL 侧即可用 playwright 接入真实主窗口。

1. **同步镜像**：`bash scripts/sync-to-windows.sh`（代码在 `D:\dev\rLive` 构建运行，改一次源码同步一次）。
2. **停掉所有 rLive 实例**：安装版与残留 dev 进程都要退出。它们共享 WebView2 数据目录 `%LOCALAPPDATA%\com.shenss.rlive\EBWebView`，**先启动的实例决定浏览器进程参数**，后来者的 `--remote-debugging-port` 被忽略。
3. **起 dev 会话**（独立脚本 `D:\dev\rlive-tauri-dev.ps1`，不放进镜像）：

   ```powershell
   $env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9223 --remote-allow-origins=*"
   Set-Location D:\dev\rLive
   bun run tauri dev 2>&1 | Tee-Object -FilePath D:\dev\rlive-tauri-dev.log
   ```

   从 WSL 起要用 `Start-Process pwsh ... -WindowStyle Hidden`，否则进程随 WSL 会话被回收。
4. **接入**（镜像网络回环直通 Windows 127.0.0.1）：

   ```bash
   curl -s http://127.0.0.1:9223/json/version    # 返回 Edg/<版本> 即就绪
   playwright-cli -s=rwin attach --cdp=http://127.0.0.1:9223
   playwright-cli -s=rwin snapshot
   ```

> [!IMPORTANT]
> 只在主窗口页面上调试：CDP 新建的标签页**不注入 Tauri IPC**（`window.__TAURI_INTERNALS__` 不存在，页面显示「未连接 rLive 客户端」），也不要关它的标签。

务实要点：

- **增量编译**：`target/debug` 有缓存时 Rust 侧约 1 分钟起好；首次全量要十几分钟。
- **端口独占**：Windows dev 会话的 vite 占 1420，而镜像网络让 WSL 与 Windows 共享 loopback，因此**它与 WSL 侧的 `bun run dev` / `tauri android dev` 互斥**，同时起会让后者的 `beforeDevCommand` 直接失败退出。
- **视口模拟必须清理**：项目 `.playwright/cli.config.json` 设置 `browser.contextOptions.viewport: null`，让 CDP 接入真实窗口而非默认固定视口；已有会话需退出后重新连接才能应用配置。`page.setViewportSize` / `Emulation.setDeviceMetricsOverride` 会把真实主窗口的网页视口锁定到测试尺寸；恢复“旧宽高”仍是固定视口，之后拖动原生窗口会出现卡片不随窗口调整的假象。响应式验证使用独立 CDP 会话，并在 `finally` 调用 `Emulation.clearDeviceMetricsOverride`，随后 detach。实机缩放回归应对比 `window.innerWidth/innerHeight` 与 Tauri `innerSize / scaleFactor`，并截屏检查，而不只修改模拟视口。
- **无 `hasTouch`**：桌面 CDP 会话拿不到触摸能力，`page.touchscreen.*` 会报 `hasTouch must be enabled`。仅检查触摸事件分支时可合成 `pointerType: "touch"` 的 PointerEvent；合成事件不经过合成器，不能替代真机手势验证。
- Rust 改动触发自动重建并重启应用，重启后重新 attach；前端改动走 Vite HMR，但**镜像不会自动同步**。
- 排查 MSE/分片/代理用 `playwright-cli requests` / `eval` 直接读真实页面状态。

### Linux（WebKitGTK）

Linux 端是 WebKitGTK，不支持 CDP，playwright 无法接入。两个替代通道：

- **右键检查**：debug 构建（`bun run tauri dev`）默认启用 devtools，在页面上
  右键即可打开 WebKit 检查器（元素、网络、控制台、媒体缓冲都有）。
- **远程检查**：需要从另一台机器看时，给进程设置
  `WEBKIT_INSPECTOR_SERVER=127.0.0.1:9223` 后启动，再用 WebKit 系浏览器
  （如 GNOME Web）打开 `http://127.0.0.1:9223` 连接检查器。

## Android 调试要点

Android 前端跑在系统 WebView，只有 **debug 构建且 ABI 匹配**的 APK 能接 CDP；release 包不创建 `webview_devtools_remote_<pid>` socket。

```bash
bun run tauri -- android build --debug --target aarch64   # 模拟器用 x86_64
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk

PID=$(adb shell pidof com.shenss.rlive | tr -d '\r\n ')
adb forward tcp:9222 localabstract:webview_devtools_remote_$PID
curl -s http://localhost:9222/json/version    # 核对 Android-Package 是本应用
playwright-cli -s=rand attach --cdp=http://localhost:9222
```

务实要点：

- **socket 要按本应用 pid 取**：设备上常有多个 WebView 各开一个 socket，直接从 `/proc/net/unix` 抓第一个会连到别的应用（`/json/version` 的 `Android-Package` 一看就知道）。
- **手势用真实触摸注入**：`adb shell input tap/swipe`，坐标按 `物理 = CSS × devicePixelRatio` 换算；断言用 CDP 读真实状态（`currentTime`、play/pause 计数、`data-visible`、`inert`）。
- **入口要走真实交互**：`pushState` 直接跳到目标 URL 会跳过沿途组件的副作用（如列表卡片先写播放列表 store 再导航），同一 URL 因此可能呈现不同状态，手势/状态类 bug 复现必须点进去。
- **组件栈只有 dev 构建有**：生产 React 只给 minified 错误码。`vite build --mode development` 并不产出 dev React（vendor chunk 仍是生产版），要组件栈只能 `bun run tauri -- android dev`——它与 Windows dev 会话争 1420 端口，二者不能同时开。
- 手机需开「USB 调试」并保持亮屏（熄屏时 WebView 挂起）。
- **触摸/手势最终必须真机复现**：模拟器注入没有真实手指微抖，镜像 WebView 版本也落后于真机。

完整环境配置、模拟器启动、事件探针和排错清单见 [Android 开发与构建](Android开发与构建.md)。

## 同步到 Windows 镜像

唯一源码工作区是 WSL 侧仓库。`/mnt/d/dev/rLive` 只是 Windows 同步镜像，不要直接编辑。首次使用先复制 `scripts/windows-sync.conf.example` 为 `scripts/windows-sync.conf` 并设置 `WINDOWS_SYNC_PATH`，之后每轮改动完成并通过检查后执行：

```bash
bash scripts/sync-to-windows.sh
```

同步不等于构建。
