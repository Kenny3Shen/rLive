# 开发指南

从源码运行、检查和构建 rLive。第一次上手只需要读「环境要求」和「启动」两节；桌面 release 构建、FFmpeg 依赖和 Android 相关内容按需往下看。

- 平台适配与后端分层：[架构说明](架构说明.md)
- 打标签发布与产物核验：[发布流程](发布流程.md)
- Android 环境、构建与真机调试：[Android 开发与构建](Android开发-Windows.md)

## 环境要求

| 依赖 | 用途 |
| ---- | ---- |
| [Rust](https://www.rust-lang.org/tools/install) | Tauri 后端 |
| [Bun](https://bun.sh/) | 前端依赖与脚本入口 |
| [Tauri 2 前置环境](https://v2.tauri.app/start/prerequisites/) | 各平台 WebView 与构建工具链 |
| clang / libclang | 桌面 `ffmpeg-next 9.0.0` 的 bindgen |
| FFmpeg headers + link libraries + 运行库 | 桌面录制；通过 `pkg-config` 或 `FFMPEG_DIR` 定位 |

Android 不编译桌面 FFmpeg、录制和本地 ASR 模块，因此不需要 FFmpeg 与 libclang 桌面配置。

## 启动

```bash
git clone https://github.com/Kenny3Shen/rLive.git
cd rLive
bun install
bun run tauri dev
```

`bun run dev` 只启动 Vite，可用于调试纯 UI。直播请求、本机代理、数据库和字幕依赖 Rust 后端，必须通过 Tauri 启动。

## 检查与构建

```bash
bun run check        # oxlint + 两个 tsconfig 的类型检查
bun test tests/      # 前端单元测试
bun run build        # tsc --noEmit + vite build
bun run tauri build  # 当前平台安装包
```

按改动风险选最聚焦的检查即可，不必每次全跑。涉及 Rust 的改动另跑 `cargo test`（在 `src-tauri/`）。

## 应用图标

所有平台的图标由脚本从同一份矢量设计生成，`scripts/icon-design.ts` 是唯一的几何与配色来源：

```bash
bun run icons            # 重新生成全部图标资源
bun run icons:preview    # 输出遮罩预览图，默认 /tmp/rlive-icon-preview.png
```

设计遵循移动端裁剪安全约束：品牌内容（渐变环、播放三角、live 指示点）全部收在画布中心的圆形安全区内，只有满幅渐变背景会被遮罩裁掉，因此圆形、squircle、圆角矩形任意启动器形状都不会切到内容。Android 自适应图标前景把标记压在 108dp 画布的中心 60dp 圆内（官方安全区 66dp）。

| 产物 | 说明 |
| ---- | ---- |
| `src-tauri/icons/*.png`、`icon.ico`、`icon.icns` | Windows / Linux / macOS 圆角满幅图标；ICO 含 16–256px，ICNS 含 16–1024px |
| `src-tauri/icons/ios/*.png` | iOS 方形满幅图标，圆角由系统遮罩负责 |
| `src-tauri/icons/android/mipmap-*/` | 旧版启动图标（圆角 `ic_launcher`、圆形 `ic_launcher_round`）与自适应前景 |
| `src-tauri/icons/android/drawable/` | 自适应背景渐变矢量与 Android 13+ 主题图标单色层 |
| `src-tauri/icons/android/mipmap-anydpi-v26/` | `ic_launcher` 与 `ic_launcher_round` 的 `adaptive-icon` 定义 |
| `public/rlive.svg` | 前端 favicon 与标题栏图标 |

Android 资源会同时写入 `src-tauri/gen/android/app/src/main/res/`，改完可用 aapt2 验证能编译链接：

```bash
aapt2 compile --dir src-tauri/icons/android -o /tmp/icons.zip
```

> [!IMPORTANT]
> 不要用 `tauri icon` 重新生成，它会按位图缩放覆盖上述资源，丢掉安全区约束、单色层和圆形图标。改图标只改 `scripts/icon-design.ts` 再跑 `bun run icons`。

## Windows 开发（WSL 源码 + Windows 运行）

源码维护在 WSL，构建和运行在 Windows 侧的同步镜像目录（见[同步到 Windows 镜像](#同步到-windows-镜像)）。在镜像目录的 PowerShell 中构建：

```powershell
.\scripts\build-windows.ps1     # release 构建
bun run tauri dev               # 开发运行
```

`build-windows.ps1` 会自动调用 `vcvars64.bat` 并准备 FFmpeg 与 LLVM。手动执行 Cargo/Tauri 命令时，需要 Visual Studio 的 `x64 Native Tools` 环境（MSVC headers 与 Windows SDK），并至少设置：

```powershell
$env:LIBCLANG_PATH = "D:\dev\LLVM-22.1.8\bin"
$env:Path = "$env:LIBCLANG_PATH;$env:Path"
```

### FFmpeg 与 LLVM

`scripts/build-windows.ps1` 优先读取进程级或用户级的 `FFMPEG_DIR` 与 `LIBCLANG_PATH`，并把同时包含 `libclang.dll` 和 `clang.exe` 的 MSVC-compatible LLVM `bin` 目录加入当前构建进程的 `PATH`。把依赖放在开发盘时，可用完整 FFmpeg SDK `D:\dev\FFmpeg` 与独立 LLVM `D:\dev\LLVM-22.1.8\bin`，再设置对应环境变量。

未设置 `FFMPEG_DIR` 时，脚本才用 MSYS2 与 MinGW-w64 自建裁剪版 FFmpeg 9.0.1 shared SDK，并缓存到 `%LOCALAPPDATA%\rLive\build`；缺失的 MSYS2 工具链（`make`、`diffutils`、`mingw-w64-x86_64-gcc`、`mingw-w64-x86_64-nasm`、`mingw-w64-x86_64-pkgconf`）由脚本用 pacman 补齐。构建会校验官方 FFmpeg 源码 SHA-256，只启用录制用到的组件，并把 `avformat`、`avcodec`、`avutil`、LGPL 2.1 许可证和构建说明放到 `rlive.exe` 同目录。

> [!IMPORTANT]
> 不要把 Android NDK 的 LLVM 路径用于桌面构建。桌面目标需要 MSVC-compatible LLVM；Android 使用单独的 NDK clang 配置，Linux/WSL 下执行 `bun run tauri -- android ...` 时 `scripts/tauri.ts` 会自动注入 NDK 的 bindgen、`cc-rs` 和 linker 环境。

携带上游许可证不代表应用整体分发合规已经完成。

## 桌面端实机调试

前端在真实 WebView 里运行时（而非纯浏览器 + mock），才能复现 MSE、触摸合成、IPC
与代理转发的真实行为。Windows 与 Linux 的调试通道不同。

### Windows（WebView2 + CDP + playwright）

WebView2 支持 Chromium DevTools 协议：给 dev 进程注入
`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 后，WSL 侧可以直接用 playwright 接入。

1. **先同步镜像**：`bash scripts/sync-to-windows.sh`，代码在 `D:\dev\rLive` 上构建运行。
2. **停掉所有 rLive 实例**：安装版（`D:\rLive\rlive.exe`）与任何残留的 dev 进程
   都要退出。所有实例共享同一个 WebView2 数据目录
   `%LOCALAPPDATA%\com.shenss.rlive\EBWebView`，**先启动的实例决定浏览器进程参数**，
   后来者带上的 `--remote-debugging-port` 会被忽略。
3. **带调试参数启动 dev 会话**（在镜像外的独立脚本，例如 `D:\dev\rlive-tauri-dev.ps1`）：

   ```powershell
   Set-Location D:\dev\rLive
   $env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9223 --remote-allow-origins=*"
   bun run tauri dev 2>&1 | Tee-Object -FilePath D:\dev\rlive-tauri-dev.log
   ```

   从 WSL 启动时用 `Start-Process powershell` 起独立进程，避免随 WSL 会话被回收。
4. **WSL 侧接入**（镜像网络回环直通 Windows 127.0.0.1）：

   ```bash
   curl -s http://127.0.0.1:9223/json/version   # 应返回 WebView 版本
   playwright-cli attach --cdp=http://127.0.0.1:9223
   ```

> [!IMPORTANT]
> 只能在主窗口的页面上调试：通过 CDP 新建的标签页**不会注入 Tauri IPC**
> （`window.__TAURI_INTERNALS__` 不存在，页面会呈现「未连接 rLive 客户端」）。
> 也不要关闭主窗口页面的标签，那会干掉应用主页面。

Rust 改动会触发 tauri dev 自动重建并重启应用，重启用 playwright 重新 attach 即可；
前端改动走 Vite HMR。排查 MSE/分片/代理问题时，可用 `playwright-cli requests`、
`console`、`eval` 直接读真实页面的网络与缓冲状态。

### Linux（WebKitGTK）

Linux 端是 WebKitGTK，不支持 CDP，playwright 无法接入。两个替代通道：

- **右键检查**：debug 构建（`bun run tauri dev`）默认启用 devtools，在页面上
  右键即可打开 WebKit 检查器（元素、网络、控制台、媒体缓冲都有）。
- **远程检查**：需要从另一台机器看时，给进程设置
  `WEBKIT_INSPECTOR_SERVER=127.0.0.1:9223` 后启动，再用 WebKit 系浏览器
  （如 GNOME Web）打开 `http://127.0.0.1:9223` 连接检查器。

## Android 调试要点

Android 前端运行于系统 WebView，只有 **debug 构建且 ABI 匹配**的 APK 能通过 CDP 远程调试；release 包不创建 `webview_devtools_remote_<pid>` socket。

```bash
# 真机（arm64）
bun run tauri -- android build --debug --target aarch64
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk

PID=$(adb shell pidof com.shenss.rlive | tr -d '\r\n ')
adb forward tcp:9222 localabstract:webview_devtools_remote_$PID
curl -s http://localhost:9222/json/version    # 应返回 WebView 版本

playwright-cli attach --cdp=http://localhost:9222
```

x86_64 模拟器改用 `--target x86_64`。手机需开启「USB 调试」并保持屏幕常亮，熄屏时 WebView 会挂起。触摸与手势类问题必须在真机复现：模拟器注入的输入没有真实手指微抖，镜像 WebView 版本也落后于真机。

完整环境配置、模拟器启动、事件探针模板和排错清单见 [Android 开发与构建](Android开发-Windows.md)。

## 同步到 Windows 镜像

唯一源码工作区是 WSL 侧仓库。`/mnt/d/dev/rLive` 只是 Windows 同步镜像，不要直接编辑。首次使用先复制 `scripts/windows-sync.conf.example` 为 `scripts/windows-sync.conf` 并设置 `WINDOWS_SYNC_PATH`，之后每轮改动完成并通过检查后执行：

```bash
bash scripts/sync-to-windows.sh
```

同步不等于构建。
