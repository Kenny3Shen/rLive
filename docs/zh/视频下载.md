# 视频下载

rLive 的 B 站视频下载：从视频卡片或播放页把 DASH 的视频轨与音频轨下载到本机，再无转码合并成一个可直接播放的 MP4，同时缓存当前账号可获取的 CC 字幕与当前集的弹幕。下载任务由 Rust 后台队列管理，切走页面或最小化窗口都会继续；开关应用也不会丢任务，未完成的条目可在下次启动后继续。

桌面端与 Android 都支持。两端共用同一套 Rust 队列与断点续传，只有收尾合并不同：桌面端在进程内用 FFmpeg 做流复制，Android 没有链接 FFmpeg，改用 Kotlin 的 `MediaExtractor` + `MediaMuxer` 重封装。浏览器预览没有 Tauri IPC，不提供下载。

## 一、入口

- **播放页「更多操作」**：顶部 HUD 的磁贴菜单里有「下载」，点开后选择画质并确认；桌面与移动端都从这里进入。
- **桌面端底部控制栏**：播放页桌面布局的底栏也有一枚「下载」按钮，效果相同。
- **视频卡片**：桌面端在 UGC 视频卡片上右键，Android 长按卡片，选择「下载」即可直接加入队列。卡片入口按当前账号可用的最高画质开始，不弹画质选择框；列表条目缺少 `cid` 时先读取稿件详情，下载该卡片的第一个分 P。它不会读取观看历史，也不会自动下载整个合集或整季。
- **下载页签**：从「关注 → 下载」进入，地址是 `/follow?view=downloads`。录制和下载统一归入关注页，视频发现页只保留推荐、热门、番剧、影视；旧 `/video?tab=download` 链接会重定向到新位置。下载任务不参与视频内容列表请求。

播放页只对可下载的 B 站稿件显示入口：普通 UGC 视频与番剧 / 影视单集都能下载，直播、IPTV 与短视频流不在范围内。一个任务对应**当前这一集 / 这一个 P**，不会自动把整季或整个合集都排进队列。

## 二、画质与开始下载

播放页的画质列表来自当前播放页的 `accept_quality`，默认选中播放器当前画质。当前账号不可用的档位会置灰，不能选择；匿名或非大会员身份能下载的最高档位，与在线播放能看到的上限一致，rLive 不会绕开账号权限去请求更高档位。卡片入口不展示画质列表，直接使用同一套账号权限下的最高可用档位。

确认后任务立即进入队列：

1. 后端用当前 Cookie、代理与请求头解析一次 playurl，拿到视频轨、音频轨的完整分片表。
2. 按字节区间顺序下载 `video.m4s` 与 `audio.m4s`。两条轨本身就是完整 fMP4 文件，支持 HTTP Range 断点续传。
3. 两条轨完整后、合并前获取当前集的可用字幕，转换为 WebVTT 保存到任务目录；视频没有字幕时不生成字幕文件。手动 CC 与平台返回的 AI 字幕都可缓存，但 AI 字幕仍受登录权限限制。同时按完整媒体时长获取每 6 分钟一段的弹幕，保存为本机 JSON 快照；暂停后继续会复用已成功保存的段，只补取缺失段。
4. 进入「合并中」：桌面端在进程内用 FFmpeg 做流复制（不重新编码）；Android 通过 `RliveVideoMuxPlugin` 用 `MediaExtractor` 读两条轨、`MediaMuxer` 写 MP4，同样不解码、不转码。
5. 合并成功后改名为 `<标题>.mp4`，任务进入「已完成」。字幕或弹幕请求、个别字幕轨或弹幕段缓存失败不阻断视频完成，应用内播放页会明确提示，已成功缓存的字幕与弹幕仍可使用。

同一稿件、同一 P 重复点击不会重复创建任务：未完成的条目会被复用，已完成或正在进行的条目直接返回原任务。失败或已暂停的条目再次发起下载时，如果换了画质，会丢弃旧画质的分片重新下载，避免把两条不同 profile 的分片拼进同一个文件。

## 三、下载页签

页面沿用关注页的筛选与内容布局：宽窗口在左侧筛选栏按「全部 / 未完成 / 已完成」切换（各选项带数量），窄窗口把同样的三段范围收进与收藏、IPTV 平台筛选一致的下拉框——圆角边框背景、44px 触摸高度、可见文字和箭头，当前值也显示对应计数。切换只改地址栏的 `downloadView`，返回列表时保留所选范围。

下载卡片与录制卡片统一为横向媒体样式：左侧封面标注时长，窄窗口封面收紧到 80px，标题独占正文整列（14px，与其他页签一致），状态与作者挤在同一行，不再为状态单独占一行；画质、文件大小和下载进度另起一行横跨封面与正文两列，避免被窄正文列挤成一团。宽窗口保持原来的 176px 封面、标题与状态并排、作者次行和 16px 标题。暂停、继续、重试、系统播放器、文件位置与删除统一使用右侧带操作提示的图标按钮，保持 44px 触摸命中区，窄窗口纵向排列且不会误触整卡播放；加载骨架按真实操作数量占位，不再由固定三枚纵向按钮撑高卡片。已完成文件直接点击卡片内容区播放，不额外提供播放按钮或底部按钮栏。未完成任务显示下载比例与进度条，已完成文件不再重复显示满格进度。封面加载失败时显示下载图标。

- **下载任务**：排队、下载中、已暂停、合并中、失败，以及应用退出时被中断的条目。
- **已完成**：合并完成的 MP4，点击整张卡片进入应用内离线播放器，聚焦播放入口后也可按 `Enter` 或 `Space` 打开。桌面端右键、Android 长按卡片打开操作菜单，可选择应用内播放、使用系统播放器或删除；桌面端还可打开文件位置。Android 没有可浏览应用私有目录的文件管理器入口。
- **暂停 / 继续**：暂停在下一个数据块边界生效，已经写入的分片保留；继续时从断点续传。合并阶段不能暂停。
- **重试**：失败条目保留已下载的字节，重试会从断点继续；换画质则从头下载。
- **删除**：二次确认后删除该条目的整个目录与记录。正在下载的条目会先等后台写入停止，再删目录；Windows 上不会留下被占用的半成品文件。

未完成卡片不进入播放器，暂停、继续和重试按任务状态提供；这些操作也可从右键或长按菜单执行。卡片内的操作按钮独立响应，不会误触整卡播放。

队列**同一时刻只下载一个任务**，其余按创建顺序排队。暂停或失败不会阻塞后面的条目；当前任务结束后自动开始下一个。进度通过 Tauri 事件推送（约每 500ms 一次），存在排队、下载中或合并中任务时每 2 秒轮询兜底；暂停与失败不触发轮询。列表保持未完成优先、创建时间倒序，切回页面重新获取最新状态。

有任务处于排队、下载中或合并中时，主导航「关注」显示录制与下载任务总数，「下载」页签显示进行中的下载数量。暂停、失败和已完成不计入徽标；任务开始推进或结束后，计数随事件自动更新。

## 四、应用内播放

已完成的条目可在桌面端和 Android 上直接播放，不需要重新请求 B 站播放地址，也不依赖登录态。播放器只读取本机 MP4 与已缓存的字幕、弹幕；播放文件本身不需要互联网连接，封面仍可能需要联网加载。

- **播放控制**：支持暂停 / 继续、进度拖动、倍速、音量、字幕、弹幕开关和全屏；画面内顶部 HUD 与底部控制栏沿用应用现有播放器布局。字幕菜单可关闭字幕或切换已缓存语言，断网也可使用。
- **离线弹幕**：按本机视频时间轴显示缓存弹幕，暂停、倍速和拖动进度与画面同步；弹幕开关和字号、透明度、显示区域、屏蔽词沿用现有播放器设置。不支持离线发送弹幕，高级 / 代码等模式仍按现有普通滚动降级。
- **页面排版**：不设独立顶部横栏；返回与文件操作位于底部操作栏，画面内 HUD 的返回箭头在窗口化时返回列表、全屏时先退出全屏。播放器、侧栏断点、宽度及内边距沿用在线 VOD；侧栏集中显示标题、作者、画质、时长和文件大小，不显示额外的离线播放说明小字。
- **断点续播**：观看进度保存在该下载任务的 `entry.json` 中，暂停或离开播放器时保存。再次进入同一条目会恢复未看完的位置；不足 3 秒的短暂停留不保存，已到片尾的位置下次从头播放。
- **返回列表**：从列表进入时保留「全部 / 未完成 / 已完成」筛选；直接打开播放链接时返回「关注 → 下载」。Android 全屏时按返回先退出全屏。
- **系统播放器**：下载列表与播放页均保留「系统播放器打开」，可在 WebView 不支持文件编码时使用其他播放器。应用不会同步外部播放器的观看进度。

应用内播放只加载本机视频与已缓存字幕、弹幕，不重新请求在线详情、评论、弹幕或字幕，不向 B 站上报观看历史，也不支持未完成任务边下边播。删除下载条目会同时删除视频、字幕、弹幕及其本地观看进度。旧版本已完成的下载没有字幕或弹幕缓存时仍可播放，但不会在回放时联网补取；需删除条目后重新下载才能缓存。

## 五、输出与存储

下载根目录是应用数据根目录下的 `downloads/`（与录制库同级）。桌面端可在下载筛选栏点「打开下载目录」定位，窄窗口的按钮在横向筛选下方；Android 上这个按钮不显示，目录位于应用私有沙箱 `<dataDir>/rlive/downloads`，应用外不可直接浏览。每个任务一个自包含目录：

```
downloads/
  <任务 id>/
    entry.json          # 任务元数据、字幕索引、弹幕缓存状态、最终文件名与本地观看进度
    video.m4s.part      # 视频轨临时文件
    audio.m4s.part      # 音频轨临时文件
    output.mp4.part     # 合并中的临时文件
    <标题>.mp4          # 完成后的成片
    subtitle-<id>.vtt    # 可选；每条可获取字幕单独缓存
    danmaku.json        # 可选；弹幕分段快照，可能只有部分成功段
```

任务 id 由稿件身份生成：普通视频是 `<bvid>-<cid>`，番剧 / 影视是 `ep-<ep_id>-<cid>`，因此同一稿件换集不会互相覆盖。文件名取稿件标题，去掉跨平台非法字符与控制字符，最多保留 80 个字符，并将含 `.mp4` 后缀的完整文件名限制为 255 个 UTF-8 字节；Windows 保留设备名（包括带其他后缀的标题）自动加下划线前缀。

成片是标准 MP4 容器内的原始音视频流，没有二次编码，画质与下载到的 DASH 轨一致。文件名与`entry.json`是恢复队列的唯一依据：应用启动时会扫描 `downloads/`，把上次处于下载中 / 合并中的任务改为「已暂停」并提示可继续，排队中的任务则自动重新入队；已完成但文件被移动或删除的条目会标为失败。

应用内播放由 Rust 在 `127.0.0.1` 的临时端口提供受控本地文件服务，支持 HTTP Range 随机读取；地址带随机 token，只允许访问已完成任务获授权的成片、字幕与弹幕快照，不开放任意文件路径。录制回放与下载共用本地 HTTP 文件读取逻辑。

Android 的下载目录在应用私有沙箱内，`file://` 不能直接交给外部应用。选「系统播放器打开」时 Rust 通过 `RliveVideoMuxPlugin` 的 `openFile` 命令，由 `FileProvider` 把文件换成 `content://` 再发 `ACTION_VIEW`，只授予一次性读权限；没有能打开 MP4 的应用时返回错误提示。应用内播放不经过 `FileProvider`。

## 六、合并失败排查

桌面端若下载已经达到 100%，但提示「创建输出文件失败: Invalid argument」，先检查应用实际加载的 FFmpeg 是否包含 MP4 封装器。旧版裁剪 SDK 只启用了 FLV、MPEG-TS 输出，虽能读取下载的两条 DASH 轨，却无法创建 MP4 输出上下文；这不是下载不完整，也不是视频标题中的中文导致的。

自建版本必须使用包含 `--enable-muxer=flv,mpegts,mp4` 的 FFmpeg SDK；仅重新编译 Rust 或继续使用旧 DLL 不会补齐这个能力。三个桌面平台的准备脚本都会断言 `CONFIG_MP4_MUXER`，并在组件配置变化后重建旧缓存。自行设置 `FFMPEG_DIR` 的 Windows 开发者需自行更新 SDK，不能继续指向缺少 MP4 的旧构建。

新版会在合并前检测 MP4 支持，缺失时明确提示更新 FFmpeg 或重新安装应用。更新为包含修复后运行库的版本后，在原失败任务上点「重试」即可复用已经下载的分片，无需删除任务重新下载；重试仍需联网解析播放地址。

## 七、限制

- Android 端依赖系统 `MediaMuxer`，只做容器重封装；B 站两条 DASH 轨都是完整 fMP4，实测路径与桌面一致，但不同厂商 ROM 的解复用器差异仍可能影响部分冷门编码。
- 一个任务只下载当前这一集 / 这一个 P，不提供整季批量下载。弹幕仅缓存下载时平台返回的当前弹幕快照，不会自动更新。字幕仅缓存平台当前返回的可用轨道，不额外进行语音识别或翻译。
- 成片保留下载轨的原始编码，应用内能否解码取决于系统 WebView 与设备；遇到不支持的编码可使用系统播放器打开。仅支持已完成文件，不支持边下边播；字幕和弹幕分别作为独立 VTT、JSON 文件保存，不烧录或封装到 MP4 内，外部播放器不会自动继承应用内的字幕选择或弹幕显示。
- 画质上限受当前 B 站账号权限约束；版权或地区受限的番剧 / 影视，playurl 本身就会失败，任务会显示上游错误。
- 下载不占用播放器的代理会话，但会占用网络带宽；同时只跑一个任务，避免多任务争用连接。
- 应用退出时未完成的任务会保留在磁盘上，重新打开后需要手动「继续」或自动从排队态恢复；不会在后台守护进程中继续下载。
