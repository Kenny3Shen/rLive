# YouTube 平台接入说明

YouTube 作为直播平台接入现有的推荐、分类、搜索、关注、历史、多画面和 HLS 播放链路。实现参考 [Fy1Sync](https://github.com/Fy1ng/Fy1Sync) 的直播地址规范化与音视频格式选择思路，使用 Rust 实现匿名网页接口，不需要安装 `yt-dlp` 或配置 YouTube Data API key。

## 使用方式

在直播页切换到 `Youtube` 页签，可按关键词查找正在直播的视频。推荐使用直播关键词搜索；新闻、游戏、音乐等分类也是对应主题的直播搜索，并非 YouTube 官方分区目录。搜索列表只接受平台明确标记正在直播的结果，不将点播或预告当作直播。

搜索框可直接输入以下内容，也可在「房间号」模式或多画面添加窗口使用：

- 11 位视频 ID，例如 `jfKfPfyJRdk`。
- `https://www.youtube.com/watch?v=...`、`https://www.youtube.com/live/...` 或 `https://youtu.be/...`。
- `@频道名`、`https://www.youtube.com/@频道名/live` 或 `https://www.youtube.com/channel/UC.../live`。

频道入口解析当前直播场次。关注使用稳定频道标识，刷新状态时重新查找频道当前的直播；视频 ID 保留在房间的内部播放元数据中。频道同时直播多场时，频道 `/live` 页选择哪一场由 YouTube 决定。

## 播放与网络

后端使用匿名 Innertube 客户端请求视频信息与 `hlsManifestUrl`，解析 master playlist 中同时包含 H.264 视频和 AAC 音频的档位。清晰度按分辨率与帧率排列。播放器沿用 Video.js 10 HLS 适配器；清单、密钥与分片通过现有 Rust `stream_proxy` 改写为本机地址，统一处理同源与请求头。

API、网页、图片和媒体请求遵循「设置 → 网络」的代理模式。缩略图与频道头像使用 `ytimg.com`、`ggpht.com` 和 `googleusercontent.com` 图片 CDN 白名单。访问 YouTube 需要当前网络出口能够连接 YouTube 和 Google 视频 CDN。

视频 `player` 响应不包含频道头像。房间详情额外从 Web `next` 响应的 `videoOwnerRenderer.thumbnail` 读取当前视频所属频道的头像，并选择最大尺寸，通过现有图片代理加载。开播状态刷新不查询头像；头像查询失败时保留名字首字母占位，不阻断房间详情或播放。

当前只提供公开直播的 HLS 档位，不实现高分辨率分离音视频的自适应合并、PO token 提供器或播放器 JavaScript 签名求解。桌面端和 Android 共用 Rust 请求路径，Android 无需运行外部取流进程。

## 实时聊天

聊天从当前视频观看页获取 `liveChatRenderer` continuation，调用 `youtubei/v1/live_chat/get_live_chat` 并按照上游等待时间轮询。消息复用现有 `danmaku-batch` 事件、房间切换围栏和有界批处理，断线交给共享重连策略处理。

只接收本次弹幕连接开始后发布的消息，不重放连接前的聊天。首屏与自动重连都复用本次连接的时间边界和消息 ID 去重；缺少发布时间的消息不展示。没有新消息的轮询仍继续推进游标，暂时缺少下一游标时有限重试，持续缺失或请求失败则按共享策略重新建立连接。

时间边界优先使用续页令牌的服务器生成时间校正本机会话起点，缺失时使用 HTTP `Date`。若两者都不可用，首个带消息的响应仅用于建立历史边界，从之后的消息开始展示；HTTP `Date` 只有秒精度，因此其降级路径可能漏掉边界附近不足一秒的消息。

支持普通文本、Super Chat、Super Sticker、会员与礼物通知。表情保留平台提供的文字标签，不加载任意聊天图片。消息 ID 仅在后端用于有界去重；Super Chat 的稳定 ID 可供现有悬浮层去重。外币金额不转换为人民币。

公开网页聊天为匿名只读接入，不提供消息发送、登录、会员购买、付费、管理或撤回操作。聊天关闭、场次结束或上游拒绝时会显示状态提示；播放是否可用与聊天是否开启分别判断。

## 能力边界

- 只播放当前直播；点播、直播回放和未开始的预告不进入播放流程。
- 未接入 YouTube 账号授权。会员专享、年龄限制、私密直播、地区限制和机器人验证可能阻止匿名观看，错误不能当作主播已下播。
- 推荐和主题搜索依赖公开网页索引，结果及分页可能随地区、语言、时间和接口格式变化，不保证覆盖全部直播。
- 在线人数只使用搜索结果明确提供的观看人数。房间 player 的 `viewCount` 是累计播放次数，不当作在线人数显示。
- 签名媒体地址为短时有效值，长期播放、换清晰度或网络变化后可能需要重新载入。
- 本接入没有绕过广告或付费权限的保证。
- 公开网页 API 没有稳定兼容性承诺。若上游停发 HLS、聊天令牌或改变字段，需要重新验证适配器。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `src-tauri/src/sites/youtube/mod.rs` | `LiveSite` 入口 |

修改时优先运行 `cargo test --lib youtube`、`bun run check` 及受影响的现有前端测试，再在 Windows 主窗口确认搜索、清晰度切换、实际播放和聊天。仅拿到播放 URL 不代表媒体分片能持续读取。

## 本次验证

2026-11-25 在 Windows 主窗口通过真实平台页签进入 YouTube，推荐成功加载直播结果，默认搜索输入 `@LofiGirl` 能解析当前直播并进入播放器。1080p 正常播放，菜单列出 1080p 至 144p 六档，切换到 720p 后视频持续推进、`readyState=4`；音频与视频的解码字节计数均增长。公开聊天消息进入现有列表，检查期间没有浏览器控制台错误。

同日修复后，Windows 主窗口确认页签精确显示 `Youtube`。重新进入 Lofi Girl 直播间，观察超过 80 秒，首屏不再重放之前约 18 分钟的历史聊天，随后六批共 14 条聊天消息进入列表，所有消息时间戳均晚于本次连接起点，列表自动跟随到最新消息，浏览器控制台无错误。另以真实上游接口连续轮询五轮，确认空消息页后仍能推进游标并接收后续新消息。

头像修复后，同一 Windows 主窗口重新搜索 `@LofiGirl` 并进入直播间，顶部和侧栏均成功加载 176×176 的频道头像，不再显示名字首字母占位。本机图片代理返回 HTTP 200、`image/jpeg`，响应体 14638 字节。

上述记录只代表当时网络出口和对应公开直播的实测结果。未进行 Android 真机验证，也未验证会员专享内容、长期签名续期、真实 Super Chat 支付事件或 YouTube 专属录制回归。
