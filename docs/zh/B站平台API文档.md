# 哔哩哔哩平台 API 文档

更新时间：2026-07-27。本页说明 rLive 对哔哩哔哩的接入能力、上游接口类别与本机账号边界；它不是哔哩哔哩开放平台的官方开发文档。

## 能力总览

| 能力 | 状态 | rLive 行为 |
| --- | --- | --- |
| 分类、推荐、分区房间、搜索 | 已支持 | 使用网页公开可访问的直播与搜索数据；列表可按上游返回继续加载。 |
| 房间详情 | 已支持 | 解析真实房间号、主播、封面、热度、开播状态与公告。 |
| 播放与清晰度 | 已支持 | 获取可用协议、格式、编码与清晰度，并经本机 `stream_proxy` 交给网页播放器。 |
| 实时弹幕与 SC | 已支持 | 连接房间 WebSocket，展示普通消息、图片表情与醒目留言。 |
| 账号 | 已支持 | 可扫码登录或手动保存 Cookie；Cookie 仅保存在本机。 |
| 单条普通弹幕发送 | 已支持 | 需要本机发送开关和有效登录态；仅允许用户主动发送一条文本。 |

## rLive 接入接口

所有站点适配器都实现统一的读取接口：`get_categories`、`get_recommend_rooms`、`get_category_rooms`、`search_rooms`、`get_room_detail`、`get_play_qualities` 与 `get_play_urls`。前端通过 `site_*` Tauri command 调用这些能力，不直接持有上游 Cookie、短时 token 或播放签名。

哔哩哔哩专用的实时能力包括：

- `danmaku_connect`：使用房间弹幕信息建立接收连接；断线时会轮换网关并刷新短时凭据。
- `bilibili_danmaku_send_status` / `bilibili_danmaku_send`：仅供应用内、用户显式操作的单条普通文本发送。
- SC 只用于展示；rLive 不提供支付、送礼或付费留言写入。

## 上游数据与播放

分类、房间列表、搜索、房间详情、弹幕连接信息和播放信息来自网页使用的直播接口。部分读取请求需要网页环境字段或 WBI 签名；这些属于适配器内部实现细节，不是稳定的第三方应用契约。播放地址与短时签名不进入前端持久化缓存，刷新房间或切换清晰度时会重新获取。

常规房间详情会解析真实 `room_id`，因此短号、展示号和发送所需的真实房间号不会混用。播放链路支持上游给出的可用清晰度与线路；具体可用项会随直播状态、账号、地区和平台策略变化。

## 账号、弹幕与发送

接收普通弹幕通常可匿名工作；扫码或手动 Cookie 登录可改善网页登录态兼容性。普通图片表情只加载经过来源校验的 B 站 CDN 图片，SC 仅展示平台下发的事件。

发送使用登录后的网页写入接口：

```text
POST https://api.live.bilibili.com/msg/send
```

发送前必须同时满足：

1. 「设置 → 账号」中的 `danmaku_send_enabled` 已开启；该默认关闭的开关只保存在当前设备，也不会随配置导入或导出。
2. 本机 Cookie 含 `SESSDATA` 与 `bili_jct`；后者作为 CSRF 值使用。
3. 真实数字房间号、非空单行文本和当前保守的长度/冷却校验均通过。

rLive 只提交用户主动输入的一条普通文本，不支持批量、循环、定时、自动回复、礼物、支付或不确定结果的自动重试。写入 command 返回不生成本地假弹幕；右侧列表与飘屏只在正常房间连接收到平台真实回显后显示消息。

## 安全与验证

Cookie、CSRF、消息正文、短时 token 和上游原始错误不写入日志、不导出也不返回到前端。发送 HTTP 客户端禁止跟随重定向，以免将登录态交给重定向目标。

上游接口和权限会变化。即使本机 Cookie 写入成功，也不代表哔哩哔哩向 rLive 授予公开应用写入权限；请仅在有权发言的房间手动验证，并遵守平台条款、审核规则和当地法律。
