# rLive v9.6.0 更新公告

发布日期：2026-11-21

本版新增 AcFun 直播弹幕、视频与文章评论，完善播放侧栏的关注操作，并改进 Android 点播启动、斗鱼 FLV 转发和封面加载体验。

## 主要变化

- **AcFun 互动内容**：直播支持接收实时弹幕；视频和文章支持查看主评论、楼中楼回复以及热门优先或最新排序。宽窗使用独立评论栏，窄窗通过评论抽屉查看，选集与评论样式进一步和 B 站页面统一。
- **关注项操作菜单**：播放侧栏的关注项新增桌面右键和移动端长按菜单。桌面端可开启录制、切换自动录制、移入分组或取消关注；Android 移动端长按仅支持移入分组或取消关注，不显示录制能力。桌面端操作录制中的关注项时，当前房间的弹幕连接和发送状态会继续保留。
- **Android 点播启动**：重构视频首开流程，先挂载媒体并取得可播数据，再加载 HUD、控制栏和详情。竖横屏切换、加载中旋转、换画质、仅音频切换、恢复画面和重试时的布局与入场动画更加稳定。
- **播放性能**：斗鱼 FLV 续流重组改为游标扫描，减少临时分配和不必要的缓冲区搬移；封面代理分流、B 站列表封面使用保持比例的 WebP，并保留图片懒加载与缓存。
- **界面修复**：直播、视频、下载与录制卡片的桌面右键菜单固定宽度，长标题改为单行省略并保留悬停提示，避免菜单被不同长度的标题撑开。

## 已知限制

- AcFun 评论与直播弹幕目前均为只读，尚不支持发送、评论互动或账号登录；视频与文章评论依赖上游公开接口，可能受登录、地区或服务端策略限制。
- Android 点播启动流程已在 Android 16 x86_64 模拟器的 WebView 133 中验证，尚未覆盖 Android 真机和断网实机场景；关注菜单的 Android 手动长按也尚未验收。
- 图片代理的分流与 WebP 策略已通过聚焦回归，但目前没有稳定、可复现的端到端加载提速证据；封面仍可能受上游慢请求影响。
- Linux AppImage 可以启动并通过依赖检查，但当前验收环境启动时报告缺少 GStreamer `appsink` 元素；本次没有完成 AppImage 内的实际 HLS/DASH 播放验收。
- Windows 验收包含直播录制和 B 站视频下载，但本次两个直播样本均未生成非空弹幕记录，因此没有验证非空录制弹幕的回放或导出。
- Windows 上 xASR 当前会因 CrispASR `v0.8.48` 缺少所需 CUDA 卷积核而回退 CPU，选择「自动」或「CUDA」不会改变实际 provider；xASR 不使用热词，也尚未完成同口径性能 benchmark。
- Intel Mac 当前没有可用的 CrispASR 运行库，不支持本地语音字幕；Apple Silicon Mac 使用 CPU 推理。桌面本地语音字幕首次使用时仍需联网下载运行库和所选模型，独立字幕窗口仅在直播间提供入口。
- Android 不支持多画面、录制和本地语音字幕。
- Windows 安装包未做 Authenticode 签名，可能触发 SmartScreen 提示；macOS 安装包未做 Apple 签名与公证，首次启动可能需要在「系统设置 → 隐私与安全性」中允许打开。

## 构建与验收

CI run `44896171169` 第二次尝试通过，前端检查、生产构建和 1024 项前端单元测试通过；Rust 库测试 921 项通过、1 项按设计忽略，忽略项为 `asr::tests::crispasr_end_to_end`。

Release run `44896171205` 的版本校验、Windows、macOS arm64/x64、Linux、Android 与草稿发布作业全部成功。产物包含 Windows NSIS/MSI、macOS DMG、Linux DEB/RPM/AppImage 和 Android arm64-v8a APK。

Windows x64 的 NSIS 安装包已在隔离目录完成安装、启动和退出，关于页显示 `v9.6.0`；MSI 已完成 administrative install 载荷检查。验收通过 AcFun 直播、FLV 录制与回放、Twitch HLS 与 MPEG-TS 录制回放、AcFun 视频和文章评论、关注项桌面操作菜单、B 站视频播放与 480P 下载；最终 MP4 含 H.264 视频和 AAC 双声道音频，并可通过应用内离线回放。

Linux DEB、RPM 与 AppImage 均成功解包，`ldd` 无缺失依赖，未动态依赖 FFmpeg，也未包含 ASR 运行库；三类产物均在隔离 XDG 环境中通过 8 秒启动存活检查。Android APK 已通过 v2 签名验证与最终 arm64 native symbols 检查，本次环境没有 arm64 真机，未执行安装和启动验收。

macOS 两个架构均由发布工作流构建成功，但尚未在 Apple 实机验证安装和核心功能。
