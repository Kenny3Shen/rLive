# rLive v9.3.1 更新公告

准备日期：2026-11-05

> [!WARNING]
> v9.3.0 的 tag 虽已存在，但 Release 草稿已撤回且从未公开。本公告列出 v9.3.1 的代码变化，安装包可用状态以 GitHub Release 为准。Android arm64 真机与 macOS 人工验收尚无结果，构建与自动检查通过不能替代真机验证。

本版承接 v9.3.0 未公开的功能，并补齐桌面下载合并与移动端启动、布局修复。

## 未公开功能（原 v9.3.0）

- **B 站视频下载与离线回放**：从视频卡片或播放页按当前账号权限下载 DASH 视频、音频轨；队列支持暂停、继续、重试、断点续传与重启恢复。桌面用 FFmpeg、Android 用 `MediaMuxer` 合并为 MP4；完成项可在应用内离线播放，支持续播、倍速、全屏、字幕语言切换和弹幕开关，也可交给系统播放器。字幕与弹幕只缓存下载时当前分 P 可获取的内容。使用说明见[视频下载](../视频下载.md)。
- **本地媒体统一**：录制库与下载任务集中到关注页「录制」「下载」页签，任务数徽标和统一的本地媒体卡片贯穿导航与列表；录制回放补齐共享控制栏、弹幕定位与进度跟随，下载播放器补齐返回、文件操作、倍速、全屏和进度保存。旧深链接继续兼容。

## 本次修复

- **桌面下载合并**：下载已达 100% 却提示「创建输出文件失败: Invalid argument」，根因是旧裁剪版 FFmpeg 只启用了 FLV / MPEG-TS 输出，缺少 MP4 封装器。三个桌面平台的准备脚本现在启用并断言 `CONFIG_MP4_MUXER`，组件配置变化后不再复用旧 SDK；合并前会检测 MP4 支持，缺失时给出明确提示。自行指定 `FFMPEG_DIR` 时，仍须确保 SDK 与实际加载的 DLL 都支持 MP4。排查见[合并失败排查](../视频下载.md#六合并失败排查)。
- **FFmpeg 精简构建**：录制与下载合并只做流复制 / 容器重封装，不转码。三个桌面平台只编译 `avformat`、`avcodec`、`avutil`，删除 Matroska、zlib、swresample 和无实际来源的解析器、解码器，不因 MP4 增加视频编码器；保留 H.264/HEVC/AAC 参数探测及序列头提取，避免裁剪后 HLS 缺少尺寸而录制失败。Windows 使用原生线程，避免隐式依赖开发机 PATH 中的 `libwinpthread-1.dll`。本公告不提供安装包体积降幅数据。
- **移动端卡片与筛选**：窄屏收紧封面，标题独占正文列，状态与作者同行，画质、大小和进度跨列展示；操作按钮保留 44px 触摸命中区且不会误触整卡播放，状态筛选复用与其他页签一致的下拉组件，宽屏布局保持原有信息层级。
- **Android arm64 启动**：原生库中的 8 个 `__aarch64_ldadd*` / `__aarch64_ldset*` 强未定义 outline atomic helper 曾导致启动失败；Android `aarch64` 构建现在静态链接 NDK compiler-rt builtins，发布工作流对最终 APK 内的 `librlive_lib.so` 做符号断言。原生库符号与编译检查通过，但不替代真机启动验收。

## 开发者说明

- 原子计数更新从已弃用的 `fetch_update` 改用 `try_update`，仅消除弃用警告，保持原有计数行为。
- MP4 能力检查合并为一个必要 helper，仅保留一个实际库能力测试；录制回归改用 332 字节的 H.264 FLV 素材，不为旧 FLV1 测试编译额外解码器，不新增重复冒烟测试。

## 构建与验收

- 版本元数据统一为 `9.3.1`，安装包以本次 Release 资产为准；请勿使用 v9.3.0 已撤回草稿升级。
- 本地按新白名单编译 FFmpeg 9.0.2，仅产出三个 av* 静态库；静态链接 Rust 库测试为 839 通过、1 忽略，无弃用警告。真实下载素材的 MP4 重封装及 FLV/MPEG-TS/HLS 路径通过，输出保持 H.264/AAC 原编码。前端检查与 896 项单元测试通过。
- Android arm64 真机的安装、启动及下载 / 离线回放，以及 macOS 的安装、启动、联网与核心播放人工验收尚无结果；不宣称全平台人工验收通过。
- 常规覆盖升级保留原任务及下载分片。更新后在原失败任务上点「重试」即可重新合并，仍需联网解析播放地址；不要删除任务重新下载。
